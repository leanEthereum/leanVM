\subsection{A load-bounded repair of the BLAKE2s memory frontier}\label{note:zk-memory-count-coarse}

\paragraph{Result and extra condition.} A shared $32$-cell padding frame can normalize all $144$ coarse BLAKE2s memory-count products using existing compression positions and ordinary XOR self-copies. Together with Theorem~\ref{thm:zk-bc-coarse-normalization}, this makes all ten BLAKE2s count-column frontiers public. The construction preserves the established restricted privacy interface, with one additional visible fair prefix bit. Its resource cost depends on a public bound $\zkBlakeLoad$ on BLAKE2s accesses to each real memory cell. The first construction uses two rows per interval; the stronger variant below uses thirty-two and supports bound $256$ with fewer XOR rows. \emph{Small frames alone do not imply the read bound}: arbitrarily many compressions can read the same cell in one small frame. This is a conditional feasibility branch, not a completed full-ZK proof.

\subsubsection{A load bound and an exact label assignment}

Keep the $65536$ real/filler compression positions and their bytecode-normalized placement fixed. Suppose each memory address receives at most $\zkBlakeLoad$ accesses from these rows, counting all nine operand roles and any aliases. Their addresses are disjoint from the padding libraries. At every such address, assign its BLAKE2s accesses the initial integer labels $0,\ldots,k-1$, then assign every other opcode's accesses the remaining labels. This preserves all values, complete read chains, final counters, bytecode labels and row positions. Each BLAKE2s label is at most $\zkBlakeLoad-1$. Consequently its real exponent in any one column and coarse interval satisfies
\[
 0\le u_{c,j}\le\zkMemoryCoarseCap=4096(\zkBlakeLoad-1),
 \qquad c<9,\quad j<16.
\]
The bound needs neither public addresses nor public control flow. Prioritizing these labels can change the other opcode columns, which still require normalization.

\paragraph{A static sufficient condition.} Suppose every call owns a fresh disjoint frame, each BLAKE2s operand stays inside that frame, and the function's control-flow graph inside the frame is acyclic. Count the BLAKE2s operand occurrences at each relative cell in the public function body, including output and aliased roles. If this count is at most $\zkBlakeLoad$ in every function, the dynamic load bound follows: a cell belongs to only one call and each instruction executes at most once there. Private branches can only omit occurrences. Loops must advance to fresh frames, or require a separate public visit bound. This gives a checkable program-class certificate without revealing the call trace; the existing compiler and reservation-aware allocator have not yet been proved to supply it.

\begin{lemma}[Two labels per interval]\label{lem:zk-two-label-router}
For any $u_0,\ldots,u_{15}\in[0,\zkMemoryCoarseCap]$, put $\zkMemoryCoarseTarget=\zkMemoryCoarseCap+61$. There are $32$ distinct labels $a_j,b_j\in\{0,\ldots,\zkMemoryCoarseTarget\}$ such that $a_j+b_j=\zkMemoryCoarseTarget-u_j$ for every $j$.
\end{lemma}
\begin{proof}
Process the intervals in order. Choose $a_j\in\{0,\ldots,30\}$, then set $b_j=\zkMemoryCoarseTarget-u_j-a_j$. Always $31\le b_j\le\zkMemoryCoarseTarget$, so a low label cannot equal a high one. Previously used low labels exclude at most $j$ choices; previously used high labels exclude at most another $j$. Since $2j\le30$, some choice remains. The unused labels form the absorber's exact complement. This is a deterministic construction, not a mixing or concentration argument.
\end{proof}

\subsubsection{One frame, nine independent routers}

Use $32$ repetitions of a known baseline compression in one shared frame, two rows in each coarse interval. Its nine distinct operand cells have offsets $0,1,2,3,8,9,10,11,12$; its return controls remain at $16,17,18$. A separate closed loop contains nine XOR instructions, one per operand cell, and a JUMP using controls $24,25,26$. Each XOR reads its target cell twice, as operands $a$ and $c$, and zero at offset $30$ as operand $b$. The required value relation is simply $v\mathbin{\mathrm{XOR}}0=v$: writing the same value to the same cell satisfies the existing write-once arithmetization. No fresh output cell or verifier operation is needed.

Repeat the XOR loop
\[
 \zkCopyRepeats=\frac{\zkMemoryCoarseCap+30}{2}
 =2048(\zkBlakeLoad-1)+15
\]
times. Each target address then has $32+2\zkCopyRepeats=\zkMemoryCoarseTarget+1$ reads. Independently in each of the nine chains, assign its compression rows the labels from Lemma~\ref{lem:zk-two-label-router} and its XOR accesses the complement. Thus the real rows and router contribute exactly $\zkMemoryCoarseTarget$ to every column/interval exponent. All other Flock padding contributes known coarse offsets. The integer sums, and hence the $144$ products, are public. Different count columns use distinct target cells, so their assignments cannot conflict.

The XOR zero cell has the fixed read count $9\zkCopyRepeats$. Both return loops have fixed visits and disjoint control cells. Every chain, including those auxiliary cells and all code locations, is complete. The nine complementary label sums vary with the real trace; the uncertainty moves into \texttt{XOR.cnt\_a} and \texttt{XOR.cnt\_c}. Final counters of this router are public, but those of the real execution need not be. Neither fact supplies a simulator for the remaining count tree.

\subsubsection{Preserving the existing masks and prefix}

There are $3840$ general-input positions in each coarse interval after the first. In the first, only $437,438,439$ remain outside the five protected general-input positions. Directly using two of these for witness-dependent labels would invalidate the retained $4096$-point prefix law. Instead move the last individual pair of the low bank, originally at $9567,12287$, to $437,438$, retaining its original labels and independent swaps. Use the two vacated positions for routers. In every other interval use the first two general-input positions. All $32$ router positions are now at least $4096$. No mandatory profile position, calibration row, adapter or protected row moves; the complete packed compression witness may remain unchanged by choosing the known baseline at the exchanged general positions.

The moved pair is slot fifteen of block pair $119$. Its geometric label factors are unchanged, and both old and new positions remain in coarse interval zero. To prove privacy, conservatively omit \emph{all} sixteen slots of block pair $119$ from the low-bank span arguments, conditioning on their independent bits. The native exhaustive certificate verifies both remaining high-region quotient spans at all $8192$ thirty-two-point cosets, and the remaining $87$ prefix-unexposed low scalar weights at all $32256$ sixteen-point cosets. Every tested map is still onto $\K$; the low certificate also checks the actual additive NTT. The proofs of Theorems~\ref{thm:zk-split-region-interface} and~\ref{thm:zk-prefix-split-interface} therefore apply with those smaller exact spanning sets. There is no new exceptional-query probability for these two regions.

Only the relocated $\mathsf{cnt\_cv1}$ bit newly reaches the prefix. Its two known nonzero coefficient positions $437,438$ are disjoint from every previous visible direction. The prefix consequently encodes $1117$ independent fair bits, including the $32$ adapter bits, plus a public baseline. The new router's lane-$59$ coefficients vanish on this prefix. All changed non-BLAKE2s columns lie in other lanes; real BLAKE2s rows remain above the prefix. The old terminal and PC fixed-disclosure budgets are unchanged because the new visible bit belongs to the disjoint low bank.

The relocated count bits also continue to fix the eleventh-packet child: their physical residues are at least sixteen modulo sixty-four, outside its count-child-zero blocks. The $1536$ adapter directions and their $32$ visible bits are unchanged. Conditional on the real execution, the deterministic router labels and the omitted low-bank bits, repeat the old metadata replacements, then the adapter replacement. Their uniforms absorb the new terminal, child and selected-query translations. The memory/root and compression-value/Flock hybrids still have their original reserved random words and independent profile choices.

\begin{theorem}[Conditional full BLAKE2s coarse normalization]\label{thm:zk-memory-coarse-normalization}
Under the preceding load bound, reservations and common-completion/public-prefix assumptions, the source of Theorem~\ref{thm:zk-count-adapter-interface} admits the described modification. All $160$ height-fourteen BLAKE2s count products are public, including the bytecode column, with unchanged public heights and verifier equations. The same restricted boundary and eleventh-packet child have a joint simulator below $2^{-151}$, retaining the actual $1117$-bit law of the complete $4096$-point prefix. This does not include preceding GKR messages, the XOR disclosures or the full PCS opening.
\end{theorem}
\begin{proof}
The load bound and exact routers fix the nine memory frontiers. Existing independent masks preserve coarse products, including after the in-interval relocation. The bytecode calibration is unchanged; all added code visits and their placements are public offsets. The preceding conditional span argument proves the same restricted simulation with the same error ledger. No source randomness is credited to the deterministic router itself.
\end{proof}

\paragraph{Concrete reservation.} Reuse segment one's already reserved frame index five, at exponent $2^{22}+1280+32\cdot5$, for the shared router. It previously belonged to general position $437$ and is separate from the old low-bank frame. Leave the other reserved frames allocated; no new memory slot is required. The $32$ compression/return cycles keep code pair $1140,1141$ and the existing public total visits to that pair. Place their returns at their compression positions, applying the same public exchange to the two low-bank returns. Reserve XOR codes $1142,\ldots,1150$ and return code $1151$, ten additional positions, for $99$ altogether. Put their XOR rows at the first $9\zkCopyRepeats$ XOR positions and their returns at JUMP positions $2^{18},\ldots,2^{18}+\zkCopyRepeats-1$. These do not meet any Flock-side reservation; other libraries must use the complement.

For the illustrative public bound $\zkBlakeLoad=16$, this uses $276615$ XOR rows and $30735$ additional JUMPs, leaving $247673$ XOR and $821233$ JUMP positions before allocating the real execution and remaining libraries. The existing $26959$ wholly free $256$-cell slots remain available conservatively. General-input positions decrease from $57608$ to $57576$; all five protected rows and all $98304$ independent profile choices remain. This budget does not establish that an arbitrary small-frame program meets the read cap, that enforcing it by copying fits, or that the remaining opcode normalizers fit. Those are explicit P1 obligations.

\paragraph{Evidence and next obligation.} \auditref{zk_memory_count_coarse_audit.py} checks the exact transfer algorithm, maximum-profile positions and chains, disjoint prefix supports and the two exhaustive erasure certificates. Three finite valid frame-allocation patterns have identical $144$ frontier products, code/memory images and public row counts but different real final counters; the reference ISA, counted buses and complete label chains all pass. These are component checks, not a complete padded VM run. Next either realize the load cap through a reservation-aware compiler/allocator, or replace it by a wider-capacity router. Then normalize the remaining eighteen columns, including the transferred XOR/JUMP uncertainty, without consuming masks already needed by the joint proof.

\subsubsection{Thirty-two labels per interval: a stronger capacity theorem}

\begin{lemma}[Disjoint groups with independently prescribed sums]\label{lem:zk-group-label-router}
Let $\zkRouterWidth$ be a positive even integer, set $\zkRouterRadius=16\zkRouterWidth-1$, and suppose $\zkMemoryCoarseCap$ is divisible by $2\zkRouterWidth$. Put
\[
 \zkMemoryCoarseTarget=\zkMemoryCoarseCap+\zkRouterWidth\zkRouterRadius,
 \qquad
 \zkRouterLength=\frac{\zkMemoryCoarseCap}{\zkRouterWidth}+2\zkRouterRadius+\zkRouterWidth.
\]
For any $u_0,\ldots,u_{15}\in[0,\zkMemoryCoarseCap]$, one can assign $\zkRouterWidth$ distinct labels to each interval, all $16\zkRouterWidth$ labels distinct in $\{0,\ldots,\zkRouterLength-1\}$, with interval sum $\zkMemoryCoarseTarget-u_j$.
\end{lemma}
\begin{proof}
For interval $j$, write its required sum as $\zkRouterWidth q+t$, $0\le t<\zkRouterWidth$. Choose $\zkRouterWidth/2-1$ pairs $(q-a,q+a)$ and a last pair $(q-a,q+a+t)$. For each pair choose $a\in\{1,\ldots,\zkRouterRadius\}$ avoiding all labels already assigned. A used label excludes at most one choice of $a$: the lower endpoint is below $q$ and the upper one above $q$. Before any pair there are at most $16\zkRouterWidth-2$ used labels, fewer than the available gaps. Thus a choice always exists. Also $q\ge\zkRouterRadius$ and $q\le\zkMemoryCoarseCap/\zkRouterWidth+\zkRouterRadius$, so every endpoint is in the stated chain. The sums and distinctness follow by construction.
\end{proof}

Set $\zkRouterWidth=32$ and use $512$ shared-frame compressions. The same nine XOR self-copy instructions now need only
\[
 \zkCopyRepeats=\frac{\zkRouterLength-512}{2}
 =64(\zkBlakeLoad-1)+271
\]
repetitions. Lemma~\ref{lem:zk-group-label-router} assigns their compression labels independently in each operand chain; the XOR reads receive the complement. The total memory exponent is still transferred into XOR, but its correction capacity now grows with the number of compression labels per interval. At $\zkBlakeLoad=256$ the cost is $149319$ XOR rows and $16591$ extra JUMPs, leaving $374969$ and $835377$ respective positions in the candidate layout.

\paragraph{Freeing the first interval's thirty-two rows.} The preceding privacy proof already discards all sixteen slots of block pair $119$ from its spanning sets. Move its other thirty rows to the first thirty general-input positions of interval one, assigning each original pair to two consecutive selected positions. Keep slot fifteen at $437,438$. Use all $32$ vacated positions, $9552,\ldots,9567$ and $12272,\ldots,12287$, for the first interval's routers, and the first thirty-two remaining general-input positions in each other interval. The low bank keeps its original complete chains and all independent swaps; each moved pair stays inside a single coarse interval. Its public coarse offset moves by $\sum_{n=3808}^{3837}n=114675$ from interval zero to interval one in each of the ten columns. Its returns follow the same permutation. General-code visits and mandatory calibration are unchanged.

No new proof erasure is needed: the same $87$ low scalar weights and the same high quotient maps suffice. The relocated positions still avoid count-child-zero residues, and only the same one bit reaches the prefix. Thus Theorem~\ref{thm:zk-memory-coarse-normalization}, its $1117$-bit prefix law and its error below $2^{-151}$ all extend to this variant. It uses the same $99$ code locations and conservative frame reservation, leaving $57096$ general-input positions. The audit checks both router widths, their full chains in three finite valid libraries each, and the exact maximum-profile geometry. This construction supersedes the two-row variant for the active capacity plan, but still excludes the other eighteen count columns and the full transcript.

\paragraph{What the current compiler supplies.} The read-only example \path{crates/rec_aggregation/examples/zk_frame_load_audit.rs} counts all nine operand occurrences at each relative cell of every emitted function, excluding the ordinary filler cycles. These are public static upper bounds under the fresh-frame, single-visit contract, not dynamic measurements or certificates for arbitrary hinted executions. The compiler lowers runtime loops to recursive fresh-frame calls, copies scalar and stack-buffer arguments into callees, and bridges heap-backed compression operands through local cells. Its inlining and constant pooling can substantially increase same-frame incidence. The audit checks the actual aggregation guest against the public cap $256$ and exhibits an explicit straight-line sixteen-compression program whose aliased message cell is read $64$ times in one small frame. Function calls therefore help establish the contract, but neither frame size nor the mere presence of calls implies bound sixteen.

The aggregation guest is not yet covered as a whole: its bytecode exceeds the current eleven-bit code reservation; large allocations need the multi-slot allocator of Proposition~\ref{prop:zk-multislot-allocation}; and ordinary range checks dereference numerical addresses, which require the public-prefix variant below. The ZK sampler must also replace ordinary repeating filler cycles, establish pointer semantics and total allocation bounds, and fit the remaining normalizers. The improved read-capacity theorem removes one quantitative mismatch, not these common-sampler obligations.

\subsubsection{Compatibility with the public range-probe prefix}

Theorem~\ref{thm:zk-public-probe-envelope} moves the segment-zero mask bank and payload by $65536$ address exponents, leaving segments one through seven alone. The frame-capacity calculation does not by itself preserve the joint metadata proof. Here the relevant library has a useful additional property: all $21500$ operand/frame/PC/count frames and the single low-bank frame lie in segment zero, while the general-input rows, bytecode calibration and MUL adapters occupy the other two payload segments.

\begin{corollary}[The restricted interface survives frame relocation]\label{cor:zk-probe-relocated-interface}
Use the thirty-two-label router, the public range-probe prefix and the relocated frame reservation just described. Retain the load bound, valid common completion and public count-prefix hypotheses of Theorem~\ref{thm:zk-memory-coarse-normalization}. Its complete conclusion still holds: all $160$ coarse BLAKE2s count products are public, and its restricted joint view, including the earlier adapter child and the $1117$-bit prefix law, has a simulator below $2^{-151}$. The reservation leaves $26703$ free $256$-cell slots before fragmentation. This is not a claim that the old transcript is unchanged by relocation.
\end{corollary}
\begin{proof}
Multiply every relocated library frame pointer by the fixed nonzero element $\gen^{65536}$. Keep instruction addresses, relative operands, compression data, count labels and physical row positions. In the closing JUMP also multiply its target frame word by this element. The library accesses are thereby renamed injectively within their disjoint reservation, and each complete compression/return cycle is still valid. The return-control cells are disjoint from compression operands, so no compression input changes. Chains and code visits retain their lengths and labels. For each fixed choice of these new frame addresses, the original private swaps still preserve the bus multisets, memory image, code image and packed compression witness.

The nine memory-count and bytecode-count directions are unchanged. In particular every BLAKE2s count-column frontier, all lane-$59$ source polynomials, every prefix disclosure and both exhaustive low/high query spans are identical to those of the thirty-two-label construction. Its omitted block pair $119$, adapter supports and fixed-disclosure budgets are unchanged. The final-memory-count vector is reindexed, but lies outside lane $59$ and contributes only an arbitrary fixed complement to the child replacements. No statement about its own privacy follows here.

For the remaining terminal metadata and actual final GKR children, repeat the triangular proof of Theorem~\ref{thm:zk-flock-children-interface}. The seven operand projections are unchanged. The frame bank's direction becomes
\[
 \gen^{65536}\gen^{1280}(1+\gen^{32})\gen^{64i},
\]
so precisely the old weighted-span event supplies its terminal frame uniform. In each PC pair the two frames are equal. The bus forms contain the PC and each count only as singleton monomials. The residual $P_t+\gen Q_t$ cancels every count term; its PC coefficient is the same nonzero bytecode-address coefficient as before. Multiplying the common frame therefore changes neither the PC residual direction nor its fixed prefix map. Finally, the child count-plane matrix depends on the count coefficients, not on frames. Its minor and all conditional count spans are unchanged. All other translations caused by the relocated operand/frame banks are absorbed in the same later PC/count coordinates. The stronger prefix and split-region proofs use these same projections, so the same argument applies on their retained fibers.

Perform those metadata/child/raw-query replacements first, then the unchanged adapter replacement. Their private choices preserve the relocated memory image and shared product root. Apply the root-decoupling hybrid and the new memory-envelope simulator while retaining these uniforms; simulate the unchanged compression-value/Flock interface last. This order does not retain actual children while independently replacing their root. Only the memory-envelope term in the previous exact ledger changes, from $3(22+12)/2^{192}$ to $3(2\cdot22+12)/2^{192}$. The additional $66/2^{192}$ leaves the total below $2^{-151}$. Capacity is the four-run calculation in \noteref{zk-memory-frames}.
\end{proof}

\paragraph{Evidence.} The \nolinkurl{--relocated-library} mode of \auditref{zk_memory_probe_prefix_audit.py} rebuilds every metadata compression/return cycle at the new addresses, checks all $56700$ nonzero lane-source directions against the actual rows, verifies the frame rescaling and PC/count bus identities, reproduces the joint boundary ranks and checks independent swaps and the relocated low-bank chains. The revised total error is checked exactly. This closes compatibility of the established BLAKE2s/count-query interface with the public range-probe memory construction, not common completion. A general compiler/bootstrap, reserved code placement, total allocation and the remaining opcode normalizers are still missing; so are the earlier GKR messages, other table/Flock messages, full query family, complete opening and authentication.
