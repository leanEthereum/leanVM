\subsection{Memory: a fixed-prefix obstruction and a small-frame repair}\label{note:zk-memory-frames}

\paragraph{Conclusion.} Restricting programs to relocatable small frames is a useful repair, provided a public allocator reserves specific addresses for genuinely unused random words. Ordinary function calls alone do not provide this guarantee. We prove an obstruction for unrestricted execution-preserving padding, then a pin-preserving memory-value construction that avoids it and hides its complete algebraic opening envelope. The envelope covers the memory dependence of the actual mixed PCS. Joint simulation with access counts, the bus transcript, other committed columns and authentication remains outside the positive theorem.

\subsubsection{Why unrestricted memory padding fails}

The current encoder treats each initial lane's entries directly as novel-basis coefficients. For the field elements whose standard binary encodings are \texttt{2} and \texttt{3}, not the integers interpreted in characteristic two, its basis satisfies
\[
 (\novel_0(x),\novel_1(x),\novel_2(x),\novel_3(x))=(1,x,1,x),
 \qquad \novel_j(x)=0\quad(j\ge4).
\]
Indeed, $x$ lies in $\subsp_2$, the first normalized subspace polynomial is $X$, and $\Wn{1}(x)=1$. Every index $j\ge4$ has a higher nonzero bit whose subspace factor vanishes. Consequently, a lane starting with $(0,0,b,0)$ exposes $b$ at either query, regardless of every later coefficient. The verifier receives the raw pre-fold lane, so later folding cannot erase this disclosure.

\begin{proposition}[An unavoidable aligned memory prefix]\label{prop:zk-memory-alignment}
For every accepted leanVM layout with $\kmem\ge20$ and stack log $\mu\le28$, either the low or the top memory-value limb starts at an initial PCS lane boundary.
\end{proposition}
\begin{proof}
Put $\nmem=2^{\kmem}$ and $\zkLaneLen=2^{\mu-6}$. The three memory-value columns and the final-memory-count column have size $\nmem$ and global indices $0,1,2,3$. Decreasing-size placement, with ties broken by index, places these four blocks consecutively. Their initial offset is a multiple of $2\nmem$, because every preceding block is strictly larger than $\nmem$. Since $\zkLaneLen\le4\nmem$, either $\zkLaneLen\le2\nmem$ and the low limb is aligned, or $\zkLaneLen=4\nmem$ and adding $2\nmem$ aligns one of the low and top limbs. This argument allows arbitrary accepted table heights.
\end{proof}

\begin{proposition}[A privacy floor for execution-preserving padding]\label{prop:zk-memory-floor}
There is a fixed public program with two valid executions and the same public inputs and heights such that every padding strategy preserving its accessed memory values has the following property. In the honest interactive experiment with independent uniform initial queries, any common simulator has error greater than $2^{-21}$ for at least one execution, for every common accepted padded layout. This includes padding that permutes instruction rows, inserts cycles, relabels read counters and randomizes unused memory.
\end{proposition}
\begin{proof}
Use public inputs zero, a private word $\mem[\gen^2]=b(1+y+y^2)$ with $b\in\{0,1\}$, and an XOR of that word with itself writing $\mem[\gen^3]=0$. A SET at index $2^{19}$ forces $\kmem\ge20$. Finish through public control cells outside the first four indices; standard filler blocks complete all table sizes. Both executions are valid, and every value limb starts with $(0,0,b,0)$.

The aligned limb in Proposition~\ref{prop:zk-memory-alignment} is determined by the public layout. Let $D=2^{\mu-6+\rexp}$ be the initial query-domain size, with $1\le\rexp\le4$, and let $q$ be the number of initial queries. The observable event that one of them equals \texttt{2} or \texttt{3} has probability $p=1-(1-2/D)^q$. On this event the selected authenticated raw lane reveals $b$ exactly. The two real views therefore have statistical distance at least $p$, so a common simulator has error at least $p/2$ for one of them. Current configurations satisfy $D\le2^{26}$ and $q\ge56$, giving
\[
 \frac p2\ \ge\ \frac{1-(1-2^{-25})^{56}}2\ >\ 2^{-21}.
\]
Taking a projection of the full view cannot increase distance. Correlations with the other padding or later messages cannot remove this lower bound.
\end{proof}

\paragraph{Scope and native evidence.} This rules out a general compiler-free, execution-preserving padding transformation for the current query domain, not arbitrary ZK provers or a publicly specified restricted program class. In particular, discarding the supplied witness, recompiling or relocating its private accesses is outside the proposition. The native example \path{crates/lean_vm/examples/zk_memory_prefix_audit.rs} constructs both complete valid VM proofs with memory log $20$ and stack log $23$. Separately, it checks the exceptional leaves with the actual scalar NTT, interleaved commitment and authenticated pruned paths. The complete Fiat-Shamir proofs use their ordinary queries; those runs do not force the exceptional event or establish a Fiat-Shamir probability theorem.

\subsubsection{The small-frame contract}

Fix the public memory height and reservation set before seeing the witness. Every real or padding access, including frame headers, returns, arrays, indirect accesses and filler frames, must avoid the reserved addresses. Each allocation fits a public slot of size $\zkFrameSize$; larger buffers must use an explicitly supported layout. For every supported witness, prove that its execution can be relocated into these slots with frame-relative addressing and pointers preserving the program's semantics. Code that observes numerical addresses requires its own argument. The entry point must also keep private values out of the reserved initial prefix, using public compilation or a bootstrap if necessary. These are restrictions on the public program and its allocator, not new verifier checks or permission to choose a different program after seeing the witness.

Current calls already receive frame addresses through allocation hints, and the executor uses an integer-index bump allocator. The research-only interval allocator below now skips reserved blocks for both these hints and filler frames, without changing the ISA or verification equations. It is not a full ZK sampler. Returning from a function does not free its committed values: leanVM memory is write-once, so the capacity bound counts all allocated frames, not just simultaneously live ones. In particular, used intermediate values cannot simply be overwritten by randomizers.

\begin{lemma}[Legal unused words]\label{lem:zk-unused-frame-words}
For any execution satisfying this contract, replacing each reserved unused word by an independent uniform element of $\E$ preserves the instruction constraints, public inputs, bus balance and all read counts.
\end{lemma}
\begin{proof}
No instruction reads or writes a replaced cell. Its seed and finalization tuples contain the same address and new value, with count $1$ on both sides. The replacement therefore changes neither their balance nor any count. Its three $\K$ limbs are independent uniform elements. This is a statement about valid witnesses, not about the distribution of their bus proof messages.
\end{proof}

\subsubsection{A prefix that respects public inputs}

Put $\zkLaneLen=2^{\zkLaneLog}$ and
\[
 \zkPinSpace=\{h\in\K^{\zkLaneLen}:h_0=h_1=0\}.
\]
This is the difference space needed to preserve the two public-input coefficients. Every polynomial with coefficients in $\zkPinSpace$ vanishes at $0,1$, and conversely: the encoder evaluations there are $h_0$ and $h_0+h_1$.

\begin{lemma}[Perfect hiding of initial memory queries]\label{lem:zk-pinned-prefix}
Keep $f_0,f_1$ public and reserve coefficients $2,\ldots,t+1$ as independent uniform masks. Any at most $t$ distinct initial evaluation queries have a witness-independent joint distribution. Queries at $0,1$ have their prescribed public answers; all other distinct answers are uniform and independent.
\end{lemma}
\begin{proof}
The consecutive polynomials $\novel_2,\ldots,\novel_{t+1}$ form a basis for the degree-at-most-$t+1$ polynomials divisible by $X(X+1)$. Dividing by this factor leaves a degree-$0$ through degree-$t-1$ basis. Evaluation on any at most $t$ distinct points outside $\{0,1\}$ is onto by interpolation. Uniform masks therefore absorb every private-data shift. Repeated queries add no information.
\end{proof}

For the full algebraic opening, use a power of two $\zkPadBlock>q+2$, where $q$ bounds the initial query count, and assume $\zkLaneLen\ge8\zkPadBlock$. Define
\[
 \zkPrefixSpace=\{h\in\zkPinSpace:\operatorname{supp}(h)\subseteq\{2,\ldots,5\zkPadBlock-1\}\}.
\]
For a fixed distinct query set $\qset$, define the common $\K$-linear observation map
\[
 V(h)=\bigl((\Enc(h)[x])_{x\in\qset\setminus\{0,1\}},\ \mle h(r)\bigr),
 \qquad r\gets\E^{\zkLaneLog}.
\]
The last entry represents three $\K$ coordinates.

\begin{lemma}[A query-safe prefix with public pins]\label{lem:zk-pinned-envelope-prefix}
Except with probability at most $(\zkLaneLog+3)/|\E|$ over the independent point $r$, the restriction $V|_{\zkPrefixSpace}$ is onto its displayed codomain. The bound is uniform in every fixed query set of size at most $q$, including sets containing $0,1$.
\end{lemma}
\begin{proof}
Lemma~\ref{lem:zk-pinned-prefix} supplies the query coordinates. Put $Z(X)=\prod_{x\in\qset\cup\{0,1\}}(X+x)$. Its degree is at most $q+2<\zkPadBlock$ and its first two novel-basis coefficients vanish. The five coefficient vectors of $Z(X)\novel_{j\zkPadBlock}(X)$, $j=0,\ldots,4$, lie in $\zkPrefixSpace$ and in the query kernel. Disjoint low and high index bits give exactly the factorization in Lemma~\ref{lem:prefix}: a nonzero low-coordinate multilinear polynomial, a tail selector and five Boolean weights. Its proof, with the same five-weight lemma, supplies the three extension coordinates with failure at most $(\zkLaneLog+3)/|\E|$.
\end{proof}

\subsubsection{Hiding the entire first-folded memory contribution}

Split one memory-value column into eight equal initial-lane segments. Reserve the five complete segments
\[
 \zkFreeLanes=\{3,4,5,6,7\}=7\mathbin{\oplus}\{0,1,2,3,4\},
\]
and the first $5\zkPadBlock$ cells of segments $0,1,2$, except global indices $0,1$. Here $\oplus$ is bitwise exclusive-or. These two excluded cells hold the public input. Let $\zkMemoryMasks$ be this address set. All its cells are unused and independently uniform; fixed real data occupies only the remaining addresses.

\begin{theorem}[Pin-preserving memory envelope]\label{thm:zk-memory-envelope}
For an independent uniform column point $r\in\E^{\zkLaneLog}$ and three independent uniform lane-fold coins, the joint view consisting of every segment's initial query answers, its first two coefficients, every $\mle f_l(r)$, and the entire folded vector $F=\sum_{l=0}^7\eq(\fc,l)f_l$ has an efficient simulator receiving only the two public coefficients, with error at most
\[
 \frac{\zkLaneLog+9}{|\E|}.
\]
The query list may be arbitrary of length at most $q$, independently of $r,\fc$. This includes all later algebraic PCS disclosures for an eight-lane vector with a single common-point initial weight, also allowing weights supported on the first two coefficients of any segment. In particular, the public-input line introduces no further error. It excludes preceding VM disclosures, authentication and Fiat-Shamir.
\end{theorem}
\begin{proof}
Compare two choices of the real coefficients, with the same public pins. Their differences in every segment lie in $\zkPinSpace$, since every segment's first two coefficients are either public or reserved masks. On the event of Lemma~\ref{lem:zk-pinned-envelope-prefix}, translate masks in $\zkPrefixSpace$ to move all eight differences into $\ker V\cap\zkPinSpace$.

The five fold weights on $\zkFreeLanes$ span $\E$ over $\K$ except with probability $6/|\E|$. This is Lemma~\ref{lem:five} after complementing the three fold coordinates. Each $\K$ coordinate vector of the residual folded difference is still in $\ker V\cap\zkPinSpace$. A fixed right inverse of the five fold weights therefore cancels the whole folded difference using corrections in the five fully random segments, themselves in this kernel. No correction touches either public pin or any real coefficient.

The resulting translation is a bijection of the uniform mask space and preserves every component of the enlarged view, including each segment's first two coefficients because every correction lies in $\zkPinSpace$. Its law is thus identical for both real vectors on good coins. The simulator keeps the public coefficients, sets other nonreserved entries to zero, samples the masks and computes the view. The union bound gives the stated error. Before the first fold finishes, the allowed initial weights use the segments only through their retained MLEs and first two coefficients. Every later witness-dependent algebraic opening message is determined by $F$ and the honest coins, as in Theorem~\ref{thm:pcs-padding}.
\end{proof}

\paragraph{Embedding in the actual stack.} Suppose $\mu=\kmem+3$. Every memory column occupies an aligned group of eight of the sixty-four initial lanes, even if larger columns precede memory: those columns have sizes divisible by $2\nmem$, and memory wins every size tie. The first three PCS folds process the three low lane bits, so each memory column folds internally before it can mix with another column. The three-limb envelope therefore has error at most $3(\zkLaneLog+9)/|\E|<2^{-185}$ under $\mu\le28$. No nonzero selector on the other lane bits is needed. We may retain the previous, slightly weaker bound $3(\zkLaneLog+12)/|\E|$ in existing error ledgers.

\begin{proposition}[Isolation inside the actual mixed PCS]\label{prop:zk-memory-pcs-isolation}
Fix every non-memory-value coefficient, the honest coins and all claimed values outside the three memory-value columns. Suppose the initial weight on each memory-value column is a multiple of one common-point equality weight plus a weight supported on its two public-input coefficients. Then the entire algebraic PCS view depends on the memory-value columns only through the three envelopes of Theorem~\ref{thm:zk-memory-envelope}. The weights outside these columns may be arbitrary. The actual leanVM claim family satisfies this restriction.
\end{proposition}
\begin{proof}
Before the first three lane folds finish, a memory lane interacts only with lanes of its own column. Every inner product contributing to their sumcheck polynomials is a linear combination of that lane's retained common-point MLE and first two coefficients. After those folds, its entire contribution to the committed vector is the retained $F$. All subsequent folds, introduction polynomials, deeper query answers and final plaintext entries are functions of these vectors, the fixed complement and the coins. Initial raw query answers are retained separately.

In the actual verifier, the three framework memory-value claims use one common GKR point. The public-input claims have point $(r_{\mathrm{pi}},0,\ldots,0)$, hence support only on the first two coefficients. Table columns, count columns, bytecode and Flock's packed vector occupy disjoint blocks. Their selectors and Frobenius weights may be complicated, but cannot reach an unfolded memory column before its first three internal folds. Batching merely scales the displayed weights. The retained envelopes also determine all memory claim values used to form that batch.
\end{proof}

This is a conditional factorization and a coupling for changes to memory values, not a witness-free simulator for the fixed non-memory data or preceding reductions. It does remove the isolated-one-point restriction for the memory contribution to the actual mixed PCS.

\paragraph{Frame capacity.} Choose a power-of-two slot size $\zkFrameSize\le\zkPadBlock$, so it divides both $\zkPadBlock$ and $\zkLaneLen$. All reserved regions are unions of whole slots, with the public-input exception. Allocate real and padding frames only in the three intervals $[l\zkLaneLen+5\zkPadBlock,(l+1)\zkLaneLen)$, $l=0,1,2$. This gives
\[
 \frac{3(\zkLaneLen-5\zkPadBlock)}{\zkFrameSize}\ \text{slots},
 \qquad |\zkMemoryMasks|=5\zkLaneLen+15\zkPadBlock-2.
\]
For example, $\kmem=20$, $\mu=23$, $\zkPadBlock=\zkFrameSize=256$ allows $1521$ slots and $389376$ payload cells. The current maximum initial query count is $228$, so $\zkPadBlock>q+2$ holds. This is a conservative memory-only capacity example, not a reservation theorem for all existing bus, count and Flock libraries. The verifier equations are unchanged, but reserved memory can increase commitment size and public heights.

\paragraph{Why a periodic gap is weaker.} Reserving only the first half of every power-of-two frame leaves one fixed address bit equal to zero on every mask. If a later PCS level exposes that bit as a pre-fold lane, its other lane is unmasked by Proposition~\ref{prop:lane}. The five complete random segments above instead hide the entire first-folded vector, so no separate assumption about later query geometry is needed. A mere density of random cells is not the invariant we need.

\begin{proposition}[Larger frames in consecutive payload slots]\label{prop:zk-multislot-allocation}
The memory-envelope and memory/root theorems do not require each allocation to fit one $256$-cell slot. In the reservation of Section~\ref{sec:zk-flock-reservation}, the wholly free slots form four runs of lengths $5503,8187,9178,4091$. Round each requested allocation up to whole slots. If every rounded request has at most $\zkAllocationCap$ slots and their total is at most
\[
 26959-3(\zkAllocationCap-1),
\]
a forward allocator, skipping to the next run when a request does not fit, completes without entering any reserved cell. The guarantee includes all allocated objects, not only live frames.
\end{proposition}
\begin{proof}
Segment zero has free slot intervals $[2688,8191)$ and $[8192,16379)$; the other two have $[7201,16379)$ and $[12288,16379)$. These follow directly from the reserved frame sets. At each of the three possible run transitions the allocator abandons fewer than $\zkAllocationCap$ slots. If some request failed in the last run, the total rounded demand would exceed total free space minus this abandoned space, contradicting the displayed bound. Every granted allocation is contiguous and disjoint, so ordinary relative offsets remain available within it. The privacy proofs use only that the designated mask set is unused; its geometry and random dimension have not changed.
\end{proof}

This is a capacity theorem, not a relocation theorem for code inspecting numerical addresses or dereferencing fixed absolute addresses. The current range-check lowering in \path{crates/lean_compiler/src/lower.rs} touches the address represented by its operand and by its complementary exponent, even when all call frames are fresh. Those accesses can hit the mask prefix. A shifted or replaced range-check gadget needs its own soundness and capacity argument; simply declaring those read words unused is invalid. The public entry point, heap operations and ordinary filler also remain part of the allocator contract.

Another possible repair is to randomize these semantically unconstrained probe values and propagate each change to its local DEREF copy. This preserves the instruction's value equality, but couples the memory masks to additional committed words and table columns. It would require a new joint masking theorem; the present proof, which fixes all non-memory-value coefficients, does not establish it.

In particular, shifting both range-check dereferences by a positive public exponent $b$ while keeping the test $xy=\gen^{k-1}$ is unsound. The invalid input $x=\gen^{-1}$ and complement $y=\gen^k$ pass that product test, and their shifted addresses have valid integer exponents $b-1,b+k$ whenever $1\le b$ and $b+k<\nmem$. The unshifted gadget used nonnegative address exponents to exclude this case; the shift loses that lower bound. \auditref{zk_memory_count_coarse_audit.py} checks the multi-slot allocator and a complete five-instruction shifted-check cycle with $b=4096,k=8$ against the reference ISA and counted buses. Both probe addresses are outside the mask prefix, yet the asserted range is false. This rejects the naive shifted gadget, not a different range-check construction.

\subsubsection{Keep the range probes public, move the masks}

\paragraph{A repair without new instructions.} The range-check problem does not require shifting its probes or bit-decomposing its operand. Instead, make their entire possible address prefix public and move the unused mask bank beyond it. Only the first memory segment needs this change. The following variant proves the memory envelope and its shared-root composition. Corollary~\ref{cor:zk-probe-relocated-interface} separately carries the established restricted BLAKE2s/count-query interface through the frame relocation; neither result proves full ZK.

Let $\zkProbePrefix=2^{\zkProbeLog}$ satisfy $5\zkPadBlock\le\zkProbePrefix$ and $\zkProbePrefix+5\zkPadBlock\le\zkLaneLen$. Fix the first $\zkProbePrefix$ words to a public vector, namely the two public inputs followed by zeros. In segment zero replace the old reserved prefix by the $5\zkPadBlock$ unused words at offsets $\zkProbePrefix,\ldots,\zkProbePrefix+5\zkPadBlock-1$. Leave segments one through seven unchanged. All remaining accesses avoid these random banks, but may probe the fixed public prefix.

\begin{lemma}[An unused mask bank after a public prefix]\label{lem:zk-probe-prefix}
Fix any query set of size at most $q$. On the coefficient space supported in $[\zkProbePrefix,\zkProbePrefix+5\zkPadBlock)$, the joint map of evaluations outside $\subsp_{\zkProbeLog}$ and one independent uniform-point MLE is onto, except with probability at most $(\zkLaneLog+3)/|\E|$. Evaluations inside $\subsp_{\zkProbeLog}$ vanish for every difference of coefficient vectors agreeing on their first $\zkProbePrefix$ entries.
\end{lemma}
\begin{proof}
The novel-basis polynomials with indices at least $\zkProbePrefix$ span the polynomials of degree below $\zkLaneLen$ divisible by $\Wn{\zkProbeLog}$. For $0\le i<5\zkPadBlock\le\zkProbePrefix$, disjoint index bits give
\[
 \novel_{\zkProbePrefix+i}(X)=\Wn{\zkProbeLog}(X)\novel_i(X).
\]
The first factor is nonzero outside $\subsp_{\zkProbeLog}$. Interpolation therefore supplies all displayed query coordinates. Put $Z(X)=\prod_{x\in\qset\setminus\subsp_{\zkProbeLog}}(X+x)$. Its degree is below $\zkPadBlock$. The five polynomials $\Wn{\zkProbeLog}Z\novel_{j\zkPadBlock}$, $0\le j\le4$, lie in the shifted mask bank and the query kernel. Their coefficient MLEs have the factorization of Lemma~\ref{lem:prefix}, except that the tail selector uses $r_{\zkProbeLog}$ in place of $1+r_{\zkProbeLog}$. Exclude zero rather than one for that coordinate. The same five-weight span and degree argument gives $(\zkLaneLog+3)/|\E|$.
\end{proof}

\begin{theorem}[Memory privacy with public range probes]\label{thm:zk-public-probe-envelope}
For this modified reservation, the entire envelope of Theorem~\ref{thm:zk-memory-envelope} has a simulator given only the public prefix, with error at most
\[
 \frac{2\zkLaneLog+12}{|\E|}
\]
per value limb. Proposition~\ref{prop:zk-memory-pcs-isolation} still applies. With the parameters of Theorem~\ref{thm:zk-memory-root-decouple}, the three-limb envelope jointly with the shared bus root still has total error below $2^{-151}$.
\end{theorem}
\begin{proof}
For segment zero, use Lemma~\ref{lem:zk-probe-prefix} to cancel the query and MLE difference. Queries in $\subsp_{\zkProbeLog}$ already have their fixed public answers. For the other segments use Lemma~\ref{lem:zk-pinned-envelope-prefix}. Both corrections preserve the first two coefficients. Every segment difference now lies in the common full observation kernel and in $\zkPinSpace$, so the unchanged five fully random segments cancel the entire folded difference exactly as before. Two prefix exceptions and the $6/|\E|$ fold-span exception give the displayed bound. The simulator retains the public prefix and sets all other nonreserved coefficients to zero before sampling masks.

The root-kernel construction uses only segments three through seven, which have not changed. Their words remain unused even though the low public prefix is read. The root-decoupling theorem therefore retains its original error, uniformly in the accessed words, read labels and non-memory data. Add $3(2\zkLaneLog+12)/|\E|$ for the new envelope; with $\zkLaneLog\le22$ the sum remains below $2^{-151}$. This is the memory/root marginal, not simulation of the retained table data or intermediate GKR.
\end{proof}

\paragraph{The current range-check contract.} The compiler caps constant bounds at $2^{\texttt{MIN\_LOG\_MEM}}=2^{16}$. Runtime bounds retain their existing program obligation $1\le k\le2^{16}$. On an honest successful check, both probed exponents $e,k-1-e$ lie in $[0,2^{16})$. Thus $\zkProbePrefix=65536$ covers every such probe without changing a single range-check instruction or its soundness argument. Every copied word is an entry of the public prefix, including the possibly nonzero inputs at exponents zero and one. Which entry is copied, and its access count, may still be private; hiding that selection remains part of the table/count obligations. Every local destination belongs to the relocated private frame, and no random word is read by this gadget.

\paragraph{Capacity at the candidate height.} Keep $\kmem=25$, $\mu=28$ and $\zkPadBlock=256$. Translate every segment-zero payload frame by $65536$ address exponents, leaving the other segments alone. The conservative padding-frame sets still fit. In slot coordinates relative to the new segment-zero payload base $65536+1280$, its free runs become $[2688,8191)$ and $[8192,16123)$; the other runs remain $[7201,16379)$ and $[12288,16379)$. Their total is $26703$ slots, exactly $256$ fewer than before. The next-fit guarantee is consequently
\[
 \text{total rounded demand}\ \le\ 26703-3(\zkAllocationCap-1).
\]
This relocation preserves each existing padding frame's internal relative offsets and count-chain lengths, but changes its address-dependent table coefficients. The capacity calculation alone does not certify joint table-mask spans or a semantics-preserving transformation of the real program. Corollary~\ref{cor:zk-probe-relocated-interface} supplies the former argument for the established restricted interface; real-program relocation and the other table disclosures remain open.

\paragraph{Evidence and remaining integration.} \auditref{zk_memory_probe_prefix_audit.py} checks the shifted native-basis identity, all four allocation runs, legal translations annihilating a multilevel algebraic wire, and the actual six-bit lane schedule with arbitrary non-memory weights and public-input terms. It checks the revised root/envelope bound exactly. The native example \path{crates/lean_vm/examples/zk_memory_probe_prefix_audit.rs} uses a three-instruction public bootstrap to enter a payload frame, keeps the ordinary range gadget, and supplies seven exponents including both endpoints and both public-input probes. Two complete proofs and a separate scalar-NTT check test legality, not a full ZK distribution. The bootstrap shows that private entry cells need not occupy the public prefix; compiling a general entry point, relocating pointers and all padding libraries, proving total allocation and covering the other committed columns remain P1 obligations. No production prover or verifier is changed.

\subsubsection{A public entry wrapper and executable interval allocator}

\paragraph{Public prefix values need not be zero.} Theorem~\ref{thm:zk-public-probe-envelope} holds unchanged for any fixed prefix vector computable from the public statement, with its first two entries equal to the public inputs. Its proof compares vectors agreeing on the whole prefix, not specifically vectors with zero entries there. The same observation applies to its memory/root and restricted-interface corollaries. This permits public control words in the entry frame. It does not permit witness-dependent pointer or return values in that prefix.

\paragraph{Compiler construction.} Take a zero-argument, zero-result entry body that is not itself called by the source program. Give it a fresh ordinary function name, then compile a new \texttt{main} that calls it once and returns. Compile the body as an ordinary function, not by shifting the bytecode of the old \texttt{main}: its local jumps must use the actual frame pointer, whereas the old entry lowering substitutes one. The optional mask-loading hints use fixed public addresses and introduce no instruction accesses to the masks. This is a public program transformation and changes its bytecode digest before selecting a witness.

\begin{lemma}[A fixed public entry frame]\label{lem:zk-public-entry-wrapper}
Suppose the new entry frame fits below $\zkProbePrefix$, the first allocated body frame is chosen by a fixed public allocation policy, and the body respects its ordinary calling convention. Its only low-prefix accesses are prescribed public-input assertions and ordinary range probes into the fixed prefix. The wrapper's complete low-memory prefix is independent of the private execution. No private result is returned into it.
\end{lemma}
\begin{proof}
The ordinary zero-argument call places the callee entry PC, a nonzero constant and the hinted callee pointer in wrapper cells. The first allocation's size and base are public. Its two control stores copy the wrapper frame pointer and the return PC into the callee; neither reads a private callee value. The call receives no return cells. After the callee's return the wrapper stores its public halt destination and returns to the sentinel with frame pointer one. The compiler's constant pooling shares only these same public values. Thus every instruction that writes a wrapper cell writes a public value; all other low cells remain their prescribed public values. The body's control flow may be private, but it cannot change these words under the hypotheses. Count labels and the number of low-prefix accesses are not asserted to be public.
\end{proof}

\paragraph{The required address discipline.} View each allocated frame or buffer as an object, with its own base and relative indices. All instruction accesses must belong to that object, the public-input cells, or the permitted public range-probe prefix. Pointers may be copied, stored, returned and advanced by relative offsets within their object; data arithmetic, hashes, published values and branch tests must not inspect their numerical encodings. Equality of in-bounds pointers is allowed, since the same object/offset is preserved and distinct nonempty allocations are disjoint. Numerical address ordering, cross-object arithmetic and comparisons involving one-past or empty-buffer addresses need separate arguments and are not covered. Empty buffers may still be allocated and their pointers carried or discarded, but not dereferenced or observably inspected. The compiler's frame-pointer and return-PC stores are administrative pointer operations, not data leakage. No addresses, allocation history or control-flow trace are thereby declared public.

\begin{proposition}[Execution-preserving allocation under the address discipline]\label{prop:zk-reserved-allocation}
Fix a wrapped program satisfying this discipline, its public prefix and the candidate's four payload runs. Round every allocation, including an empty buffer, up from $\max(1,\text{requested cells})$ to whole $256$-cell slots. Assume each request uses at most $\zkAllocationCap$ slots and their total is at most $26703-3(\zkAllocationCap-1)$. The forward interval allocator realizes the same data computation and public outputs, never allocates a mask cell, and preserves valid instruction and bus relations. The guarantee counts call frames, static and runtime buffers, compiler helper allocations and any separately budgeted filler frames. It is a legality theorem, not a transcript-hiding theorem.
\end{proposition}
\begin{proof}
The four-run capacity proof applies to these positive rounded requests, including empty buffers. At every allocation choose the first aligned interval suffix large enough, discard any insufficient suffix and never move the cursor backward. Allocations are contiguous, disjoint and outside the mask reservation.

Relate the old and new executions by preserving object identities and relative offsets, copying data words, and updating every stored memory pointer to its relocated target. Public prefix addresses and code addresses stay fixed within this comparison of allocations of the same wrapped program. Proceed instruction by instruction. Frame-relative accesses and permitted pointer-offset products address corresponding cells. Data XOR/MUL and compression operations see identical data. Pointer copies, the current-frame store and saved return controls preserve the relation; JUMP destinations and allowed branch decisions therefore agree. Ordinary range checks see identical index values and the same public probe vector. Write-once consistency is preserved by disjointness and by the equality of all repeated writes at corresponding addresses. Pointers to empty objects have no observable use, so granting them a fresh slot cannot affect the computation.

Assign corresponding instruction accesses the same read labels at the renamed addresses. Every chain retains its length, data values and complete label set, with pointer values consistently relocated. Its seed and final tuples match the renamed instruction tuples, and state transitions match through the updated frame pointers. Thus the bus balances and all local instruction relations still hold. Replacing unused reserved words by independent uniform words is then legal by Lemma~\ref{lem:zk-unused-frame-words}. The allocation decisions cannot depend on these masks because no permitted computation reads them. Their independence, rather than a public allocation trace, is the needed property.
\end{proof}

\subsubsection{Public values do not hide the probe counts}\label{sec:zk-probe-count-prefix}

\paragraph{An uncovered initial lane.} Use the current candidate with $\kmem=25$, $\kbc=19$, $\mu=28$ and table log-heights $(19,19,19,19,20,18)$ in the usual opcode order. The final-memory-count column starts at initial lane $40$, offset zero. This is distinct from the value limbs and from the BLAKE2s count columns in lane $59$. Its coefficient at index zero is $\gen^{\zkProbeAccess(0)}$, where $\zkProbeAccess(j)$ denotes the total number of instruction accesses to address $\gen^j$. Since $\novel_0(0)=1$ and $\novel_i(0)=0$ for $i>0$, the raw lane value at encoder query zero reveals this count exactly. Preserving public memory values does not make that count public.

\begin{proposition}[A count leak left by value-only padding]\label{prop:zk-probe-count-floor}
There are two complete small-frame executions with the same public program, memory values on the entire probe prefix, public inputs and heights, but distinct read counts at address one. Any common candidate-layout completion that adds the same deterministic number of accesses at that address to both executions leaves an honest-query simulator-error floor
\[
 \frac{1-(1-1/D)^q}{2},\qquad D=2^{22+\rexp}.
\]
At rates $\rexp=1,2,3,4$ the current initial query counts are $228,113,76,57$, respectively. The floors exceed $2^{-17},2^{-19},2^{-20},2^{-22}$. Arbitrary unused-value randomness, row permutations and complete read-label permutations cannot remove this projection.
\end{proposition}
\begin{proof}
Use the ordinary range check of a private exponent against $65536$. Compare exponents zero and $1279$: their probe pairs are $\{0,65535\}$ and $\{1279,64256\}$. All local control and copied values occupy a frame beyond the public prefix and unused mask bank. Keep the entire prefix public, and perform the same remaining instructions in both runs. Only the first run probes address $\gen^0=1$, giving respective final counts $\gen$ and $1$. Counts remain distinct after adding an identical fixed number of accesses, since the admitted counts do not wrap the order of $\gen$.

On the observable event that any of the $q$ independent honest queries equals zero, the authenticated initial count lane distinguishes the executions perfectly. The event has probability $1-(1-1/D)^q$. Statistical distance between the real views is at least that probability; the triangle inequality gives half of it for at least one distance to a common simulator. Changes to other coefficients, other lanes or later messages cannot erase this projection. The statement is conditional on a common valid candidate completion; the native witness pair below checks legality at its smaller layout. It does not prove a probability statement for Fiat-Shamir queries or forbid witness-dependent count completion.
\end{proof}

\paragraph{A fixed-cost completion, not random overwriting.} Choose a power-of-two prefix length $\zkProbeCountSize\le\zkProbePrefix$ and public integer quotas $\zkProbeCountQuota(j)$, $0\le j<\zkProbeCountSize$. Require every prior real and padding execution in scope to satisfy $\zkProbeAccess(j)\le\zkProbeCountQuota(j)$. Subsequent padding must avoid this prefix or already be included in those counts. All its memory values are the existing prescribed public vector. The targets can depend on the public program and resource class, but not on its private execution.

\begin{lemma}[Fixed-cost prefix-count completion]\label{lem:zk-probe-count-completion}
Reserve one disjoint eight-cell frame per protected address and four public instruction locations, with quotas and total rows inside the native capacity and count non-wrapping bounds. Valid cycles can set every protected final counter to $\gen^{\zkProbeCountQuota(j)}$ while preserving all previously accessed values and all unused value masks. The helper frames are initialized to public values. The added opcode counts are exactly $\sum_j\zkProbeCountQuota(j)$ DEREF rows and the same number of JUMP rows, independent of the private access vector. All initial count-lane answers in $\subsp_{\log_2\zkProbeCountSize}$ then have a publicly computable value. This is a legality and projection theorem, not privacy of the new table or GKR messages.
\end{lemma}
\begin{proof}
In the frame for index $j$, put the public address $\gen^j$ at offset zero, a pointer to offset two at offset one, the public value $\mem[\gen^j]$ at offset two, and one at offset three. Offsets four and five hold the two public cycle-entry PCs, and offset six holds the frame's own address. These values are fixed before selecting the witness. The first cycle is a DEREF with offsets $(0,0,2)$ followed by JUMP with offsets $(3,4,6)$ back to that DEREF. The second uses DEREF offsets $(1,0,2)$ and JUMP offsets $(3,5,6)$. In the second cycle the indirect operand and value operand name the same private cell; the two accesses receive consecutive labels, as required by the native bus. Both cycles only copy equal values and close their state transitions.

Repeat the first cycle $\zkProbeCountQuota(j)-\zkProbeAccess(j)$ times and the second $\zkProbeAccess(j)$ times. Exactly the former touches the protected prefix, once per repetition. Their total repetitions are the public quota. All other accesses lie in the helper frame; no reserved mask is touched. Assign complete consecutive read labels at every affected memory and code address, continuing the prior chains. Each state cycle balances, and each read chain matches its seed and finalization tuples, so the union remains valid. Neither memory values nor public inputs change. Finally, all novel-basis polynomials of index at least $\zkProbeCountSize$ vanish on the indicated subspace. The remaining coefficients are precisely the public final counts.
\end{proof}

\paragraph{Capacity and transferred information.} For deterministic public targets, any additive completion whose local frames stay outside the prefix needs at least $\sum_j(\zkProbeCountQuota(j)-\zkProbeAccess(j))$ extra DEREF rows: each such instruction can reach only one protected address, and no other opcode with an external frame reaches one. The fixed-cost lemma uses dummy accesses to make the total row budget public. At uniform quota $8$, completing all $65536$ addresses consumes the entire candidate DEREF table before any real DEREF rows; such a blanket bound cannot fit at height $19$. Even smaller quotas need a certified budget for the real execution and all other libraries. This does not rule out a more selective normalization or a statistical count source; it rules out treating the repair's cost as automatically negligible. The helper frames can be packed into eight-cell blocks, but must be reserved separately from the real allocator and existing padding libraries.

The completion hides only the specified final-count projection. The split between the two cycle types remains in their bytecode counts, helper-cell counts and instruction-table metadata. In particular their aggregate repetitions are $\sum_j\zkProbeCountQuota(j)-\sum_j\zkProbeAccess(j)$ and $\sum_j\zkProbeAccess(j)$. Public final counts do not make these private quantities public or cancel their GKR disclosures. The unused-value and memory/root lemmas still apply when their reservations and independence hypotheses hold, but the enlarged count/table/PCS interface and common capacity need a new joint argument. No private address or access vector is added to the public statement.

\paragraph{A direct residual count-root test.} This is not only a hypothetical composition problem. Give three addresses quota two and realize their prior reads by the real-read cycle in three separate frames and a separate code pair. Compare access vectors $(2,0,0)$ and $(1,1,0)$. After completion they have identical protected counters and opcode totals, but their full cycle-union count roots are $\gen^{44}$ and $\gen^{34}$. To check the exponents, a cell with $a$ accesses contributes $\binom a2$ to the count root. A helper frame at target $T$ and prior count $a$ has access multiplicities $(T-a,a,T+a,T,T-a,a,T)$, while its prior-read frame has five cells accessed $a$ times. Summing their triangular contributions, the three protected-cell contributions and the four helper/two prior bytecode contributions gives the stated totals. The native bus audit checks both valid unions. Thus the top-up cycles must enter count normalization before any claim of joint privacy; simply adding them to an otherwise unchanged count-root completion is not a solution. These cycle unions are a residual diagnostic, not complete candidate-layout VM executions.

The same mode of \path{crates/lean_vm/examples/zk_memory_probe_prefix_audit.rs}, enabled by \texttt{zk-research}, verifies four complete native proofs at common public input, bytecode and heights: two leaking witnesses and their fixed-cost $128$-cell prefix completions. \subsubsection{What the repair does not yet prove}

The same masks enter the memory bus fingerprint products, GKR and memory opening claims. The continuation \noteref{zk-memory-root} proves one joint step: the shared bus root and this three-limb opening envelope, below $2^{-151}$, using independent directions in the opening's kernel. Proposition~\ref{prop:zk-memory-pcs-isolation} extends the root-decoupling hybrid to the actual algebraic PCS while retaining the other reductions' actual marginal. It does not simulate that marginal or the intermediate fingerprint GKR messages. We must still simulate those disclosures jointly and fit every cycle library into the nonreserved slots. Unused values do not randomize final read counts; count normalization and hiding remain separate obligations. Finally, Merkle roots and paths and the separate Fiat-Shamir experiment require their own simulation arguments.

\paragraph{Executable evidence.} \auditref{zk_memory_frames_audit.py} checks the low-point encoder identity, the finite alignment cases and actual placement samples, the exact privacy lower bound, and pin-preserving mask translations over the native fields. In four query modes, including zero and small subspaces, those translations cancel every observation of a small multilevel algebraic wire schedule, including introduction polynomials and final plaintext values. A sixty-four-lane instance also places larger columns before memory and uses arbitrary weights outside memory; both the envelope translation and root kernels annihilate every algebraic observation. It also checks the whole-frame capacity. These are finite certificates supporting the proofs, not sampled estimates of their error bounds or a full VM simulator. Run the separate native obstruction example with \texttt{cargo run --release -p lean\_vm --example zk\_memory\_prefix\_audit}.
