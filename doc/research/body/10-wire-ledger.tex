\section{Concrete wire and resource ledger}\label{sec:zk-wire-ledger}

This ledger records the present verifier, not a simplified protocol with independent replacements for its claims. It separates transmitted values from derived claims and identifies where masks are reused. The experiment is the single-proof honest interactive model of Definition~\ref{def:zk-target}: announced heights and PCS configuration are public, challenges are independent honest coins, and private padding is freshly sampled before commitment. Authentication is included in the target but not in the proved algebraic lemmas. Fiat-Shamir is a separate deployment obligation.

\subsection{The reduction wire}

The following order follows \path{crates/lean_vm/src/cpu/mod.rs} and \path{python-verifier/verifier.py}. An entry counts extension-field scalars unless it explicitly says otherwise. Public announcements precede the initial commitment; every later row also has the preceding wire in its conditioning context.

The $112$ column claims comprise five framework claims, $104$ table claims and three public-input claims. The logical BLAKE2s value columns are remapped into the packed Flock vector; they are not extra independent committed columns. Public bytecode evaluation and the fixed Flock matrix evaluations are locally computable in the native verifier. The relevant source functions include \texttt{finish\_claims} and \texttt{verify\_balance}; the reference reduction continues through \nolinkurl{table_sumcheck}, \nolinkurl{verify_flock_zerocheck}, \nolinkurl{verify_flock_lincheck} and \nolinkurl{ring_switch}. Challenges and running claims are part of the view even when their values are derived rather than transmitted.

\paragraph{The recursive interface.} The guest in \path{crates/rec_aggregation/guests/aggregate.py} follows the same reduction in \texttt{verify\_gkr}, \texttt{verify\_tables}, \texttt{verify\_flock} and \texttt{open\_stacked}. Its advice additionally supplies layout and authentication witnesses, plus evaluations deferred to the outer verifier. In particular, the bytecode value is an explicit guest hint, whereas the native verifier evaluates that public polynomial locally. The three deferred fixed-polynomial claims must be included wherever the external aggregation object exposes them. This does not make every private guest hint a public disclosure; the protected statement and its external verifier determine the view. Advice validation belongs to soundness and does not by itself prove privacy.

\subsection{The PCS wire}

The opening is not just its final MLE claim. \texttt{verify\_whir} receives an initial quadratic message, further quadratic fold messages, introduction polynomials for both out-of-domain claims and query constraints, later commitment roots, out-of-domain evaluations, raw queried leaf images, authentication paths, grinding nonces and the final residual plaintext table. Their exact multiplicities follow the public PCS configuration. At a nonfinal level the new root precedes its out-of-domain evaluation; the final level sends the residual instead. The level's grinding and query challenges then select the authenticated old-oracle leaves, and a fresh batching coin introduces their constraints. Subsequent fold messages retain this same committed polynomial.

An initial raw leaf is the full $64$-lane base-field image, before challenge folding. Rust omits the known leading zero lanes from its serialized image; reconstruction recovers exactly the full image consumed by the reference and recursive verifiers. Later raw leaves carry three base-field limbs per folded extension value. Authentication paths are a separate byte stream, not additional independent uniform scalars. Neither compressed serialization nor later folding removes the initial raw-lane observation used in Proposition~\ref{prop:zk-memory-floor}.

\paragraph{A proved conditional interface.} Proposition~\ref{prop:zk-memory-pcs-isolation} covers the actual memory contribution to this mixed algebraic opening when $\mu=\kmem+3$. Corollary~\ref{cor:zk-memory-root-wire} retains the entire non-GKR algebraic marginal while replacing the shared root. This is stronger than an isolated opening theorem but weaker than simulating that marginal: table/count/Flock data and all authentication still need their own joint proof.

\subsection{A size-compatible candidate, not a completed sampler}

In table order XOR, MUL, SET, DEREF, JUMP, BLAKE2s, the logical committed widths are $(15,15,8,15,14,37)$. Eighteen BLAKE2s value columns are virtual inside a packed vector with $256$ base-field coefficients per compression. Thus the exact number of placed coefficients is
\[
 \begin{aligned}
 \zkPlacedSize={}&4\nmem+\nprog
 +15\cdot2^{\tau_0}+15\cdot2^{\tau_1}
 +8\cdot2^{\tau_2}\\
 &+15\cdot2^{\tau_3}+14\cdot2^{\tau_4}+275\cdot2^{\tau_5},\\
 \mu={}&\max\{15,\lceil\log_2\zkPlacedSize\rceil\}.
 \end{aligned}
\]
All terms are positive. The current PCS accepts $\mu\le28$. Already the packed Flock vector alone rules out the former $\kbatch=21$ construction: its log size is $29$.

\begin{proposition}[Capacity ceiling for the eight-segment memory branch]\label{prop:zk-flock-capacity}
If $\mu=\kmem+3\le28$, the BLAKE2s batch log satisfies $\kbatch\le\kmem-7\le18$.
\end{proposition}
\begin{proof}
The four memory columns occupy $4\nmem$ coefficients. Since other positive columns remain, the packed Flock column has size strictly less than $4\nmem$. Its power-of-two size is therefore at most $2\nmem$, so $\kbatch+8\le\kmem+1$. The stack cap gives $\kmem\le25$.
\end{proof}

The compact support in Theorem~\ref{thm:zk-compact-two-point} meets this necessary ceiling. One reference-accepted candidate is
\[
 \kmem=25,\qquad \kbc=11,\qquad
 (\tau_0,\ldots,\tau_5)=(19,19,19,19,20,18).
\]
It places $\zkPlacedSize=248776704$ coefficients in a stack of log $28$, with $60$ occupied initial lanes of length $\zkLaneLen=2^{22}$. The packed Flock vector precedes memory and occupies sixteen lanes; the memory-value groups begin at lanes $16,24,32$. All four supported PCS rates admit this layout. With the original two-point support, the first $96$ Flock banks used $61440$ independent binary choices and left $65536$ real-compression slots; the current three-point refinement below uses the same heights.

For the memory reservation with $\zkPadBlock=256$, the remaining payload capacity is $3(2^{22}-1280)=12579072$ words. At fixed frame size $256$ this is $49137$ slots; smaller publicly supported frames can increase the slot count. This does not establish that every Flock padding frame, bus/count cycle, return and real allocation fits, or that the existing GKR lemmas apply at the resulting bus height. Those checks constitute the remaining common-sampler theorem. The accepted resource profile is a useful constraint on that theorem, not a replacement for it. \auditref{zk_two_point_audit.py} checks the reference layout and the compact support's exact bound and native-field span certificates.

\paragraph{A capacity check is not a privacy check.} \noteref{zk-flock-coset} proves initial-opening obstructions for two compact layouts. Applying $\zkFlockOrder$ to BLAKE2s rows and their packed blocks puts all $96$ profiles in each initial Flock lane, with $3840$ original random choices and $4096$ real slots. A fixed-query binary-rank defect motivates independently randomizing the other padding-bank positions too. This keeps the coefficient budget and endpoint theorem unchanged, but can increase private frame requirements; those requirements belong in the common sampler proof. For the negative theorem's longer public program, bytecode log $17$ still gives stack log $28$, with $248905728$ placed coefficients; the audit checks this variant too.

\paragraph{General-input and metadata refinements.} \noteref{zk-flock-interface} rules out keeping every padding IV pinned and uses $98304$ binary-choice rows on $\zkTripleSupport$ plus $98304$ general-compression positions, leaving $65536$ real slots. \noteref{zk-flock-columns} pairs $16256$ of those complementary positions for compression-preserving metadata swaps; the other $82048$ positions, including the five-row metadata bank, may use independent general inputs. All thirty-seven BLAKE2s claims now join the Flock endpoint theorem. The library uses $36$ reserved code locations and replaces existing compression/return cycles. Sharing frames in the counter bank reduces Flock's allocation to at most $6160384$ cells, leaving $25073$ slots of size $256$ for real execution and other banks. No new committed coefficient or verifier equation is needed. The other banks and remaining packed opening are not proved.

\paragraph{Current cross-parent candidate.} The local core in \noteref{zk-flock-children} has four PC banks, four count banks, seven operand banks and one frame bank. Its PC/count swaps change physical bit two within a fixed child slot. Four additional count banks change physical bit three. Together they supply eight kernels and four quotients in one sixteen-point encoder coset, sufficient for any twelve raw values by \noteref{zk-flock-sixteen}. No global shuffle is used. The source occupies $36856$ complementary rows and $62$ code locations, leaving $61448$ general-input positions. Frame sharing leaves at most $181252$ Flock padding frames, or $5800064$ cells, with $26480$ payload slots of size $256$ remaining. Each count bank has a complete $2560$-read bytecode chain with geometric weights. The twelve-value theorem retains all twelve final GKR children and the earlier terminal/memory/root interface. Multi-coset query privacy, preceding GKR messages, authentication and common allocation remain open. Public heights and verifier equations are unchanged.

\paragraph{Full-query rejection of this source.} The fixed-completion six-query certificate in \noteref{zk-flock-query-fiber} rules out $128$-bit privacy for this source at every supported rate. Its $110588$ legal metadata bits include exactly $56700$ nonzero lane-$59$ directions, all accounted for in the obstruction. A replacement must change the low-coordinate count image or the completion; the preceding capacity and selected-coset facts do not resolve that obstruction.

\paragraph{Current balanced long-chain repair.} \noteref{zk-flock-lowbank} adds $3840$ compression cycles in otherwise free low blocks, with one shared frame and two code locations. This makes $40696$ reserved complementary compression rows and $64$ code locations, leaving $57608$ general-input positions. Flock requires at most $177413$ padding frames, or $5677216$ cells. The remaining cell count gives a ceiling of $26960$ slots of size $256$, not a packing theorem; the explicit allocation below leaves $26959$. There are $129788$ independent metadata bits and $66300$ nonzero lane-$59$ directions. Pairing all $56$ lower-half blocks across the half boundary enables a full thirty-two-point high-region theorem. Independent count columns and disjoint old-terminal/new-query masks add a simultaneous sixteen-point low coset, jointly below $2^{-151}$. At this exponent the complete $4096$-point prefix is also retained through its $1084$ independent mask bits, including $188$ exposed PC bits. Arbitrary query families and common allocation remain open; freely disclosing the larger $8192$-point prefix would leak.

\paragraph{In-frame adapter extension.} \noteref{zk-count-adapter} modifies $3072$ mandatory binary-compression cycles, adding one MUL row to each and reserving three more code locations. Compression and return counts, allocated frame count and the $57608$ general-input positions are unchanged. The $1536$ new bits raise the metadata budget to $131324$ and the nonzero lane-$59$ source directions to $67836$. The full $4096$-point prefix exposes $1116$ independent bits. The new MUL positions are distinct and below $196608$, within the public height $19$; compatibility with other MUL reservations remains unproved. These adapters hide one earlier count child with the preceding restricted interface below $2^{-151}$, but not its preceding coefficients, other intermediate children, or their own MUL terminal/opening disclosures. Their fixed public count offsets must be included in normalization.

\paragraph{Reused bytecode calibration.} Proposition~\ref{prop:zk-bc-pool-normalization} reassigns $95112$ unadapted mandatory compression cycles among ten code pairs at $1120,\ldots,1139$. This reserves twenty more instruction positions but adds no rows, frames or random bits. All $98304$ profile-choice bits remain independent, and $120$ unadapted mandatory positions need no reassignment. The full $65536$-row private BLAKE2s budget and all $57608$ general-input positions are retained. Theorem~\ref{thm:zk-bc-coarse-normalization} also makes this column's sixteen coarse products public by sorting real rows and routing labels through the same pool. The existing restricted projection remains covered; other count columns, the full opening and the global reservation still need proof.

\subsubsection{One disjoint Flock-side reservation}\label{sec:zk-flock-reservation}

The following allocation joins the existing Flock-side libraries, adapters and bytecode calibration. It does not yet allocate the real execution or the remaining count/table libraries. In payload segment $l<3$, number the $32$-cell frames by $s$, with address exponent $l2^{22}+1280+32s$. Keep all their cells allocated, including presently unused words. Use these public frame sets:

\begin{center}
\small
\begin{tabular}{@{}cll@{}}
\toprule
Segment & Frame indices & Contents \\
\midrule
$0$ & $0,\ldots,21499$ and $65535$ & Wider metadata library and shared low bank \\
$1$ & $0,\ldots,57607$ & General-input compressions, including the five protected rows \\
$2$ & $0,\ldots,98303$ & Mandatory binary-compression source \\
\bottomrule
\end{tabular}
\end{center}

The old wider-library allocator uses exactly its displayed prefix: every explicit reserved index lies inside it, and fresh allocations fill its remaining indices. Its low-bank frame is separate. Order the general-input rows by physical position. In segment two, allocate the $3072$ adapted rows first, in adapter-pair order; then the $95112$ calibration rows in their public physical order; then the remaining $120$ mandatory rows. These sets are disjoint, lie wholly after each reserved memory prefix, and do not touch the five fully random memory segments. The independent compression choices and old metadata source maps are unchanged.

Keep the old $64$ metadata/low-bank code positions, the three adapter positions and the twenty calibration positions. Use the additional compression/return pair $1140,1141$ for the general-input rows and the $120$ remaining mandatory rows. Its visit count is public; assign its complete bytecode labels in public row order. All $89$ code positions are distinct except this intentional sharing, and their maximum is $1141<2^{11}$. Their operand templates are compatible with the allocated frames. Thus merging these cycle libraries introduces no memory or code conflict, while their internal shared-address chains remain as specified.

Place each padding cycle's return at the JUMP-table position equal to its original physical BLAKE2s position, before the independent whole-row swaps. These are $196608$ distinct positions below $2^{18}$, leaving $851968$ positions at JUMP height twenty. For calibration code pairs, give each return the same bytecode label as its compression; their two separate instruction chains have identical visit counts. This realizes the per-interval JUMP transfer in Theorem~\ref{thm:zk-bc-coarse-normalization}. Keep the $3072$ prescribed MUL adapter positions from \noteref{zk-count-adapter}; the other opcodes receive no rows from this library. The BLAKE2s complement is exactly the $65536$ real-bank positions, $4096$ per coarse interval. These placements do not affect the old masking maps, whose changed rows remain in their specified positions.

The three frame sets occupy respectively $2689$, $7201$ and $12288$ aligned $256$-cell slots. Of the $49137$ available payload slots, exactly
\[
 49137-(2689+7201+12288)=26959
\]
remain wholly free. The earlier $26960$ cell-count ceiling misses one slot because the partial final metadata slot and isolated low-bank frame cannot share a whole $256$-cell allocation. This correction changes no statistical-error bound.

\auditref{zk_count_reuse_audit.py} enumerates the row/frame/code sets and the remaining aligned slots. Its \texttt{--full} mode additionally rechecks the complete wider metadata library and its exact frame prefix against the reference ISA and bus. This closes the Flock-side row/frame/code-disjointness subproblem. It does not place the other JUMP/MUL libraries, finish all-opcode normalization, implement the reservation-aware real-program allocator or supply the common full-VM sampler.
