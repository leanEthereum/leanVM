\paragraph{Status.} Full statistical ZK for leanVM is not proved. We have explicit valid-padding constructions and statistical simulators for selected algebraic views, supported by exact finite-field audits. These results do not yet compose into one simulator for a complete proof. Production protocol code is unchanged. This file is the entry point; detailed proofs live in the indexed companion notes.

\section{The goal and the proposed mechanism}\label{sec:zk-goal}

The objective is an optional statistically zero-knowledge prover for leanVM, obtained by changing the witness through valid execution padding, not by adding random masking weights to the verifier. Ordinary non-ZK proofs should retain their existing protocol and cost. ZK proofs may pay for additional rows, memory and prover randomness. \emph{For free} refers to avoiding mandatory privacy machinery on the ordinary path, not to a proved zero-overhead construction.

The starting observation is that table rows are unordered and closed execution cycles can be inserted without changing the public computation. We seek public reservations of valid cycles, unused memory and legal counter-label permutations whose private random choices hide every witness-dependent disclosure. Randomness must be distributed across the actual folding and opening geometry. Merely permuting rows, appending a random suffix, or making a trace look pseudorandom is insufficient.

The padded witness must preserve the intended relation, public inputs and outputs, every local constraint, bus balance and complete read chains. Reserved instructions and resource bounds are public; choosing a program or announced size as a function of a secret would disclose that choice. Some notes assume a disjoint valid completion without constructing it. That assumption remains a proof obligation, not an implementation detail.

\section{What statistical zero knowledge means}\label{sec:zk-definition}

\paragraph{Statement and witness.} Write $\zkRel(\zkStmt,\zkWit)=1$ for the intended VM execution relation. The public statement $\zkStmt$ includes the program identity, public inputs and outputs, parameters and declared resource bounds. The private witness $\zkWit$ contains the execution data being proved. Any permitted public preprocessing must be included in the model and bound to the statement. Privacy is required for every admissible witness for the same statement, not for an average witness distribution.

\begin{definition}[Statistical distance]
For discrete random variables $X,Y$ on the same space,
\[
 \zkSD(X,Y)
 =\frac12\sum_a\left|\Pr[X=a]-\Pr[Y=a]\right|
 =\sup_A\left|\Pr[X\in A]-\Pr[Y\in A]\right|.
\]
Thus distance at most $\epsilon$ bounds the distinguishing advantage of every test, including computationally unbounded tests~\cite{distance}.
\end{definition}

\begin{definition}[Interactive statistical ZK target]\label{def:zk-target}
Let $\zkSec$ index a family of protocol parameters and let $\zkProver_{\mathrm{pad}}$ be the honest padded prover. For every probabilistic polynomial-time verifier $\zkVerifier^*$, there must exist an expected polynomial-time simulator $\zkSim_{\zkVerifier^*}$ and a negligible error $\zkErr$ such that, for every admissible $\zkStmt,\zkWit$ with $\zkRel(\zkStmt,\zkWit)=1$ and every polynomially bounded auxiliary input $\zkAux$,
\[
 \zkSD\!\left(
 \zkView_{\zkVerifier^*}^{\zkProver_{\mathrm{pad}}}
      (1^{\zkSec},\zkStmt,\zkWit;\zkAux),
 \zkSim_{\zkVerifier^*}(1^{\zkSec},\zkStmt;\zkAux)
 \right)
 \le \zkErr(\zkSec).
\]
Statement and witness lengths are bounded polynomially in $\zkSec$. The view includes the verifier's input, auxiliary input, private coins and all received messages. The simulator receives no witness, secret execution, or unsimulated witness-dependent residual. This is the auxiliary-input simulation formulation, with statistical rather than computational closeness~\cite{zk-definition}.
\end{definition}

A negligible error eventually falls below every inverse polynomial in $\zkSec$. The current concrete notes instead bound error at leanVM's fixed fields $\K=\F_{2^{64}}$ and $\E=\F_{2^{192}}$, aiming for a total privacy error at most $2^{-128}$ over the stated resource range. A bound at one parameter choice is not by itself an asymptotic theorem. Statistical privacy also does not imply statistical soundness: a statistically ZK argument may still rely on computational assumptions for binding and knowledge soundness.

\paragraph{What the current lemmas actually establish.} Unless stated otherwise, they sample independent uniform coins of an honest interactive verifier and simulate only a specified projection of the algebraic transcript. Coins may be sampled in advance; an online simulator against adaptively chosen challenges is not claimed. A theorem for such a projection is weaker even than honest-verifier ZK for the complete interactive protocol, and much weaker than Definition~\ref{def:zk-target}. Error bounds are meaningful only with the note's layout, completion, query and setup assumptions.

\paragraph{The deployed noninteractive target.} leanVM uses Merkle commitments and Fiat-Shamir. Its ultimate claim must therefore specify a noninteractive simulation experiment, including public setup, any random-oracle access, simulator programming permissions and query bounds. The observable experiment must cover the actual proof and any exposed deferred claims, together with the relevant oracle interaction. Definition~\ref{def:zk-target} states the interactive benchmark; it is not a definition or proof of Fiat-Shamir ZK. Replacing hash-derived challenges by independent coins without justification, or appealing to collision resistance alone, does not close this gap.

\section{How a complete proof would have to work}\label{sec:zk-composition}

\paragraph{One joint view.} The target contains the commitments, announced sizes, bus and count products, every GKR message, table sumcheck, Flock zerocheck and lincheck, ring switching, the complete stacked PCS opening, its final plaintext table, authentication paths and externally visible deferred claims. The protocol order is specified in \path{doc/leanvm/main.tex}. No later disclosure of a padding value may be silently omitted from its privacy analysis.

Individual hiding claims do not compose automatically. If a fair bit $U$ masks a secret bit $b$, both $U$ and $U\oplus b$ are individually uniform, but their pair reveals $b$. Likewise, two sumchecks can each look random while revealing the witness through their shared masks. What is needed is a joint simulator, or conditional hybrids that retain every already exposed coordinate and justify the remaining randomness. Only then may their statistical errors be added.

\paragraph{The useful proof pattern.} Identify the native affine relations between the observations, then prove that legal padding choices make the remaining coordinates uniform on the appropriate affine set, except on explicitly bounded exceptional coins. Factor that distribution conditionally to expose unused randomness, and analyze the nonlinear messages it hides. A witness-dependent invariant need not itself become uniform if the resulting observable distribution is independent of it. But it cannot be passed to the final simulator as an unexplained input.

\paragraph{Evidence standards.} An exact nonzero determinant can certify a nonzero polynomial; a degree bound and the actual challenge distribution can then bound its failure probability. A successful numerical rank at one point, especially a large binary rank, is not such a bound. An audit replaying selected messages through the reference verifier checks their algebra, not the omitted messages or a full VM execution. Our randomness arguments use genuine random choices; a pseudorandomness assumption alone does not establish statistical privacy.

\section{Current results and their boundaries}\label{sec:zk-status}

The following are the main entry points, not pieces of an already composable construction. Their bounds refer to different views and, sometimes, different padding layouts or setup models.

\paragraph{Final GKR layer: a joint four-round tail.} \researchnote{zk-four-round-tail} hides the last four sumcheck rounds of the final GKR layer, their incoming claim, final children and five framework evaluations, below $2^{-152}$. It uses forty-eight sparse row-swap banks, respects native push/pull/count relations and retains a private self-loop invariant. The supported layer has twenty rounds: its first sixteen rounds are excluded, as is composition with earlier layers. The theorem assumes compatible count normalization and a disjoint valid completion. It does not include the subsequent table proof or PCS.

\paragraph{Coarse GKR layers: a separate setup branch.} \researchnote{zk-mul-control} jointly simulates the first two GKR layers and the seventeen-field terminal boundary below $2^{-155}$, outside an honest public-setup exception below $2^{-222}$. It requires public random word/frame-scale libraries and native field-valued frame/offset support that is not implemented. These are additional, unadopted assumptions. The intervening layers are omitted; this theorem cannot simply be joined to the four-round tail theorem.

\paragraph{Counts: normalization and a partial internal simulator.} \researchnote{zk-count-columns} makes all twenty-eight count-column products public using valid cycles and label routing, subject to capacity and compatibility conditions. This does not hide the internal count tree. \researchnote{zk-count-uniform-tail} proves an eight-round count-only tail theorem below $2^{-157}$. \researchnote{zk-count-completed-head} supplies exact conditional head-rank certificates for that construction, but not a uniform head failure bound or a joint simulator with the fingerprint channels.

\paragraph{Table constraints: a conditional composition route.} \researchnote{zk-jump-rank} hides the isolated JUMP constraint sumcheck; \researchnote{zk-jump-metadata} adds its terminal columns. \researchnote{zk-table-batch} reduces simulation of the actual six-table sumcheck to a larger preceding view that still needs simulation. \researchnote{zk-jump-bus-padding} hides the bus-batched JUMP component and its boundary below $2^{-146}$, but does not establish its joint privacy with preceding GKR messages.

\paragraph{Flock: prefix and endpoints, not the middle.} \researchnote{zk-flock-endpoints} jointly hides the within-block prefix, terminal evaluations, complete lincheck and sixty-four ring-switching input slices below $2^{-148}$. It reserves $73728$ random-choice compressions in a public batch of $2^{21}$. The intervening batch-coordinate zerocheck rounds, preceding VM messages and ring-switching proof are excluded. \researchnote{zk-flock-middle} provides conditional rank evidence, not the missing complete statistical theorem.

\paragraph{PCS: restricted algebraic openings.} \researchnote{zk-pcs-padding} hides a complete algebraic WHIR opening for one independent random-point claim, assuming freely random padding coefficients. \researchnote{zk-stacked-padding} extends this to one common Frobenius orbit. Neither covers the full actual stacked claim family jointly with the VM reductions, nor realizes every required coefficient with valid cycles. Commitments and Fiat-Shamir are excluded.

\section{What remains before claiming full ZK}\label{sec:zk-remaining}

\begin{enumerate}
\item \emph{One realizable padded prover.} Fix a public resource policy and compatible reservations for every component; construct the complete valid trace for every supported execution. Establish that padding preserves the intended statement and does not introduce a soundness loophole.
\item \emph{Complete joint algebraic simulation.} Cover all bus/count GKR layers and their table interface, then the complete table, Flock and ring-switching transcripts. Replace residual numerical rank evidence with uniform statistical bounds where required.
\item \emph{All opening disclosures.} Handle the actual stacked weights, multiple evaluation points, pre-fold query lanes, introduction polynomials and final plaintext table, jointly with the preceding transcript.
\item \emph{The noninteractive security model.} Prove the appropriate commitment and Fiat-Shamir simulation theorem, including externally exposed recursive/deferred claims and the intended repeated-proof use. State setup and oracle assumptions explicitly.
\item \emph{End-to-end validation.} Account for total privacy error and padding cost, implement the optional prover, and test against the Rust, Python and recursive verifiers. A change to their shared protocol would require a separate design decision; it is not part of the padding-only claim.
\end{enumerate}

The immediate algebraic target is a complete joint bus/count GKR simulator retaining what the table proof needs. The four-round note proposes a coupled push/pull/count analysis to extend the tail within the current capacity. That is a candidate, not a general induction. The full PCS and noninteractive obligations remain independent sources of risk; another tail round alone does not resolve them.
