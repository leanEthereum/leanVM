\section{Recursion}\label{annex:rec}

A leanVM proof is verified by a RISC-V program, and that program's run is proven like any other: recursion needs no machine of its own and no circuit. This annex describes the verifier as a program (\S\ref{rec:verifier}), and the trees of such programs that aggregate many proofs into one (\S\ref{rec:tree} to \S\ref{rec:root}). The three custom instructions are what make it cheap: the verifier's arithmetic in $\E$ is one \texttt{EXT} row a product (\S\ref{sec:vm}), its elements move between memory and the extension registers by \texttt{eld} and \texttt{esd}, and its hashing, the transcript and the Merkle paths, is one \texttt{blake2s} a compression, on words that are hashed where they lie. Proving a verifier's execution is the recursive composition of~\cite{BCCT13}.

\subsection{The verifier as a program}\label{rec:verifier}

The verifier's core (\S\ref{sec:e2e}) never branches on a value of the proof: which checks it makes, in which order, on how many scalars, depends on the proof's \emph{shape} alone, the program verified, each table's height and the rate. So the verifier program for a shape is a straight line of instructions with no loop, no branch and no call, generated by running the verifier's code once over a recording arithmetic and writing down each step it takes. The same code is the native verifier, so the two cannot differ in what they check, and the program's text depends on the shape and on nothing else: building it needs no proof.

\paragraph{The proof is the advice.} The program reads the proof from its advice (\S\ref{sec:vm}), which is the prover's, laid out so that each word is used where it is. A scalar of $\E$ is three words on a $32$-byte boundary, which \texttt{eld} loads. The scalars one transcript step absorbs (\S\ref{sec:e2e-fiat-shamir}) are one $64$-byte block, the step's message, and the program writes into it the words the prover does not choose: the count, the tag, and the zeros of an absent scalar. An opened row of words is its leaf's hashed blocks. A Merkle path is one block a level: room for the node below, then the sibling. Nothing the advice holds is trusted: a word is bound by a hash that reaches a root or the transcript's state, or by an equality the program checks.

\paragraph{Arithmetic.} A product or a sum of products in $\E$ is one \texttt{EXT} instruction on extension registers. The generator allocates the $125$ writable ones by the furthest next use, spilling an element to memory by \texttt{esd} and loading it back by \texttt{eld}. An equality $a=b$ is the zero-result form, which traps unless $a+b=0$. A check on words, such as a query position's bits, is integer instructions and a branch over an illegal word.

\paragraph{Hashing.} A transcript step is one \texttt{blake2s}: its chaining value the state, its message the block of the advice, its result the new state. A step that squeezes writes its state where the challenge is read as an element, and the next step takes its chaining value from there, so the state is never copied. A leaf is a chain of compressions on the advice's blocks from the zero prefix's state (Annex~\ref{annex:pcs}), a constant of the program, its last result written into the path's first block. Each level of a path is one node instruction (\S\ref{sec:vm}): the position's low bit orders the node and its sibling, and the result is written into the next level's block; the last one is the node its stratum fixes, compared with the tree's top levels, which are hashed once. A row of elements, three words to a $32$-byte slot so that each is an element where it is, is copied into a message block of the program's own first.

\paragraph{A failed check is a trap.} The program has one exit, reached only if every check passed; any other run traps, and a trap is the absence of a proof (\S\ref{sec:vm}). So a proof of a run of the verifier program is a proof that its verifier accepted. The image is empty: the program writes its constants itself, so two verifier programs differ by their text alone, and the claim on RAM's image a proof of one leaves is trivial.

\paragraph{What the run outputs.} The verifier's core leaves the \emph{deferred claims} (\S\ref{sec:e2e}): the program claim, on the verified program's bytecode table and image, and each Flock circuit's matrix claim. A verifier program does not evaluate them. It reduces them (\S\ref{rec:reduce}) to its \emph{statement}, a fixed list of words, and its run's output is the BLAKE2s hash of the statement's words. The statement itself rides with the proof, and whoever checks the proof hashes it and compares.

\subsection{Aggregation trees}\label{rec:tree}

An aggregation tree proves that many leanVM proofs of one program $P$ verify, with one proof a native verifier checks once. Its leaves are proofs of $P$ of one shape. Its other proofs are proofs of two verifier programs, at a rate of their own. A verifier program's cycles are mostly its leaves' or children's query openings, and a lower rate needs fewer queries for the same soundness, so leaves at a lower rate than the tree's proofs move work from the aggregator, who proves every tree proof, to the leaves' provers, who run in parallel.
\begin{itemize}[itemsep=1pt,topsep=3pt]
\item A \emph{first-level node} is a proof of $\rfirst$, which verifies $\arityz$ proofs of $P$ and reduces the claims they leave.
\item A \emph{node} is a proof of $\rnode$, which verifies $\arity\ge2$ tree proofs of either kind, its own included, and reduces the claims they leave and carry.
\end{itemize}
The root is a node, or the first-level node of a tree of $\arityz$ leaves. A tree of one first-level node over one leaf, $\arityz=1$, is the recursion of a single proof. A tree has $\arityz\,\arity^d$ leaves, $d$ the number of levels of nodes.

Every tree proof states the same words, whatever the tree's size:
\begin{itemize}[itemsep=1pt,topsep=3pt]
\item its kind $\kbit$: $0$ for a first-level node, $1$ for a node;
\item its digest $\tdig$ of the leaves' outputs under it;
\item one claim on each of three \emph{dense} polynomials at prefixes of one point $\fdense$: $P$'s stacked bytecode table $\bctab$ (\S\ref{sec:e2e-bc}), its RAM image $\imgpoly$ zero padded to a power of two, and the tree programs' own tables $\fixnode$ (\S\ref{rec:identity});
\item for each of the $25$ Flock circuits $f$, the values of its matrices $A_0$ and $B_0$ (\S\ref{flock:native}) at the prefixes of length $k_f$ of one row point $\frow$ and one column point $\fcol$, $2^{k_f}$ the circuit's instance width.
\end{itemize}
The kind is a constant of each program, the digest is computed by the program, and the claims are the outputs of the node's reduction (\S\ref{rec:reduce}). A first-level node reduces no claim on $\fixnode$: its value and the point's coordinates past the other polynomials' are zero, and a parent weighs them by the kind, which is zero.

\paragraph{Digests.} A first-level node's digest is the BLAKE2s hash, from the parameter IV, of a tag, $\arityz$ and then the leaves' outputs in order. A node's is that of another tag, $\arity$ and its children's digests in order. The tags separate the levels and the counts fix the items, so a digest names its whole subtree.

\subsection{Program identity}\label{rec:identity}

A verifier of a proof of program $Q$ needs two things of $Q$: its digest, which seeds the transcript, and its bytecode table, on which the core leaves the program claim. The node program verifies proofs of itself, and cannot hold either as a constant. Three choices settle this.

\paragraph{One shape.} Proofs of $\rfirst$ and of $\rnode$ have the same shape $\taufix$: each table's height, and the sizes of the bytecode, RAM and the advice. A verifier program runs each of its instructions exactly once, so its tables' heights are its instruction counts by class, known from its text. The shape is the least fixed point of $\tau\mapsto\max(\tau,\tau(\rfirst),\tau(\rnode(\tau)))$: $\rnode$'s text depends on the shape of the proofs it verifies, and grows with the logarithm of their heights, so the iteration settles in a few rounds, and the builder refuses a tree whose shape has not settled after eight. Each text is then padded to the shape's bytecode size with illegal words, which no run reaches. The node program verifies a child of either kind with one text, since everything it does depends on the shape alone.

\paragraph{One seed.} A tree proof's transcript is seeded not with its program's digest but with the tree's: a hash of a label, $P$'s digest, the leaves' shape, $\arityz$, $\arity$, $\taufix$ and the rate. The seed is the same for both kinds and a constant of both programs. The run's output, which the transcript absorbs with the seed, is the hash of the statement, whose first word is the kind, so the transcripts of the two kinds stay apart.

\paragraph{The table as a claim.} What binds a child's proof to its program is the program claim alone. With $T_0$ and $T_1$ the stacked bytecode tables of $\rfirst$ and $\rnode$, of $\kappa$ variables each, the tree programs' table is
\[
  \fixnode(x,\kbit)\;=\;(1+\kbit)\,T_0(x)+\kbit\,T_1(x),
\]
of $\kappa+1$ variables, the last one the kind. The child's kind $\kbit$ is a word of its statement, which the node program holds to a bit by $\kbit^2=\kbit$. The claim the child's core leaves on its bytecode table at a point $x$ becomes a claim on $\fixnode$ at $(x,\kbit)$, which joins the reduction. So a child is checked against the table of the program it claims to be, the node program refers to its own table only through such claims, hence is well defined, and the claims are settled against the two tables the root's verifier builds from the shapes. No commitment to a program is needed.

\subsection{The per-node reduction}\label{rec:reduce}

A first-level node's program leaves, for each leaf, the program claim and each Flock circuit's matrix claim (\S\ref{rec:verifier}). The program claim is $\sum_i\mu_i\,\varphi^i(\bctab(\varphi^{-i}(\chi),\vec\alpha))+w\,\imgpoly(p)=v$, $\varphi$ the Frobenius $x\mapsto x^2$ and $\mu_i$ the weight of multiplicity bit $i$. It becomes point claims: the prover supplies $D_i=\bctab(\varphi^{-i}(\chi),\vec\alpha)$ for each bit and $I=\imgpoly(p_{<m})$ as advice, and the program checks $\sum_i\mu_iD_i^{2^i}+w\prod_{j\ge m}(1+p_j)\,I=v$, $m$ the image's variables, RAM being zero above the image. It computes $\varphi^{-i}(\chi_j)=\chi_j^{2^{192-i}}$ by squarings. A node's program does the same for each child with $\fixnode$ at the child's kind in place of $\bctab$ and no image, a tree program's being empty, and reads the claims the child carries off its statement, the one on $\fixnode$ scaled by the child's kind.

The claims are then reduced by a small proof of its own, which the node's prover makes natively and the node's program verifies, reading it from the advice. Its transcript, started from a label, first binds every verified proof's final transcript state and every hint the claims rest on; each child's statement, carried claims included, is bound by its own transcript's seed. Then:
\begin{itemize}[itemsep=1pt,topsep=3pt]
\item \emph{The dense reduction.} With a challenge $\rbat$, the claims $s_t\,Q(p_t)=s_t\,v_t$ on $Q\in\{\bctab,\imgpoly,\fixnode\}$, $s_t$ a claim's scale, become $\sum_Q\sum_x\dwt{Q}(x)\,Q(x)=\sum_t\rbat^t s_tv_t$ with $\dwt{Q}=\sum_{t\text{ on }Q}\rbat^t s_t\,\eq(p_t,\cdot)$, proven by one sumcheck of degree two over the most variables $n$, the lowest variable first. A polynomial of $n_Q<n$ variables is bound early and waits on the rest: its share is multiplied by each later challenge. Its end is checked against the prover's values $v_Q$, which become the claims $Q({\fdense}_{<n_Q})=v_Q$.
\item \emph{The matrix reduction.} With a challenge, the claims $u^{\top}(aA_0+bB_0)w=v$, the fresh ones with $u=\erow$, $w=\wcol$ and $(a,b)=(1,\lcalpha)$ (\S\ref{flock:native}), the carried ones with $u=\eq(\frow,\cdot)$, $w=\eq(\fcol,\cdot)$ and $(a,b)$ one of $(1,0)$ and $(0,1)$, are batched and proven by a row phase over $\sum_f\sum_x\sum_c\rbat^cu_c(x)\,g_c(x)$ with $g_c=(a_cA_0+b_cB_0)w_c$, then a column phase over $\sum_f\sum_y A_0(\frow,y)\,\mwt{f}{A}(y)+B_0(\frow,y)\,\mwt{f}{B}(y)$ with $\mwt{f}{A}=\sum_c\rbat^cu_c(\frow)\,a_c\,w_c$: Spartan's second sumcheck~\cite{Set20}, every circuit sharing the challenges and waiting as above. The program evaluates each $u$ and $w$ in closed form, $\erow$ through the skip domain's Lagrange weights and $\wcol$ through the slices. A proof's fresh claims come from one batch (\S\ref{flock:batch}): they share $\zskip$, and those of one block size their whole row weight and the equality factor of their column weight, which the program evaluates once, as it does each circuit's waiting factor. The prover computes $g_c$ by one forward walk of the circuit and $A_0(\frow,\cdot)$, $B_0(\frow,\cdot)$ by two backward walks (\S\ref{flock:matrices}), so the matrices are never built.
\end{itemize}
If an input claim is false, the batched claim is false except with probability at most $N/|\E|$ over $\rbat$, $N$ the number of claims, and a sumcheck of degree two over $n$ variables then ends on a false claim except with probability at most $2n/|\E|$. Every challenge is drawn after every input claim is bound. A claim whose scale is zero weighs nothing: a first-level node's carried claim on $\fixnode$, which carries no information, is not reduced.

\subsection{The root}\label{rec:root}

The root's verifier builds $\rfirst$ and $\rnode$ from the shapes, reads the root's kind off its statement, hashes the root's statement into the output its run must have, verifies the root's proof with the native verifier's core on the tree's seed, recomputes the digest from the leaves' outputs, and settles every claim: those the root's own proof leaves, on its program's table and on the circuits' matrices, and those its statement carries, $\bctab$, $\imgpoly$ and $\fixnode$ at their prefixes of $\fdense$, and each circuit's $A_0$ and $B_0$ at its prefixes of $\frow$ and $\fcol$, by one forward walk each. That is one evaluation of each polynomial whatever the number of leaves.

\paragraph{Soundness.} Suppose the root's verifier accepts. The root's proof verifies and its deferred claims are settled, so it is a proof of a run of the program its kind names, on some advice, that reached the exit with the hash of the statement as output: by the collision resistance of BLAKE2s the program computed that very statement. The run reached the exit, so every check of the program passed: for each child, the verifier's core accepted the proof the advice holds, on the tree's seed and the hash of the child's statement, with the claims it left and the claims its statement carries as the reduction's inputs. By the reduction's soundness, if any input claim is false, an output claim is false but with probability at most $(N+4\max_fk_f+2n)/|\E|$. The root's output claims are settled true, so every claim its children left or carried is true: each child's proof is a proof of the program its kind names, with its deferred claims true, and the claims it carries are true. By induction down the tree every first-level node's run verified its leaves' cores on true deferred claims: every leaf verifies against the output its first-level node's digest commits. The digests bind the outputs, in order, to the root's. A root over subtrees of different depths is provable, since a node verifies either kind, but every leaf under it verifies all the same; its digest equals a balanced tree's only by a collision of BLAKE2s, the levels' tags and counts keeping the two messages apart. Knowledge soundness of the recursive composition of Fiat-Shamir proofs is, as for one level, heuristic in the random-oracle sense~\cite{BCCT13}.

\paragraph{Related work.} RISC Zero lifts each segment's proof into a proof of a recursion circuit and joins them in pairs~\cite{BG23}; SP1 compresses its shard proofs by a tree of proofs of a recursion machine~\cite{SP1}; OpenVM's leaf verifier is a program of its own VM, verifying a configurable number of application proofs, and its internal verifier a configurable number of its own~\cite{OpenVM}. Here, as in OpenVM, the verifier is a program of the machine it verifies, with no second arithmetization. Those systems bind the programs or circuits they accept by a commitment to their verifying keys checked inside the proof. Here a program's identity is a claim on $\fixnode$ that every node reduces and only the root's verifier settles.
