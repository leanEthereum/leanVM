\section{End-to-end protocol}\label{sec:e2e}

\subsection{Bytecode encoding}\label{sec:e2e-bc}

The program is public, so nothing is decoded in a table: both parties decode each of the $\nprog=2^{\kbc}$ instruction words once, into the fields the rows read (\S\ref{sec:bytecode}), and encode the result as one $\K$-valued multilinear $P$ in $\kbc+4$ variables:
\begin{enumerate}[itemsep=1pt,topsep=3pt]
\item lay instruction $z$ out as $16$ slots of $\K$: the class tag $\opc{j}$ in slot $2$ (\S\ref{sec:bytecode}); the flags in slot $3$, a word of selector bits naming the class's function, the finalization word for \texttt{HASH}, the accumulate and base-field bits for \texttt{EXT}; the register numbers $a_1,a_2,a_d$ in slots $4$ to $6$, $\intk{\sink}=\intk{32}$ for an instruction with no destination or with $\regs[0]$ as one; the immediate in slot $7$, sign-extended, folded with $\pc$ for \texttt{auipc}, and the link $\pc+4$ for \texttt{jal}; the successor $\intk{\tbase+4z+4}$ in slot $8$; the jump offset $\Delta$ in slot $9$, the fixed target of a branch, a \texttt{jal} or an \texttt{ecall} XOR the successor, and $0$ for an entry with none (\S\ref{sec:tab-classes}); the exit selector $\exitflag$ in slot $11$, $1$ only for \texttt{ecall}; and $0$ everywhere else: slot $10$, where a division's row puts its verdict (\S\ref{sec:tab-classes}), and slots $0$, $1$ and $12$ to $15$, which the separator, the address and nothing occupy in the bus tuple. A slot of the text holding no instruction the machine defines, the halt slot included, is all zeros: its tag is no table's.
\item read the resulting $2^{\kbc}\times16$ table as $P$, the low $\kbc$ variables indexing the instruction and the high four its slot, bits low first.
\end{enumerate}
So $P(z,0,1,0,0)$ is instruction $z$'s tag, $P(z,0,0,1,0)$ its first register, $P(z,0,0,0,1)$ its successor, and $P(z,0,0,0,0)=P(z,1,1,1,1)=0$.

\paragraph{Well-formedness.} The proof system is sound for any table $P$, a malformed one included: it proves that the rows read $P$ and did what its fields say. What makes $P$ a RISC-V program is checked once, by both parties, where a program enters: every entry with a tag reads two registers below $32$ and writes a cell in $1..32$, its successor is its own address plus $4$, its flags are ones its class defines, its exit selector is a bit, $1$ only for the one form of \texttt{ecall}, only a branch, a \texttt{jal} or an \texttt{ecall} has a jump offset, a \texttt{jal} reads $\regs[0]$ twice and has its successor as immediate, a \texttt{LOAD} or \texttt{LD} entry reads $\regs[0]$ as its second register, a \texttt{STORE} or \texttt{SD} entry writes the sink, an \texttt{LD} or \texttt{SD} entry has flags $0$, a \texttt{HASH} entry writes the sink and has immediate $0$, and an \texttt{EXT} entry reads its address from a register, not the sink, and has immediate $0$. The two verifiers check the same rules, and the digest below is of the decoded table, so a verifier is never handed a program it did not check. A table of $\nprog=2^{\kbc}$ slots, the padding and the halt slot included, makes the bus grind $\max(0,\kbc-21)$ bits before its challenges (\S\ref{sec:e2e-ledger}); the text region caps it at $2^{26}$ slots.

\subsection{The statement}\label{sec:e2e-pi}

The \emph{statement} is a program and an output: that the program, run on RAM holding its image, halts on \texttt{exit} with $\regs[10],\dots,\regs[13]$ holding the output (\S\ref{sec:vm}). The program is one digest, BLAKE2s of everything public and fixed: the table $P$, the entry point, the halt slot, $\kmem$, $\kadv$ and the image, each variable-length part length-framed. The digest seeds the Fiat-Shamir transcript (\S\ref{sec:e2e-fiat-shamir}), so every challenge depends on the exact statement; the output does too, as the words the transcript starts from.

The anchored protocol reserves CPU proof envelope \texttt{LVMP} version $17$ and the program digest domain \texttt{leanvm-rv64im-15}. Tree proofs reserve envelope \texttt{LVMT} version $15$ and transcript domain \texttt{leanvm-tree-11}. These numbers exceed the upstream and open-proposal reservations without adopting any proposal's semantics. Public byte decoders reject every earlier envelope version before parsing its body; there is no compatibility fallback. The program domain names the implemented RV64IM configuration, not an inferred identity for another ISA.

RAM's initial words need no claim: its seed column $\meminit$ is public, the image then zeros, and the verifier evaluates its extension at $\zeta$ itself, in time proportional to the image rather than to $\nmem$, the column being zero past the image (\S\ref{sec:leafstack}). The output and the exit are five claims on the committed final registers $\regfin$ at Boolean points, one per register, whose values both parties know and neither transmits:
\[
  \mle{\regfin}(\mathrm{bits}(17))\;\qeq\;\intk{93},\qquad \mle{\regfin}(\mathrm{bits}(10+i))\;\qeq\;\textsf{output}_i\quad(i<4),
\]
with $\mathrm{bits}(r)\in\cube{6}$ the number of the register, low bit first. The PCS opening binds them to the committed column, and Theorem~\ref{thm:rwmem} makes that column what the run's last writes left, so the run executed \texttt{exit} with those values in place. The initial registers are the constant zero, the advice's initial words are the prover's, and nothing else about the run is public.

\subsection{Filling the tables}\label{sec:e2e-pad}

A table is proven over a power-of-two number of rows. The prover reaches one with \emph{padding rows}, whose clock is $0$. The text carries, past the program and an illegal word that keeps a run from falling into them, for each table and each of a few sizes, a block of that many no-ops of the table's class followed by a \texttt{jal} back to the block's first instruction, which no program code jumps into. A padding row is a row at one of those instructions. A clock without the live bit does not advance, so the states pushed and pulled around a block cancel among themselves, for any number of traversals: these are the closed walks of Proposition~\ref{prop:walk}, and by Corollary~\ref{cor:clock} they are the only ones. A traversal of the block of size $n$ adds $n$ rows to its table and one to \texttt{ALU}'s, so every table can be brought to its next power of two exactly, \texttt{ALU}, where every closing jump lands, being solved last.

The verifier has no notion of a padding row, and needs none: a row is inert exactly when its clock lacks the live bit, and the filler blocks are only how an honest prover comes by such rows. A prover may close such rows around any cycle of the program's own control flow instead, and they are inert all the same, by the same two facts: their state tuples cancel because their clocks do not advance, and their accesses meet nothing of the run because the order check \eqref{eq:order} keeps the live bit off their previous timestamps (Theorem~\ref{thm:rwmem}). The filler blocks earn their place by making the fill exact, not by making it safe.

A padding row's accesses cost nothing either. Its access in slot $k$ pushes the timestamp $\intk{0}+\intk{k}=\intk{k}$, and the prover takes $\tsprev=\intk{k}$ and $v_{\mathrm{old}}=v_{\mathrm{new}}$, so the access pulls the very tuple it pushes and the two cancel, whatever the address and the value: the order check \eqref{eq:order} asks a row without the live bit only that its previous timestamps lack it too. A no-op reads $\regs[0]$ twice and writes the sink, a load or a store touches the byte at address $0$, and a compression's block is at address $0$: on zero registers, so the reads are of zeros, and a write rewrites what it writes, which is why a row can rewrite a cell but never update one in place (\S\ref{sec:tables}). Its circuit instances are honest instances on those zeros, and its read of the bytecode an ordinary one. None of this bears on soundness: by Theorem~\ref{thm:rwmem} a tuple whose timestamp lacks the live bit meets no tuple of the run, so the padding rows constrain nothing and are constrained by nothing, which is what a padding row should be. The live bit plays the part of an \emph{is-real} selector, at the cost of no column of its own.

\subsection{Fiat Shamir instantiation}\label{sec:e2e-fiat-shamir}

The transcript uses a byte duplex built from the BLAKE2s compression function, not a keyed PRF and not a permutation. Its public input is a pair of 256-bit values: a digest identifying the protocol and program or circuit, and the public statement's four words. A labeled protocol uses BLAKE2s of its label and the zero statement. A distinguished seed compression binds both before any output. A transmitted scalar contributes its three little-endian 64-bit limbs exactly once, on writing or reading; no separate observation is made. Merkle roots use their canonical two-scalar encoding. The native prover and verifier and the row verifier implement the same framing.

\paragraph{Byte interface.} Positive absorb calls concatenate until a positive squeeze or a nonce event. The last full 64-byte input block is retained until it is known whether another byte follows, so chunking cannot change finality. Positive squeeze calls concatenate one output stream: each terminal compression supplies 32 bytes, and a scalar consumes the next 24, retaining unused bytes even across scalar boundaries. A positive absorb after squeezing discards unused output but binds the number of bytes actually consumed, not the rounded number generated. Empty absorb and squeeze calls do nothing. A squeeze run is limited to $2^{49}-1$ consumed bytes; a request crossing the limit is rejected before mutation. Cloning preserves all pending input, unused output and cursors. No operation exposes an injectable chaining value: exporting the transcript returns a terminal commitment including its cursor and does not change its history.

\paragraph{Exact compression inputs.} Every duplex node uses the full 256-bit preceding chaining value, a 64-byte message, the 64-bit counter described below, and the BLAKE2s final flag set. Only the seed fixes its chaining input to the standard BLAKE2s-256 parameter IV. The counter is the disjoint bit concatenation \texttt{role[8] || length[7] || previous[49]}, with the role in the most significant bits. For absorption, \texttt{length} is the number of meaningful bytes, from 1 to 64, and \texttt{previous} is the consumed count of the preceding squeeze run on the first block only. Nonfinal input blocks have length 64; continuation blocks have previous count zero. All other nodes have both fields zero. All integers in messages are little-endian; unspecified message bytes are zero.

\begin{center}
\begin{tabular}{r l p{0.56\linewidth}}
\textbf{Role} & \textbf{Node} & \textbf{Message} \\
1 & seed & Domain digest followed by statement digest. \\
2 & first, nonfinal absorb & The first full input block. \\
3 & continuation, nonfinal absorb & A subsequent full input block. \\
4 & first, final absorb & The complete input run, zero padded if short. \\
5 & continuation, final absorb & The final input block, zero padded if short. \\
6 & output & The 64-bit output-block index, starting at zero. \\
7 & commitment & The 64-bit consumed-output count. \\
8 & PoW base & The consumed-output count followed by the difficulty, each 64 bits. \\
9 & nonce & The 24-byte nonce, then the consumed-output count and difficulty, each 64 bits. \\
\end{tabular}
\end{center}

Output, commitment and PoW-base nodes are terminal: their results never become live chaining values. An output node addresses the next 32-byte block without changing that value. Absorption and nonce nodes are internal and update it. The first/final tags and final length distinguish a full final block, a continued full block and zero padding. The output index ranges from zero through $\lfloor(2^{49}-2)/32\rfloor$; large-index primitive queries are allowed in the security model even though the application interface consumes bytes sequentially.

\paragraph{Grinding.} A nonce event first finalizes pending input. For positive difficulty $g\le63$, its terminal PoW base is computed without consuming live output. The trial is the ordinary 64-byte BLAKE2s hash of the base, the 24-byte nonce and the little-endian word \texttt{0x31574f502d534646}; its low $g$ bits must vanish. This trial's compression counter is 64, distinct from every duplex role. The prover searches the 64-bit nonce subset and sends its smallest successful member, also under parallel search; the verifier accepts any full-field nonce satisfying the predicate. The internal nonce node binds the entire nonce, difficulty and consumed-output count, then resets the output cursor. At a zero-difficulty grinding call the canonical zero nonce is transmitted and bound without a trial hash; a protocol site that omits grinding entirely emits no nonce event. Counting trials is separate from claiming a PoW improvement to soundness.

\paragraph{Published theorem and model.} Model the public BLAKE2s compression interface, including adversarially chosen chaining values, messages, counters and flags, as a random compression function with 256 output bits. The applicable result is Daemen, Mennink and Van Assche~\cite[Theorem 1, \S4.2]{DMV18}, not an ideal-permutation sponge theorem. That theorem applies to a hashing mode that is subtree-free, radical-decodable and message-decodable (Definitions 4--6), and its simulator makes at most $\fsqueries$ random-oracle queries. Applied to the single mode containing all three terminal families above, it gives
\[
  \fsloss \;\le\; \min\!\left\{1,\frac{\binom{\fsqueries}{2}}{2^{256}}\right\}.
\]
Here $\fsqueries$ counts direct arbitrary-input compression queries and all compression evaluations induced by construction queries, across every instance and branch, including honest verification and auxiliary hashing. A conservative accounting sums the full root-to-terminal path for every distinct terminal coordinate, counting shared prefixes again, rather than equating this theorem's cost with the implementation's cached compression calls. The bound has a classical 128-bit birthday work scale; it is approximately one half at $\fsqueries=2^{128}$, not a $2^{-128}$ failure guarantee for arbitrary query budgets.

\paragraph{Why the hypotheses hold.} A template's message consists of the two seed digests, absorbed bytes and nonce bytes in chronological order. Its frame bits encode the operation grammar, run lengths, prior output counts, nonce difficulties and terminal coordinate; its chaining pointers occupy the complete 256-bit chaining-value field of every nonseed node. A complete chain has exactly one seed at its first end and exactly one terminal at its other end. Any connected subtree is an interval, so an interval containing both is the entire chain: the mode is subtree-free, including across terminal families. For radical-decodability choose the set of proper final subchains. A deterministic recognizer checks chain topology and chaining-pointer positions, one terminal at the final end, no seed, canonical padding and bounded fields, and whether the visible suffix admits a valid prefix. An absorb run has role sequence 4 or $2,3^*,5$; a finite grammar-state scan handles suffixes beginning inside a run, resets and the separating positive squeeze counts. The recognizer returns the chaining-value positions of the oldest node, which must have a child in every completion, and returns failure otherwise. It does not invert the compression function, check that linked values actually hash correctly, or demand that skipped outputs were queried. A complete-chain recognizer instead requires the unique seed and reconstructs all meaningful message bytes and frame bits in linear time, using the final lengths to remove padding. This supplies message-decodability. Analyze the syntactic mode with arbitrary nonce bytes and then restrict to accepted nonce transcripts; PoW success is not a template-recognition condition. These are the hypotheses of the cited theorem, not a fresh unproved birthday-graph estimate.

\paragraph{Sequential ideal interface and adaptive histories.} The theorem's ideal oracle is indexed by message and template, not by raw API-call logs: chunkings and empty calls that produce the same template intentionally coincide. There is an exact lazy-sampling representation as a conventional prefix-consistent XOF on an injective encoding of the completed framed history and terminal family. Output index $i$ selects bytes $32i$ through $32i+31$ of that history's XOF; commitment and PoW-base inputs use disjoint families and include their terminal parameters. Keep one global table of independent 32-byte blocks. Repeated and overlapping prefix requests reuse table entries; fresh coordinates receive independent entries. After a partial squeeze, absorption records the exact consumed count in the new history. Discarding buffered bytes does not erase their old table entries, and any later request for the old history still returns them. A clone shares the old prefix's entries, while distinct later histories use different entries. Induction over adaptive operations, conditioning on the table already exposed, therefore gives the same joint distribution for both interfaces. This is a distributional reduction written here; the probability loss is solely the cited mode bound.

The prefix-XOF adapter does not seek for free: a request for index $i$ can require $32(i+1)$ output bytes, up to $2^{49}$, and its total expansion, history-encoding cost and simulator runtime must be charged in any computational protocol reduction. The simulator's at-most-$\fsqueries$ oracle-query statement is not a linear-time guarantee. Previous consumed counts are encoded history data, not instructions to generate all prior streams. The transcript's fixed 24-byte field codec is a bijection onto $\E$, so disjoint slices give unbiased challenges; unused block bytes are independent padding, not extra independent challenges when reread.

\paragraph{Explicit round-by-round adapter.} The full-transcript form in~\cite[Definition 5.3 and Theorem 5.8]{CCHLRR18} includes previous verifier messages. To reuse its doomed-state sparse-relation argument, maintain one global cache of maximal challenge batches indexed by canonical prover-message prefixes. On a syntactically admissible protocol coordinate request, recursively allocate any missing ancestor batches, reconstruct the preceding verifier messages and any omitted round-polynomial coefficients, then query the full-transcript oracle for the current batch padded to a whole number of 32-byte blocks. Admissibility means parsing under the fixed schedule and resource caps, not successful algebraic, Merkle or PoW checks; a rejecting continuation may be padded to that schedule. Return the requested block and reuse that vector for later slices, overlaps and clones. The schedule and consumed-count framing identify batch transitions; coordinates outside these syntactic histories or their used/padding blocks use an independent lazy table. Large invalid indices therefore need not be expanded into enormous protocol messages. Each first allocated vector is fresh conditioned on the already fixed ancestors, and injective parsing makes distinct canonical prefixes distinct full-transcript inputs, giving exact distributional equivalence. Authenticated Merkle hints remain covered by the PCS binding argument rather than becoming additional absorbed messages.

Let $\fsbatches$ bound challenge-batch depth over every admissible statement, announcement and history the adversary can query, not just the finally submitted proof. Let $\fscoords$ be a worst-case budget for coordinate requests delivered to this adapter before its one final verification, including simulator-generated requests, and let $\fsvectors$ be a deterministic upper bound on the distinct full-transcript vectors allocated. Ancestor completion permits $\fsvectors=\fsbatches(\fscoords+1)$; shared prefixes can support a smaller deterministic bound. For each batch use its existing vector error, or the sum of its constituent round-by-round errors capped at one, and let $\fsbatcherr$ be the largest such grouped error. Use the unground errors unless a separate joint PoW/Fiat-Shamir work argument justifies a grinding improvement. Each fresh full-transcript query escapes a doomed state with probability at most that batch's error. The union bound therefore contributes at most $\fsvectors\fsbatcherr$, conservatively $\fsbatches(\fscoords+1)\fsbatcherr$, in addition to $\fsloss$ and the existing binding and auxiliary losses, with the final probability capped at one. If using the random realized allocation count instead, its expectation belongs in that probability bound. This is the elementary ROM consequence of the cited sparse-relation proof, not a claim that its correlation-intractability theorem literally states this concrete bound. In WHIR, query positions and the adjacent batching scalar have no intervening prover message and form one batch; preserve the error for the entire stratified query set, then account for the adjacent scalar, rather than replacing that vector error by a maximum over individual positions. The fixed-dimension OOD vectors and the individual fold challenges separated by transmitted quadratics fit the same parsing. Charge the total full-transcript encoding sizes and padded vector lengths, plus the mode simulator's runtime. Neither $\fscoords$ nor $\fsvectors$ may silently be identified with $\fsqueries$ or with cached implementation calls. Removing the ancestor or grouping factors requires a stronger argument and is not claimed.

\paragraph{Scope of Fiat-Shamir claims.} For a matching classical canonical-ROM ordinary-soundness theorem, a single-stage acceptance experiment transfers with bound $\fsromloss+\fsloss$, where $\fsromloss$ is evaluated at the simulator's actual query and runtime resources and includes, or separately budgets, statement-digest binding, authenticated auxiliary data, the proof system and any claimed PoW improvement. The verifier's deterministic schedule, reconstructed from its statement and parsed announcement/message prefix, identifies maximal consecutive squeeze runs as challenge vectors. Distinct runs have different framed histories and different challenge slices within a run are disjoint; no prover message can reuse an unconsumed suffix after absorption. This adapter is necessary when applying the round-by-round argument of \S\ref{sec:iopcs}; the mode theorem alone is not a whole-protocol 128-bit security theorem. Knowledge extraction, zero knowledge, quantum security and oracle-programming or rewinding guarantees do not follow from ordinary indifferentiability and are not claimed here.

\paragraph{Why not directly CO25 or SAFE.} CO25 is Chiesa and Orr\`u's \emph{A Fiat-Shamir Transformation From Duplex Sponges}~\cite{CO25}. SAFE is Aumasson, Khovratovich, Mennink and Quine's \emph{Sponge API for Field Elements}~\cite{SAFE23}; its improved full-capacity initialization is analyzed by Khovratovich, Marhuenda Beltr\'an and Mennink~\cite[Theorem 2]{KMM23}. Those constructions use an ideal permutation, whereas the selected BLAKE2s interface maps a chaining value, message and tweaks to a shorter digest and is not invertible. Substituting it for their permutation does not instantiate their hypotheses. This is not an impossibility result for all BLAKE-based constructions; it motivates the applicable compression-mode theorem above rather than relabeling a compression function as a permutation. BLAKE2b has a larger block and digest but lacks this machine's existing compression instruction and row circuit, so a native-only reduction in its call count would not establish a recursive cost improvement.

Finally, ideal compression is an explicit assumption about the concrete primitive. Luykx, Mennink and Neves~\cite[Theorem 1]{LMN16} give a separate weakly ideal BLAKE-cipher bridge, with bound $\binom{\fsqueries}{2}/2^{512}+\binom{\fsqueries}{2}/2^{256}+\fsqueries/2^{128}$ for the appropriately mapped cipher-query budget. Its linear term cannot be omitted when claiming that stronger model, and neither result is an unconditional security proof of concrete BLAKE2s.

\paragraph{Compression accounting and cutover.} After the seed, a positive absorb run of \texttt{A} bytes followed by \texttt{S} output bytes costs \texttt{ceil(A/64) + ceil(S/32)} compressions; consecutive same-mode calls add no framing compressions. A nonce adds its internal node and, at positive difficulty, its base and trial hashes. An export costs its terminal node and, if input is pending, one nonmutating finalization; repeated exports are charged again. This favors long runs without pretending that every alternating single-scalar run becomes cheaper. The cutover uses program domain \texttt{leanvm-rv64im-13}, tree domain \texttt{leanvm-tree-10}, reduction label \texttt{leanvm-tree-reduction-4}, and proof envelopes \texttt{LVMP} version 15 and \texttt{LVMT} version 13. The leanDA host's membership label becomes \texttt{leanDA/rs-membership/v2}. Standalone bincode transcripts start with \texttt{LVFS} and little-endian version 1. Unversioned and older proof formats are rejected, with no legacy transcript path.

\subsection{The unrolled protocol}\label{sec:e2e-unrolled}

Each reduction below adds evaluation claims on columns to a shared \emph{claim pool}, proved by the final PCS \textsc{Opening} phase.

\paragraph{Setup.}

The Fiat-Shamir state is seeded by the statement (\S\ref{sec:e2e-fiat-shamir}). The prover sends the eleven table log-heights $\tau_j$, the PCS rate and the final clock $\tsfinal\in\K$ (\S\ref{sec:state}); the verifier checks each $\tau_j$ against the cap $2^{32}$ and the batch floors (\S\ref{sec:tables}), and that $\tsfinal$ is a live clock at slot $0$, and derives the layout of every stack (PCS and GKR leaves) and the producer's bit count $\nbit$ (\S\ref{sec:lookup}) from those sizes and the program's.

\paragraph{Commitment.}

\begin{enumerate}
\item \textbf{Prover.} Stack (\S\ref{sec:stacking}) every column: the read-write arrays' final columns and timestamps, $\regfin,\memfin,\advfin$ and their $\tsfin$, the advice's initial words $\advinit$ (\S\ref{sec:memchan}), the bytecode's multiplicity column $\mlt$ (\S\ref{sec:lookup}), the twenty-one packed witnesses, $\qcls{j}$ for the ten tables with a class circuit and $\qclk{j}$ for all eleven (\S\ref{sec:tab-class}, \S\ref{sec:clock}), every committed column of the eleven tables, and the register words $\regword{w}$ (\S\ref{sec:regpack}), into $q$, and send its commitment (Annex~\ref{annex:pcs}).
\item \textbf{Verifier.} Snapshots the exact original pre-commit transcript context $c_{\mathrm{pre}}$, including the chaining value and pending scalar buffer without flushing. Checks the \texttt{whir-anchor-v1} marker and expected public shape, receives the root, samples one point $a\in\E^M$, and receives the advertised value $v_a$. This completes $\mathsf{cm}=(c_{\mathrm{pre}},s,R,a,v_a)$ before the bus, table and Flock challenges. Both parties retain and reuse this immutable record for every opening.
\end{enumerate}

\paragraph{Bus.}

\begin{enumerate}
\item \textbf{Prover \& Verifier.} When $\kbc>21$, the prover sends a proof of work of $\kbc-21$ bits and the verifier checks it (\S\ref{sec:e2e-fiat-shamir}, \S\ref{sec:e2e-ledger}). A smaller program sends nothing here.
\item \textbf{Verifier.} Samples and sends the fingerprint challenge $\alpha\in\E^{4}$ and the multiset challenge $\beta\in\E$ (\S\ref{sec:gp}).
\item \textbf{Prover.} Forms the push and pull leaf vectors (\S\ref{sec:leafstack}), the push side ending on the bytecode producer's bit blocks (\S\ref{sec:lookup}), stacked into blocks and padded with $1$s. Sends one bus root $R$.
\item \textbf{Prover \& Verifier.} Run the one batched GKR (\S\ref{sec:gkr}) over the two trees, at the depth $\mu$ of the taller. The verifier checks each side's product against $R$; one $R$ for both sides is the balance check (\S\ref{sec:gp}). The pass yields two leaf claims $\widetilde V^{s}_0(\zeta)$ at one shared $\zeta$.
\item \textbf{Prover \& Verifier.} Decompose each leaf claim (\S\ref{sec:leafstack}). The verifier forms every public part itself: the block selectors, the constant entries, the index columns (\S\ref{sec:idxcol}) and RAM's seed column (\S\ref{sec:e2e-pi}). Four blocks per side belong to no table: the state boundary, plus the registers', RAM's and the advice's seed (push side) or finalization (pull side). For their committed columns the prover sends one evaluation each, entering the claim pool: on the push side the advice's initial column alone, on the pull side every final column and timestamp. Every other block belongs to a table or to a producer, and is discharged below.
\end{enumerate}

\paragraph{Linear tables.} The ten tables with a class circuit flush only tuples linear in their columns (\S\ref{sec:tables}).
\begin{enumerate}
\item \textbf{Prover.} Sends, table by table, the value of every column of $T_j$ at $\zeta_{<\tau_j}$ but its register numbers, which the table sumcheck folds (\S\ref{sec:regpack}); they enter the claim pool, a port's routed to its packed witness (\S\ref{sec:tab-class}).
\item \textbf{Verifier.} Evaluates each such table's form $B^{s}_j$ at those values, its register numbers taken as zero, its share of side $s$ short of the numbers' part, and takes it off what the tables owe (\S\ref{sec:leafstack}).
\end{enumerate}

\paragraph{Table sumcheck.} One run proves what is left of the bus, \texttt{EXT}'s share, the linear tables' register numbers' part and the producer's (\S\ref{sec:air}), and \texttt{EXT}'s three identities, the only constraints a table has (\S\ref{sec:tab-classes}).
\begin{enumerate}
\item \textbf{Verifier.} Samples and sends the batch challenge $\xi\in\E$. Its first $\nside=2$ powers weight the bus forms, one per side and shared by every table and the producer, and the next three, $\xi^{2}$ to $\xi^{4}$, \texttt{EXT}'s identities, whose sums are zero, so the target is the bus's alone. It draws no point: the batch runs at the bus point, $T_j$ tested at $\zeta_{<\tau_j}$ and a producer of $2^{\kappa}$ entries at $\zeta_{<\kappa}$.
\item \textbf{Prover \& Verifier.} Run the sumcheck over the eleven tables, a linear table's forms restricted to its register numbers, and then the bytecode's producer, $\taumax$ rounds, $\taumax$ the largest of their log heights, each joining at round $\taumax$ minus its own, against the target the verifier derived from the two leaf claims. Its summand has individual degree three and the round check pins one of the four coefficients (\S\ref{sec:prelim}), so a round costs three $\E$-elements.
\item \textbf{Prover \& Verifier.} The prover sends one value per column of \texttt{EXT} and per register number of a linear table, but for a register number its bits' values (\S\ref{sec:regpack}), and each producer's bit values $\widetilde{\mbit{k}}(\fc_{<\kappa})$, $k<\nbit$; the verifier computes each producer's public columns $\widetilde{\pubp{k}}(\fc_{<\kappa})$ itself (\S\ref{sec:lookup}). It rebuilds each $B^{s}_j$ and \texttt{EXT}'s identities from them and checks that they reproduce the sumcheck's final value; \texttt{EXT}'s column values then enter the claim pool at $\fc_{<\tau_j}$. A circuit's ports are columns of its table but live in $\qcls{j}$ or $\qclk{j}$, so their claims route there (\S\ref{sec:tab-class}); a producer's bits are slices of its multiplicity column, and a table's register numbers' bits slices of the register word that packs them, so their claims go to ring switching (below).
\end{enumerate}

\paragraph{The exit.}

\begin{enumerate}
\item \textbf{Prover \& Verifier.} Pool the five claims on $\regfin$ at the Boolean points naming $\regs[17]$ and $\regs[10],\dots,\regs[13]$, with the values $\intk{93}$ and the output; the prover sends nothing (\S\ref{sec:e2e-pi}).
\end{enumerate}

\paragraph{Flock validity.}

\begin{enumerate}
\item \textbf{Prover \& Verifier.} Run Flock's reduction (Annex~\ref{annex:flock}) once over the twenty-one circuits, batched under shared challenges (\S\ref{flock:batch}): every class circuit in table order, over $\qcls{j}$, \texttt{EXT} having none, then every clock circuit in table order, over $\qclk{j}$, each with $2^{\tau_j}$ instances. One zerocheck, its round-one message shared by all twenty-one, and one lincheck leave one evaluation claim on each packed witness, and one claim on each circuit's matrix form, which the verifier settles by one walk of the circuit once the proof is read.
\item \textbf{Prover \& Verifier.} Before any stacked opening challenge, bind and check the \texttt{whir-opening-v1} record frame of Annex~\ref{annex:pcs} against the supplied immutable commitment. This binds the original context, full shape, root, point and value into the current session before $\rsgamma$, the map and $\lambda$ are sampled. The original point is transmitted for comparison, never resampled.
\item \textbf{Verifier.} Sends $\rsgamma\in\E$, drawn after every ring-switched claim is bound. The claims are the twenty-one witnesses', then the bytecode's multiplicity column's, its suffix point being its $\fc_{<\kappa}$ and its $64$ slices the $\nbit$ bit values it sent, then zeros, which are not transmitted (\S\ref{sec:lookup}), then each register word's, its suffix point being its tables' shared $\fc_{<\tau_j}$ and its slices the bit values sent for its tables, in its order, then zeros (\S\ref{sec:regpack}); claim $j$, from zero, takes the scale $\rsgamma^{\,j}$, and both sides form the family's slices $\sfam{i}=\sum_j\rsgamma^{\,j}s_{j,i}$ (\S\ref{rs:family}). The prover sends nothing.
\item \textbf{Prover \& Verifier.} The ring switching of \S\ref{sec:ringswitch}, its map drawn after $\rsgamma$, reduces the family to one weighted-sum claim on the stack, target $\sum_ix^i\Phi(\sfam{i})$, with an MLE-friendly $\E$-valued weight (Definition~\ref{def:ipcs}) supported on the ring-switched regions, claim $j$'s being $\Phi\bigl(\rsgamma^{\,j}\eq(r_j,\cdot)\bigr)$; it joins the pool, ahead of every column claim. The circuits of one block size leave points that are prefixes of one another, so the verifier evaluates their weights in one pass (\S\ref{rs:weight}).
\end{enumerate}

\paragraph{Opening.}

\begin{enumerate}
\item \textbf{Prover \& Verifier.} Each pooled claim is one evaluation of a column at a point, its value already supplied; via the stacking selectors (\S\ref{sec:stacking}) it becomes a weighted sum $\sum_w W_j(w)\,\widetilde q(w)=c_j$ over the stacked witness. (The ring-switched claim arrives already in this form, its weight supported on the ring-switched regions.)
\item \textbf{Verifier.} Using the immutable record already bound by the checked opening frame before the ring-switch challenges, sends one batching challenge $\lambda\in\E$, drawn after every claim value is bound. With $p$ pooled point claims, the ring-switched family takes $\lambda^0=1$, point claim $j$ takes $\lambda^{j+1}$ for $j=0,\dots,p-1$, and the immutable anchor $(A_{s,a},v_a)$ takes $\lambda^{p+1}$. The $p+2$ weights are distinct powers of one challenge; the frame retransmits and checks the original anchor but never resamples it.
\item \textbf{Prover \& Verifier.} Fold the family, all point claims and the same supported anchor into $W_\lambda$ and $C_\lambda$ as in \S\ref{sec:stacking}, and run the inner-product PCS opening on $\sum_wW_\lambda(w)\widetilde q(w)=C_\lambda$ (Annex~\ref{annex:pcs}). Every weight vanishes on omitted lanes, and the verifier evaluates the extension of the occupied-prefix anchor weight at the terminal fold point. This one opening discharges every pooled claim and enforces the advertised commitment-time value; there is no separate reduction sumcheck and no root-only public opening path.
\item \textbf{Verifier.} Accepts if every check above passed: the caps, the one bus root for both sides, every sumcheck's rounds and final value, flock's batched reduction, and the PCS opening.
\end{enumerate}

\subsection{Soundness ledger}\label{sec:e2e-ledger}

The root alone fixes a list of at most $L_0=\tfrac{1}{2\slack_0\sqrt{\rate_0}}$ candidates (Theorem~\ref{thm:rbr}); the public record additionally fixes one commitment-time point and advertised value. The ideal uniform-anchor separation term is at most $2^{-124}$ for a commitment-fixed supported list of size at most $2^{32}$ in at most $32$ variables (Annex~\ref{annex:pcs}), and it is separate from failures of the later opening checks. The original opening and reduction ledger below conservatively unions over the root-fixed list: a test that a fixed polynomial passes with probability $\varepsilon$ is passed by some candidate with probability at most $L_0\varepsilon$. This preserves the bus parameter target $128+\lceil\log_2L_0\rceil=140$ at its default list cap, but does not prove that the anchored deployed system has that security level.

The original idealized round-by-round parameter ledger records algebraic error and grinding-adjusted work targets, in bits, under its field, list and layout hypotheses. The grinding adjustments are work targets, not error improvements established by the ordinary-soundness adapter above. These are not proved bounds on the concrete whole system:
\begin{itemize}[itemsep=1pt,topsep=3pt]
\item \emph{Bus} (\S\ref{sec:gp}, \S\ref{sec:gkr}): $4N/|\E|$ for the fingerprint, $N$ the larger side's linear factors, plus at most $8(\mu+1)^2/|\E|$ for the GKR; times $L_0$, at least $128$. The bytecode producer dominates $N$ with up to $2^{\kbc}(2^{\nbit}-1)$ factors (\S\ref{sec:lookup}). In a layout one commitment holds, the multiplicity column and every table's packed witness share the $2^{28}$ committed words, so $\nbit\le28$ and every block has at most $2^{28}$ rows. With $\kbc\le21$ the whole degree is below $2^{52}$, which leaves $140$ bits before the union and $128$ after. Each further bit of $\kbc$ doubles the degree and costs a bit, down to $135$ and $123$ at the text region's $\kbc=26$. The configured prover therefore grinds $g=\max(0,\kbc-21)$ bits before $\alpha$ and $\beta$, targeting a work factor of $2^g$. Converting this target into a per-oracle-query error improvement requires the separate joint PoW/Fiat-Shamir work argument and is not established here. The GKR's own term stays above $160$ bits after the union. The native verifier also refuses an announced layout whose bus would miss the configured grinding-adjusted target.
\item \emph{Table sumcheck} (\S\ref{sec:air}): $(3\taumax+\nside+\nconstot)/|\E|$ with $\taumax\le32$; at least $172$ after the union.
\item \emph{Flock} (Annex~\ref{flock:soundness}): below $2^{-183}$; at least $171$ after the union.
\item \emph{Ring switching} (Lemma~\ref{lem:rs-family}): $(\nrs-1)/|\E|+2^{-160}$; at least $147$ after the union.
\item \emph{Opening} (Theorem~\ref{thm:rbr}): each row already carries its level's list size $L_i$, so no further union applies. At the configured parameters the fold challenges' MCA errors clear $128$ bits, the batching challenges $168$, and the OOD challenges $150$. Each query phase has a $111$-bit query-error target and a separate $17$-bit grinding-work target.
\end{itemize}
The configured $128$-bit level is a design target, not a proved whole-system bound. The ideal anchor term, the original opening and reduction ledger, and concrete cryptographic losses must be accounted for separately. Merkle binding requires a concrete hash collision assumption; Fiat-Shamir requires its actual oracle-query budget, the matching ROM compilation theorem, and separate compression-mode and binding losses in \S\ref{sec:e2e-fiat-shamir}, including grinding, framing and field-sampling behavior. The random-function modelling there is an assumption, not a replacement proof of the deployed primitive against every observer. In particular, clearing a per-round target or ideal pairwise anchor uniqueness does not itself supply an end-to-end security bound, efficient knowledge extraction or Rust-to-Lean correspondence.
