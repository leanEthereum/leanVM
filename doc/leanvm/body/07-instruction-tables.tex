\section{The instruction tables}\label{sec:tables}

The instructions are grouped into eleven \emph{classes}, and each class has its own table (\S\ref{sec:bytecode}). All eleven tables are the same table: a row does the plumbing that every instruction needs, the state step, the bytecode read, the register accesses and the memory accesses, and what the class computes is a Boolean circuit proven by Flock (Annex~\ref{annex:flock}), one instance per row, whose words the row puts on the bus. The exception is \texttt{EXT}, the extension-field product, which is of degree two over $\K$: its table has no class circuit and states the product as identities instead, with an \emph{operand circuit} for what is Boolean about its row. The tables differ in which words their circuit has, where the class sends control, and how it touches memory. Every tuple a table with a class circuit flushes is linear in its columns, so that table settles at the bus's point, all but its register numbers, which the table sumcheck folds (\S\ref{sec:leafstack}, \S\ref{sec:regpack}).

A read of a lookup array (\S\ref{sec:lookup}) is the single flush \pull\ $\tup{\sep,\addr,\val_0,\val_1,\dots}$; the array's producer pushes the entry back as often as it is read.

A row's registers and memory are reads of the logs (\S\ref{sec:memchan}), each a single pull. Its register tuple, at its time $\tm$, is
\[
  \pull\ \tup{\dsep{REG},a_1,\tm,a_2,a_d,v_1,v_2,v_d},
\]
the registers read, the cell written, the values read and the value left in the written cell. Write $\acc{k}\tup{a;\,v_{\mathrm{old}}\to v_{\mathrm{new}}}$ for the row's memory access $k$, at the address $a$:
\[
  \pull\ \tup{\dsep{MEM},a,\pos\,\gen^{k},v_{\mathrm{old}},v_{\mathrm{new}}},
\]
and $\acc{k}\tup{a;\,v}$ for a read, $v_{\mathrm{old}}=v_{\mathrm{new}}=v$. A table has no constraint of its own but \texttt{EXT}'s identities: what a row asserts, its circuit asserts.

\subsection{The class table}\label{sec:tab-class}

\paragraph{The circuit's words.} A class's circuit (\S\ref{flock:classes}) reads and writes whole $64$-bit words, its \emph{ports}: the register values $v_1,v_2$, the bytecode's flags and immediate, the result, a memory cell, and so on, as the class needs. Flock packs the circuit's witness $64$ bits to a $\K$-element, so a port IS one word of the class's packed witness $\qcls{j}$, committed once (\S\ref{sec:e2e-unrolled}). The table commits none of these words again: they are \emph{virtual} columns, and a claim the bus raises on one of them at a row is routed to the same word of that row's instance in $\qcls{j}$ (\S\ref{sec:stacking}). Putting a port in a bus tuple is therefore what binds the circuit to the machine: the value it reads from a register is what the register tuple carries, the flags it decodes on are what the bytecode tuple carries, the result it computes is what the register write pushes. No constraint ties the two, because they are one committed value.

\paragraph{Columns.} The state $\pc$, the time $\tm$ and the position $\pos$; the bytecode entry's register number $a_1$ and successor $\pc^{+}$, $a_1$ like $a_2$ and $a_d$ below a field of the row's register word rather than a column of its own (\S\ref{sec:regpack}); the value read, $v_1$, a port; the flags, a port, for a class that has them; then, for a class that reads a second register, $a_2$ and the port $v_2$; for a class that writes a register, $a_d$ and the result $\mathit{out}$ (a port); for the class with control flow, the bytecode's jump offset $\Delta$, a port, the circuit's jump $\mathit{jump}$, a port, and the bytecode's exit selector $\exitflag$, the successor $\pc^{+}$ being a port of its circuit too; the immediate $\mathit{imm}$ (a port) if the circuit takes one; the memory words below. A word is $64$ bits and a register holds one, so every port that reaches a tuple is a $\K$-element as it stands.

\paragraph{Flushes.}
\begin{itemize}
  \item \textbf{State:} \pull\ $\tup{\dsep{ST},\pc,\tm,\pos,0}$, \push\ $\tup{\dsep{ST},\pc',\gen\,\tm,\gen^{n}\pos,\exitflag}$, $n$ the row's memory accesses (\S\ref{sec:state}), where the next $\pc$ is the class's (below), $\pc'=\pc^{+}$ unless said otherwise, and $\exitflag=0$ for a class with no control flow.
  \item \textbf{Bytecode:} \pull\ $\tup{\dsep{BC},\pc,\opc{j},\mathit{flags},a_1,a_2,a_d,\mathit{imm},\pc^{+},\Delta,0,\exitflag}$, a constant in place of a column the row has not: $0$ for $\mathit{flags}$, $0$ for $a_2$, $\intk{\sink}$ for $a_d$, $0$ for $\mathit{imm}$, and $0$ for $\Delta$ and $\exitflag$ outside the class with control flow, which the entry then has to hold (\S\ref{sec:e2e-bc}).
  \item \textbf{Registers:} the register tuple, a constant in place of a column the row has not: $0$ for $a_2$ and $v_2$ when the class reads no second register, $\intk{\sink}$ for $a_d$ and $0$ for $v_d$ when it writes none, and $v_d=\mathit{out}$ unless said otherwise. A class has $a_2,v_2$ exactly when its circuit takes $v_2$, and $a_d$ and its result exactly when its circuit gives $\mathit{out}$, or when it moves the word between the register and its cell (\texttt{LD}, \texttt{SD}).
  \item \textbf{Memory:} the class's accesses, $\acc{0}$ and up.
\end{itemize}
A padding row (\S\ref{sec:e2e-pad}) is a row of the class's no-op instruction on zero registers at time and position $0$, its circuit instance an honest one.

\subsection{The register words}\label{sec:regpack}

A row's register numbers, $a_1$, then $a_2$ and $a_d$ for a class that has them, $\nreg$ of them, are fields of its bytecode entry: the bytecode lookup reads them, and the register accesses name the cells they number. A register read is below $2^{5}$; a cell written may be the sink, $32$, below $2^{6}$ (\S\ref{sec:vm}). A word of its own would spend $64$ bits on five or six, so a table's numbers are packed, low first, into $\nregbit{j}$ bits, five per register read and six for a cell written: for an \texttt{ALU} row,
\[
  a_1+x^{5}a_2+x^{10}a_d,\qquad \nregbit{j}=16.
\]
Tables of one height share a word. In table order, each table joins the first \emph{register word} $\regword{w}$ of its height whose bits leave room for its $\nregbit{j}$, its fields following the previous table's, or opens one; row $x$ of $\regword{w}$ packs row $x$ of each of its tables. The words are committed, and nothing else of the numbers. The bits $\regbit{w}{k}$ are one-bit columns of each table the word packs, and each register number is the column $\sum_{b}x^{b}\,\regbit{w}{o+b}$ over its field's bits, $o$ its first: bit $b$ of an integer is the element $x^{b}$ of $\K$ (\S\ref{sec:vm}), so on a row that sum is the integer itself. A register number is thus a virtual column, of degree one in the bits, and enters the bus tuples as before.

\paragraph{What is sent.} The table sumcheck (\S\ref{sec:air}) folds a register number like any column, and at its end the prover sends, in place of the number's value at $\fc_{<\tau_j}$, its bits' values $\widetilde{\regbit{w}{k}}(\fc_{<\tau_j})$. A linear table, whose other columns the bus point settles (\S\ref{sec:e2e-unrolled}), takes part with its register numbers alone, its summand being its bus forms' part on them, so that every table's numbers are read at the table sumcheck's point: read at $\zeta_{<\tau_j}$, its words' claims would sit at a second point, whose Frobenius products the ring switching would pay again (\S\ref{rs:family}). The extension is linear, so the verifier forms the number's value as $\sum_bx^{b}\,\widetilde{\regbit{w}{o+b}}(\fc_{<\tau_j})$ and checks the final identity with it. The tables of one height share their point $\fc_{<\tau_j}$, so the bits of a word enter the ring switching (\S\ref{sec:ringswitch}) as one claim on its region: its suffix point is that point and its $64$ slices are the values sent for its tables, in its order, then zeros, which are not sent.

\paragraph{Why it is sound.}
\begin{itemize}
  \item \textbf{The bits are bits.} They are slices of committed words, Boolean by construction, as a multiplicity's are (\S\ref{sec:lookup}), and ring switching binds the values sent to the committed $\regword{w}$: values that are not its slices at that point fail the opening except with the probability of Annex~\ref{annex:rs}.
  \item \textbf{The unused bits are zero.} The verifier supplies zero for the slices past the word's last field, so a word with one of those bits set fails the opening, and an honest word has none. No register number reads those bits, so this only keeps the claim exact: soundness does not rest on it.
  \item \textbf{The numbers are the decoded ones.} A register number is one column, of value below its field's $2^{5}$ or $2^{6}$ on every row, in both the bytecode tuple and the register access. Theorem~\ref{thm:omc} makes every bytecode tuple an entry of the program, so on every row the number is its entry's field, and the access names exactly the decoded register. This is the argument a committed number had: the lookup binds it, and the packing changes how it is committed, not what binds it. A field too narrow for an entry's number would make the honest run unprovable, never a forged one provable, and the decoder's rules keep every entry within its field (\S\ref{sec:e2e-bc}).
\end{itemize}

\paragraph{Cost.} The tables of one height commit one word per row where they committed one per register number, $4$ tables of three numbers fitting in one word. A proof sends $\nregbit{j}-\nreg$ more $\E$-elements per table, bits in place of values, and the ring switching takes one more claim per word, which sends nothing.

\paragraph{Why not drop the numbers.} The bus needs a register number only at its point, $\sum_x\eq(\zeta,x)\,T[\pc_x]=\sum_iY_i\,T[i]$, for $T$ the program's column and $Y$ the pushforward of $\eq(\zeta,\cdot)$ along the rows' $\pc$, so a pushforward argument~\cite{Sou25} would commit nothing per row. But $Y$ depends on $\zeta$, a challenge: it would be a second commitment, made after one, and a second opening, where every challenge of this protocol comes after the one commitment of the whole witness (\S\ref{sec:e2e-unrolled}), an invariant its Fiat-Shamir instantiation is argued under (on what Fiat-Shamir can break, see~\cite{KRS25}). Sending $Y$ in clear instead costs a bytecode-sized vector of $\E$-elements per proof. The register word is committed with everything else, before any challenge.

\subsection{The classes}\label{sec:tab-classes}

The instructions of rv64im and the custom ones are decoded into the eleven classes below, an entry's flags selecting one function of its class (\S\ref{sec:e2e-bc}); \texttt{lui}, \texttt{auipc} and \texttt{jal}'s link $\pc+4$ are constants added to $\regs[0]$, \texttt{fence} is an addition of zeros, and \texttt{ecall} a jump to the halt slot. The reference for every function is the specification~\cite{riscv}; \S\ref{flock:classes} gives the circuits.

\paragraph{\texttt{ALU}} (arithmetic, comparisons, bitwise logic, branches and jumps). Ports $v_1,v_2,\mathit{imm},\mathit{flags},\Delta,\pc^{+}\to\mathit{out},\mathit{jump}$. The second operand is $v_2\oplus\mathit{imm}$, the decoder making one of the two zero. The bytecode's $\Delta$ is the fixed target XOR $\pc^{+}$, so that $\pc^{+}+\Delta$ is the target, and $0$ for an entry with none. With $b\in\{0,1\}$ whether the jump is taken, a wire of the circuit, the circuit gives $\mathit{jump}=b\,\Delta$, bit by bit. This is the one class with control flow, and its successor is linear in the row's columns:
\[
  \pc'=\pc^{+}+\mathit{jump},\qquad v_d=\mathit{out}.
\]
A \texttt{jal} links $\pc^{+}$ as its immediate added to $\regs[0]$, so $\mathit{out}$ is the link; a branch writes the sink. A \texttt{jalr} is the flag $\mathit{indirect}$, set with the one that makes $b=1$, and has $\Delta=0$: with $s=v_1+\mathit{imm}$ the sum, its circuit outputs $\mathit{out}=\pc^{+}$, the link, and adds $s\oplus\pc^{+}$ to $\Delta$ but for bit $0$, so that $\pc'$ is $s$ with bit $0$ cleared, $\pc^{+}$ having none. A target that is no instruction's address, misaligned or outside the text, names no entry, so the next row reads none.

\paragraph{\texttt{LOAD}} (\texttt{lb}, \texttt{lbu}, \texttt{lh}, \texttt{lhu}, \texttt{lw}, \texttt{lwu}). Ports $v_1,\mathit{imm},\mathit{flags},\mathit{cell}\to\mathit{address},\mathit{out}$: the circuit adds the address, extracts the bytes the width and the offset select from the cell and extends them, and hands the bus the word's address with the misalignment bits in it (\S\ref{sec:exp}). A load reads one register, so it has no $a_2,v_2$ columns and reads $0$ off the entry. One access, $\acc{0}\tup{\mathit{address};\,\mathit{cell}}$.

\paragraph{\texttt{STORE}} (\texttt{sb}, \texttt{sh}, \texttt{sw}). Ports $v_1,v_2,\mathit{imm},\mathit{flags},\mathit{cell}\to\mathit{address},\mathit{cell}'$, the new cell being the old one with the stored bytes replaced. A store writes no register, so it has no $a_d,\mathit{out}$ columns and reads $\intk{\sink}$ off the entry. One access, $\acc{0}\tup{\mathit{address};\,\mathit{cell}\to\mathit{cell}'}$.

\paragraph{\texttt{LD}, \texttt{SD}} (\texttt{ld}, \texttt{sd}). Ports $v_1,\mathit{imm}\to\mathit{address}$, the adder alone: a doubleword is its whole cell, so there are no bytes to select and the bus address is the sum itself (\S\ref{sec:exp}). Neither has flags, so both read $0$ off the entry for them. The word moved is a committed column, the same in the register's tuple and in the cell's, so no constraint is needed to say they agree. \texttt{LD} reads no second register and has no $a_2,v_2$ columns; its $\mathit{cell}$ is committed, and it is what $\regs[a_d]$ receives: $\acc{0}\tup{\mathit{address};\,\mathit{cell}}$ and $v_d=\mathit{cell}$ in its register tuple. \texttt{SD} writes no register and has no $a_d$ column; its $v_2$ is committed, and it is what the cell receives: $v_2$ in its register tuple and $\acc{0}\tup{\mathit{address};\,\mathit{cell}\to v_2}$.

\paragraph{\texttt{SHIFT}, \texttt{MUL}, \texttt{MULH}.} Ports $v_1,v_2,\mathit{imm},\mathit{flags}\to\mathit{out}$ for the shifts (the amount being the low bits of $v_2\oplus\mathit{imm}$), $v_1,v_2,\mathit{flags}\to\mathit{out}$ for the low and the high word of a product.

\paragraph{\texttt{DIV}} (division and remainder). Ports $v_1,v_2,\mathit{flags},q,r\to\mathit{out},\mathit{bad}$. The circuit does not divide: the prover supplies a quotient and a remainder, $q$ and $r$, as \emph{hints}, ports that are in the witness and in no column, and the circuit checks $v_1=q\cdot v_2+r$ over the integers with $r<|v_2|$, and the specification's cases for a zero divisor and the overflow. The check's verdict is the word $\mathit{bad}$, nonzero on a wrong hint, which the row puts in slot $10$ of its bytecode tuple: the program is zero there, so by Theorem~\ref{thm:omc} a row with $\mathit{bad}\neq0$ reads no entry.

\paragraph{\texttt{HASH}} (\texttt{blake2s}). Ports $v_2,\mathit{flags},h_0,\dots,h_3,m_0,\dots,m_7\to\mathit{out}_0,\dots,\mathit{out}_3$: the counter is the second register and the finalization word the flags (\S\ref{sec:vm}). The row writes no register, so it has no $a_d,\mathit{out}$ columns and reads $\intk{\sink}$ off the entry, and it has no immediate. Its block is sixteen accesses at $v_1+\intk{8k}$ (\S\ref{sec:exp}): reads of the chaining value and the message, whose words are ports, and writes of the result, whose old values $\mathit{out}^{\mathrm{old}}_k$ are four committed columns:
\begin{align*}
  &\acc{k}\tup{v_1+\intk{8k};\,h_k}\quad(k<4),\qquad
  \acc{k}\tup{v_1+\intk{8k};\,m_{k-8}}\quad(8\le k<16),\\
  &\acc{k}\tup{v_1+\intk{8k};\,\mathit{out}^{\mathrm{old}}_{k-4}\to\mathit{out}_{k-4}}\quad(4\le k<8).
\end{align*}

\paragraph{\texttt{EXT}} (\texttt{extmul}, \texttt{extmac}, \texttt{extmulk}, \texttt{extmack}). No class circuit: the table states the product as identities, and its operand circuit computes what is Boolean about the row.

The three registers hold the addresses of $a$, $b$ and $c$ (\S\ref{sec:vm}). The row reads all three and writes none. So its register tuple is under $\dsep{PTR}$ rather than $\dsep{REG}$, with $v_d$ the address read at $a_d$ and left there: the register log makes such a row write nothing (\S\ref{sec:memchan}). The row has columns $a_d$ and $v_d$, and no $\mathit{out}$.

The limbs as the row finds them, $a_0,a_1,a_2,b_0,b_1,b_2,c_0,c_1,c_2$, and the new limbs $c'_0,c'_1,c'_2$ are twelve committed columns. Then come nine accesses, one per limb. Limb $k$ is at $\mathit{addr}_k$, with $\mathit{addr}_0=v_1$, $\mathit{addr}_3=v_2$ and $\mathit{addr}_6=v_d$:
\[
  \acc{k}\tup{\mathit{addr}_k;\,a_k},\qquad
  \acc{3+k}\tup{\mathit{addr}_{3+k};\,b_k},\qquad
  \acc{6+k}\tup{\mathit{addr}_{6+k};\,c_k\to c'_k}\qquad(k<3).
\]

The operand circuit (\S\ref{flock:classes}) has input ports $v_1,v_2,v_d,\mathit{flags}$ and eight output ports, its packed witness $\qcls{EXT}$. The first two are the flags' bits, $\mathit{acc}$ and $\mathit{base}$, each a whole port, so each is $0$ or $1$ in $\K$. Bit $0$ accumulates: $c'=c+a\cdot b$ instead of $a\cdot b$. Bit $1$ makes $b$ a base-field element. The other six are the addresses $\mathit{addr}_1,\mathit{addr}_2,\mathit{addr}_4,\mathit{addr}_5,\mathit{addr}_7,\mathit{addr}_8$, $p+8$ and $p+16$ for each pointer $p$, which the circuit computes with incrementers (\S\ref{sec:exp}).

A base-field $b$ has one limb in memory, and its two high limbs are no access: the operand circuit gates $\mathit{addr}_4$ and $\mathit{addr}_5$ to $0$, and the committed column $\bpos=\mathit{base}\,\pos$, held by one more identity, moves them and every access after them: access $k$ is at $\pos\,\gen^{k}+\bpos\,\gen^{k}$ for $k=4,5$, which is $0$ for a base-field $b$, and at $\pos\,\gen^{k}+\bpos(\gen^{k-2}+\gen^{k})$ for $k\ge6$, which is $\pos\,\gen^{k-2}$ for one; the row's successor is at $\pos\,\gen^{9}+\bpos(\gen^{7}+\gen^{9})$. A high limb of a base-field $b$ thus pulls $\tup{\dsep{MEM},0,0,b_k,b_k}$, which only the absent limb $\tup{\dsep{MEM},0,0,0,0}$ of the padding tuples meets (\S\ref{sec:memchan}), so $b_1=b_2=0$, and the product is $a\cdot b_0$.

The identities say the product. $y^3+y+1$ has its coefficients in $\Ftwo$, so with $d_m=\sum_{i+j=m}a_ib_j$, a sum of products in $\K$, the reductions $y^3=y+1$ and $y^4=y^2+y$ give each new limb as a sum of products of columns:
\[
  c'_0=\mathit{acc}\,c_0+d_0+d_3,\qquad c'_1=\mathit{acc}\,c_1+d_1+d_3+d_4,\qquad c'_2=\mathit{acc}\,c_2+d_2+d_4.
\]
The table's constraints are the differences of the two sides, each of degree two with every coefficient one, and $\bpos+\mathit{base}\,\pos$; the table sumcheck proves that the four vanish on every row, a padding row's included (\S\ref{sec:air}).

The reads of $a$ and $b$ come before the rewrite of $c$, in the log. So $c$ may be $a$ or $b$.

A padding row multiplies zeros at the address $0$, at position $0$: its accesses pull padding tuples, and its identities hold.

\paragraph{Sizes.} A circuit's instance occupies $2^{\kblock}$ bits: $8$ for \texttt{LD} and \texttt{SD}, $10$ for \texttt{ALU}, \texttt{LOAD}, \texttt{STORE} and \texttt{SHIFT}, $11$ for \texttt{EXT}'s operand circuit, $12$ for \texttt{MUL}, $13$ for \texttt{MULH} and \texttt{DIV}, and $14$ for \texttt{HASH} (\S\ref{flock:classes}). Flock proves a batch of at least $2^{13}$ bits and at least eight instances, so a table has at least $2^{3}$ rows, and at least $2^{13-\kblock}$ when that is more: $2^{5}$ for \texttt{LD} and \texttt{SD}. Padding rows (\S\ref{sec:e2e-pad}) supply them.
