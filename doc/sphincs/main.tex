\title{A SPHINCS$^+$ variant}
\author{}
\date{}

\begin{abstract}

This specification defines a SPHINCS$^+$ variant with a lifetime of $2^{24}$ signatures per key pair:

\begin{itemize}
   \item \textbf{NIST security level~1}~\cite{NISTPQC}, $\approx 128$-bit (resp. $\approx 64$-bit) of classical (resp. quantum) security, in the Random Oracle model, ROM (resp. Quantum Random Oracle model, QROM).\footnote{NIST stands for National Institute of Standards and Technology. The classical bound is proved (Section~\ref{sec:security}); the quantum one is a target, not a proved statement (Section~\ref{sec:quantum}).}
  \item \textbf{Public key: 32 bytes.}
  \item \textbf{Signature: 4924 bytes.}
  \item \textbf{Verification: 497 hashes.}
  \item \textbf{Key generation: 1.38M hashes.}
  \item \textbf{Signing: approximately 190K hashes on average}, with a 1024-byte public cache.
\end{itemize}
\end{abstract}

The construction uses compressed variants of the Winternitz one-time signature (WOTS) and forest of random subsets (FORS), called WOTS$^+$C and FORS$^+$C~\cite{HK22C,KN25}. They are combined within the SPHINCS$^+$ framework~\cite{SPHINCSPLUS}. The definitions below specify the concrete variant completely.

\section{Hashing and parameters}
\label{sec:parameters}

Write $\bits r$ for $r$-bit strings, $\concat$ for concatenation, and $\LE_r(z)$ for the unsigned $r$-bit little-endian encoding of $z$. Write $x\getsr A$ for a uniform sample from $A$. Indices and bit positions start at zero; $\bot$ denotes failure.

Let $\hash:\bits{*}\to\bits{256}$ be the hash function. Most operations use its first $n=128$ output bits:
\[
  \Th(P,\tw,M)=\Truncate_n\!\left(\hash(\tw\concat P\concat M)\right).
\]
Here $P$ is a 128-bit public parameter and $\tw$ is a 128-bit \emph{tweak}: an address identifying the operation and its position in the construction. Appendix~\ref{sec:tweaks} gives every tweak's exact bytes. $\Truncate_r$ always keeps the first $r$ bits, with bits read least significant first within each byte.

The message $m$ and master secret $S$ are each 256 bits. WOTS signs 128-bit values $M$. The signature contains a 128-bit randomizer $\rho$ and one 32-bit counter $c$ per WOTS signature. Derived signing secrets, chain values and Merkle nodes are 128 bits; write $\mathcal H=\bits n$.

\midrule

$T$ & $191$ & sum of the signed chain positions\\

$(h_0,h_1,h_2)$ & $(12,7,7)$ & tree heights at those layers\\

$\cmax$ & $2^{32}$ & maximum encoding attempts per WOTS signature\\
\bottomrule
\end{tabular}

The public parameter and all signing secrets are derived from $S$. In particular,
\[
  P=\Th\!\left(0^{128},\mathsf{tw}_{\mathrm{parameter}},S\right).
\]
The component definitions below derive signing secrets as needed from this fixed $S$. Functions that read secrets use $S$ implicitly.

\section{WOTS: signing with hash chains}
\label{sec:ots}

A WOTS key is identified by a layer $\lay$, a tree $\tau$ and a leaf $e$. It contains $v=42$ chains, each with eight positions, numbered $0$ through $7$. Fix such a key. For $0\leq i<v$, derive chain $i$'s starting secret and hash forward:
\[
\begin{aligned}
  C_{i,0}&=\sk_{\lay,\tau,e,i}
    =\Th\!\left(P,\mathsf{tw}_{\mathrm{prf}}(\lay,\tau,i,e),S\right),\\
  C_{i,\mu}&=\Th\!\left(P,\mathsf{tw}_{\mathrm{chain}}(\lay,\tau,e,i,\mu),C_{i,\mu-1}\right),
    &&1\leq\mu<2^w.
\end{aligned}
\]
The endpoints $\pk_{\lay,\tau,e,i}=C_{i,7}$ form the WOTS public key. Hashing them in chain order gives one Merkle leaf:
\[
  X^{\lay,\tau}_{0,e}=\Th\!\left(P,\mathsf{tw}_{\mathrm{leaf}}(\lay,\tau,e),
    C_{0,7}\concat\cdots\concat C_{v-1,7}\right).
\]

To sign $M$, the signer encodes it as positions $x_0,\ldots,x_{v-1}$ and reveals $C_{i,x_i}$ from each chain. The verifier hashes these values forward to recover the endpoints. All valid encodings have the same sum:
\[
  \mathcal C=\left\{x\in\{0,\ldots,2^w-1\}^{v}:\sum_{i=0}^{v-1}x_i=T\right\}.
\]
Hashing forward can only increase a position. Thus one valid encoding cannot be changed into a distinct valid encoding merely by advancing along the chains.

\paragraph{Encoding a message.}
$\Enc(P,\lay,\tau,e,M,c)$ first computes
\[
  D=\Th\!\left(P,\mathsf{tw}_{\mathrm{enc}}(\lay,\tau,e),M\concat\LE_{32}(c)\right).
\]
Interpret the first and last eight bytes of $D$ as little-endian integers $d_0,d_1$. Each supplies 21 consecutive three-bit positions:
\[
  x_{21q+r}=\left\lfloor d_q/2^{3r}\right\rfloor\bmod 8,
  \qquad q\in\{0,1\},\quad 0\leq r<21.
\]
Return $x$ if bit 63 of each $d_q$ is zero and $\sum_i x_i=T$; otherwise return $\bot$. The two zero bits ensure that an accepted encoding specifies all 128 bits of $D$.

\paragraph{Signing.}
$\OtsSign(P,\lay,\tau,e,M)$ tries $c=0,\ldots,\cmax-1$ in order. At the first successful encoding $x$, it returns
\[
  (c,\sigma),\qquad \sigma_i=C_{i,x_i},\quad 0\leq i<v.
\]
It returns $\bot$ if every counter fails.

\paragraph{Recovering the leaf.}
$\OtsLeaf(P,\lay,\tau,e,M,c,\sigma)$ recomputes $x=\Enc(P,\lay,\tau,e,M,c)$ and returns $\bot$ if encoding fails. Otherwise, for each $i$, start with $C'_{i,x_i}=\sigma_i$ and apply the chain recurrence from position $x_i+1$ through $7$. Return
\[
  \Th\!\left(P,\mathsf{tw}_{\mathrm{leaf}}(\lay,\tau,e),C'_{0,7}\concat\cdots\concat C'_{v-1,7}\right).
\]

\label{rem:once}
Each WOTS key in this construction signs one fixed value: a child-tree root or a FORS public key. Choosing the least successful counter makes repeated signing of that value reveal the same positions. Revealing different positions for the same key would let an adversary combine the smaller positions from both signatures.

\section{Merkle trees: authenticating WOTS keys}
\label{sec:layer}

Tree $\tau$ at layer $\lay$ has $2^{h_\lay}$ WOTS leaves. Its parent nodes are
\[
  X^{\lay,\tau}_{\lambda,j}=\Th\!\left(P,\mathsf{tw}_{\mathrm{node}}(\lay,\tau,\lambda,j),
    X^{\lay,\tau}_{\lambda-1,2j}\concat X^{\lay,\tau}_{\lambda-1,2j+1}\right),
\]
for $1\leq\lambda\leq h_\lay$ and $0\leq j<2^{h_\lay-\lambda}$. Children are always hashed left first. Define
\[
  \TreeRoot(P,\lay,\tau)=X^{\lay,\tau}_{h_\lay,0}.
\]

An authentication path supplies the sibling of the chosen node at each height. For leaf $e$, $\TreePath(P,\lay,\tau,e)$ returns $A=(A_0,\ldots,A_{h_\lay-1})$, where
\[
  A_\lambda=X^{\lay,\tau}_{\lambda,\lfloor e/2^\lambda\rfloor\oplus1}.
\]
Here $\oplus1$ flips the low bit of the node index, selecting its sibling. Paths are ordered from leaf to root.

$\TreeFold(P,\lay,\tau,e,X,A)$ recovers the root from a leaf value $X$ and its path. Start with $V_0=X$. For $0\leq\lambda<h_\lay$, let $j=\lfloor e/2^{\lambda+1}\rfloor$ and compute
\[
  V_{\lambda+1}=\begin{cases}
    \Th\!\left(P,\mathsf{tw}_{\mathrm{node}}(\lay,\tau,\lambda+1,j),V_\lambda\concat A_\lambda\right)
      &\text{if bit $\lambda$ of $e$ is zero},\\[2pt]
    \Th\!\left(P,\mathsf{tw}_{\mathrm{node}}(\lay,\tau,\lambda+1,j),A_\lambda\concat V_\lambda\right)
      &\text{otherwise}.
  \end{cases}
\]
Return $V_{h_\lay}$. The bit selects whether the current node is the left or right child.

\section{FORS: signing digest indices}
\label{sec:fts}

A FORS instance is identified by $\idx\in\{0,\ldots,2^h-1\}$. It contains $k-1=14$ Merkle trees, each with $2^a=1024$ leaves. Tree $\kappa$ has secrets
\[
  s_{\idx,\kappa,j}=\Th\!\left(P,\mathsf{tw}_{\mathrm{ftsprf}}(\idx,\kappa,j),S\right),
  \qquad 0\leq\kappa<k-1,\quad 0\leq j<2^a.
\]
Hash each secret into a leaf, then hash pairs of children into parents:
\[
\begin{aligned}
  Y^{\idx,\kappa}_{0,j}&=\Th\!\left(P,\mathsf{tw}_{\mathrm{ftsleaf}}(\idx,\kappa,j),s_{\idx,\kappa,j}\right),\\
  Y^{\idx,\kappa}_{\lambda,j}&=\Th\!\left(P,\mathsf{tw}_{\mathrm{ftsnode}}(\idx,\kappa,\lambda,j),
    Y^{\idx,\kappa}_{\lambda-1,2j}\concat Y^{\idx,\kappa}_{\lambda-1,2j+1}\right),
\end{aligned}
\]
where $1\leq\lambda\leq a$ and $0\leq j<2^{a-\lambda}$ in the second line. The FORS public key commits to the roots in tree order:
\[
  \FtsKey(P,\idx)=\Th\!\left(P,\mathsf{tw}_{\mathrm{ftsroots}}(\idx),
    Y^{\idx,0}_{a,0}\concat\cdots\concat Y^{\idx,k-2}_{a,0}\right).
\]

\paragraph{Opening leaves.}
The digest selects indices $u=(u_0,\ldots,u_{k-1})$, each in $\{0,\ldots,2^a-1\}$. The last index must be zero and has no corresponding tree. For every $0\leq\kappa<k-1$, $\FtsOpen(P,\idx,u)$ reveals one secret and its $a$ siblings:
\[
  s_\kappa=s_{\idx,\kappa,u_\kappa},\qquad
  B_{\kappa,\lambda}=Y^{\idx,\kappa}_{\lambda,\lfloor u_\kappa/2^\lambda\rfloor\oplus1},
  \quad 0\leq\lambda<a.
\]
It returns $(s,B)$.

\paragraph{Recovering the public key.}
$\FtsRec(P,\idx,u,s,B)$ starts each tree at
\[
  W_{\kappa,0}=\Th\!\left(P,\mathsf{tw}_{\mathrm{ftsleaf}}(\idx,\kappa,u_\kappa),s_\kappa\right).
\]
At height $\lambda$, combine $W_{\kappa,\lambda}$ with $B_{\kappa,\lambda}$, putting the current value first exactly when bit $\lambda$ of $u_\kappa$ is zero. Hash this pair with $\Th$ using the tweak $\mathsf{tw}_{\mathrm{ftsnode}}(\idx,\kappa,\lambda+1,\lfloor u_\kappa/2^{\lambda+1}\rfloor)$ to obtain $W_{\kappa,\lambda+1}$. After all $a$ heights, return
\[
  \Th\!\left(P,\mathsf{tw}_{\mathrm{ftsroots}}(\idx),W_{0,a}\concat\cdots\concat W_{k-2,a}\right).
\]

A FORS instance may sign several sets of indices. Reuse reveals more leaves, so its protection decreases as openings accumulate. The randomized digest and the limit on signing requests are part of the security bound.

\section{Connecting the layers}

The \emph{hypertree} connects all $2^{26}$ FORS instances to one public root. Layer $0$ contains one height-12 tree; layer $1$ contains $2^{12}$ height-7 trees; layer $2$ contains $2^{19}$ height-7 trees. Each WOTS key in an upper layer signs one child-tree root. Each WOTS key in layer $2$ signs one FORS public key.

An index $\idx$ selects one tree and one leaf at each layer:
\[
  \tau_\lay(\idx)=\left\lfloor\idx/2^{\sum_{j\geq\lay}h_j}\right\rfloor,
  \qquad
  e_\lay(\idx)=\left\lfloor\idx/2^{\sum_{j>\lay}h_j}\right\rfloor\bmod 2^{h_\lay}.
\]
Concretely, $e_0$ is the high 12 bits of $\idx$, $e_1$ the next 7 bits, and $e_2$ the low 7 bits. Then
\[
  \tau_0=0,\qquad \tau_1=e_0,\qquad \tau_2=2^7e_0+e_1.
\]
Thus the key at $(0,0,e_0)$ signs tree $(1,\tau_1)$'s root, the key at $(1,\tau_1,e_1)$ signs tree $(2,\tau_2)$'s root, and the key at $(2,\tau_2,e_2)$ signs $\FtsKey(P,\idx)$.

\paragraph{Selecting the route and FORS leaves.}
\label{rem:rho}
For public root $\rootnode$, message $m$ and randomizer $\rho$, define
\[
  \Digest(P,\rootnode,m,\rho)=\Truncate_{h+ka}\!\left(
    \hash(\mathsf{tw}_{\mathrm{msg}}\concat P\concat\rho\concat\rootnode\concat m)\right).
\]
Interpret these $h+ka=176$ bits as a little-endian integer $N$ and extract
\[
  \idx=N\bmod2^h,\qquad
  u_\kappa=\left\lfloor N/2^{h+\kappa a}\right\rfloor\bmod2^a,
  \quad 0\leq\kappa<k.
\]
The digest is \emph{admissible} when $u_{k-1}=0$. The signer searches by sampling $\rho$. For a uniform digest, requiring this last index to be zero leaves all other indices uniform, since they use disjoint bits.

\section{The complete signature scheme}

\subsection{Key generation}
\label{rem:seed}

$\Gen$ samples $S\getsr\bits{256}$, derives $P$ as in Section~\ref{sec:parameters}, and computes $\rootnode=\TreeRoot(P,0,0)$. It returns
\[
  \pk=(\rootnode,P),\qquad \sk=(P,\rootnode,S).
\]
Only the top tree is built at key generation. Lower trees are computed as signing needs them.

\subsection{Signing}
\label{sec:sign}

Given $\sk=(P,\rootnode,S)$ and a 256-bit message $m$, $\Sig(\sk,m)$ proceeds as follows:
\begin{enumerate}
\item Sample independent $\rho\getsr\bits{128}$ until $\Digest(P,\rootnode,m,\rho)$ is admissible. Stop after at most $\amax$ attempts, returning $\bot$ if none succeeds. Extract $\idx$ and $u$ from the successful digest.
\item Compute $(s,B)=\FtsOpen(P,\idx,u)$ and $M_{d-1}=\FtsKey(P,\idx)$.
\item For $\lay=d-1,d-2,\ldots,0$, set $\tau=\tau_\lay(\idx)$ and $e=e_\lay(\idx)$. Compute $(c_\lay,\sigma_\lay)=\OtsSign(P,\lay,\tau,e,M_\lay)$, returning $\bot$ immediately on failure. Then compute
\[
  A_\lay=\TreePath(P,\lay,\tau,e),\qquad
  M_{\lay-1}=\TreeRoot(P,\lay,\tau).
\]
\item Return
\[
  \sigma=\left(\rho,(s_\kappa,B_\kappa)_{\kappa<k-1},
    (c_\lay,\sigma_\lay,A_\lay)_{\lay<d}\right).
\]
\end{enumerate}
The final value $M_{-1}=\rootnode$ is computed and discarded. Signing changes no secret state. Repeated messages are allowed, with fresh randomness for each request.

\subsection{Verification}
\label{sec:ver}

$\Ver(\pk,m,\sigma)$ rejects $\bot$ and malformed inputs. Otherwise, parse $\pk=(\rootnode,P)$ and $\sigma$ as above:
\begin{enumerate}
\item Compute $\Digest(P,\rootnode,m,\rho)$ and extract $\idx,u$. Reject unless $u_{k-1}=0$.
\item Set $M_{d-1}=\FtsRec(P,\idx,u,s,B)$.
\item For $\lay=d-1,d-2,\ldots,0$, set $\tau=\tau_\lay(\idx)$ and $e=e_\lay(\idx)$. Compute
\[
  X=\OtsLeaf(P,\lay,\tau,e,M_\lay,c_\lay,\sigma_\lay).
\]
Reject if $X=\bot$. Otherwise set $M_{\lay-1}=\TreeFold(P,\lay,\tau,e,X,A_\lay)$.
\item Accept exactly when $M_{-1}=\rootnode$.
\end{enumerate}
For an honestly generated signature, each WOTS recovery yields its original leaf and each authentication path yields its original root. Induction through the three layers therefore gives acceptance whenever signing succeeds.

\subsection{Serialization and cost}
\label{sec:costs}

Serialize the public key as $\rootnode\concat P$, 32 bytes. Store the secret key as $P\concat S$, 48 bytes; its root is recomputed from them.

A signature starts with $\rho$, followed by FORS openings in increasing $\kappa$, then WOTS signatures and their paths in increasing $\lay$. Each FORS opening contains $s_\kappa$ followed by its siblings in increasing height. Each layer contains $\LE_{32}(c_\lay)$, its $v$ chain values in increasing chain index, then its path in increasing height. The size is
\[
  \underbrace{16}_{\rho}
  +\underbrace{(k-1)(1+a)\,16}_{\text{FORS openings}}
  +\underbrace{d(4+v\,16)}_{\text{WOTS signatures}}
  +\underbrace{h\,16}_{\text{layer paths}}
  =4924\text{ bytes}.
\]

Count one call to $\hash$ regardless of input length. A valid signature takes exactly
\[
  \underbrace{1}_{\text{digest}}
  +\underbrace{(k-1)(a+1)+1}_{\text{FORS}}
  +\underbrace{d\bigl((2^w-1)v-T+2\bigr)}_{\text{WOTS}}
  +\underbrace{h}_{\text{paths}}
  =497
\]
hash calls to verify. A WOTS leaf takes $v+v(2^w-1)+1=337$ calls to derive and build. Key generation therefore takes $1+2^{12}\cdot337+(2^{12}-1)=1{,}384{,}448$ calls, including derivation of $P$.

\section{Security}
\label{sec:security}

Model $\hash$ as one shared random oracle: a new input receives an independent uniform 256-bit answer, and every repetition receives that same answer. Key generation, signing, verification and the adversary all use this oracle.

The challenger generates a key pair and gives $\pk$ to a classical probabilistic adversary. The adversary may adaptively query the hash on any byte string and request signatures on messages of its choice. It may make at most $\qs=2^{24}$ signing requests, counting repeated messages and failed requests. It finally returns $(m^*,\sigma^*)$ and wins exactly when
\[
  \Ver(\pk,m^*,\sigma^*)=1
  \quad\text{and no signing request for $m^*$ returned $\sigma^*$.}
\]
This is \emph{strong unforgeability}: even a new signature on a previously signed message counts as a forgery.

A query budget $q$ bounds every execution of the complete experiment, including key generation, signing, adversarial hashing and final verification. Each hash call counts, including repeated inputs. Uniform sampling is not a hash call. There is no separate time or memory bound on the adversary.

\begin{theorem}[Classical security]
For every integer $q\geq1$ and every adversary satisfying these limits,
\[
  \Pr[\text{the adversary wins}]\leq q/2^{127}.
\]
\end{theorem}

The Lean 4 proof using VCVio~\cite{VCVio} is in \texttt{formal/sphincs/}. Its complete statement, including seed derivation and the experiment above, is in \texttt{SphincsSecurity/Statement.lean}; the theorem is in \texttt{SphincsSecurity.lean}. It depends only on Lean's three standard axioms.

\paragraph{Quantum security.}
\label{sec:quantum}
Approximately 64 bits of security in the quantum random-oracle model is a target. No quantum security bound is proved here.

\section{Tweak encoding}
\label{sec:tweaks}

Set $\mathsf{protocol\_domain\_sep}=1$. For one-byte fields $t,\lay$ and unsigned 32-bit fields $\tau,p,j$, define
\[
\begin{aligned}
  \mathsf{enc}(t,\lay,\tau,p,j)={}&
    \LE_8(\mathsf{protocol\_domain\_sep})\concat\LE_8(t)\concat\LE_8(\lay)\concat\LE_8(0)\\
  &{}\concat\LE_{32}(p)\concat\LE_{32}(\tau)\concat\LE_{32}(j).
\end{aligned}
\]
The following table specifies all 16-byte tweaks. For WOTS and hypertree operations, $(\lay,\tau,e)$ names a key. For FORS operations, $(\idx,\kappa)$ names a tree. Node indices $j$ run from left to right at height $\lambda$, with leaves at height zero.

\begin{center}
\begin{tabular}{@{}ll@{}}
\toprule
Tweak & Encoding\\
\midrule
$\mathsf{tw}_{\mathrm{prf}}(\lay,\tau,i,e)$ & $\mathsf{enc}(0,\lay,\tau,i,e)$\\
$\mathsf{tw}_{\mathrm{chain}}(\lay,\tau,e,i,\mu)$ & $\mathsf{enc}(1,\lay,\tau,2^wi+\mu-1,e)$\\
$\mathsf{tw}_{\mathrm{leaf}}(\lay,\tau,e)$ & $\mathsf{enc}(2,\lay,\tau,0,e)$\\
$\mathsf{tw}_{\mathrm{node}}(\lay,\tau,\lambda,j)$ & $\mathsf{enc}(3,\lay,\tau,\lambda,j)$\\
$\mathsf{tw}_{\mathrm{enc}}(\lay,\tau,e)$ & $\mathsf{enc}(4,\lay,\tau,0,e)$\\
$\mathsf{tw}_{\mathrm{ftsprf}}(\idx,\kappa,j)$ & $\mathsf{enc}(5,\kappa,\idx,0,j)$\\
$\mathsf{tw}_{\mathrm{ftsleaf}}(\idx,\kappa,j)$ & $\mathsf{enc}(6,\kappa,\idx,0,j)$\\
