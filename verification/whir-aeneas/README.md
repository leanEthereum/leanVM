# Actual Rust WHIR extraction

These artifacts are source extraction work, not a completed Rust-to-Lean verifier-equivalence proof. They do not establish a security level, knowledge soundness, unique binding, or universal equivalence between Rust acceptance and the proof model.

## Pins and reproduction

The source worktree currently records the normal merge `ac08c3b36b1751116d520be5c2a24f43c8199ed2`, combining the semantics-preserving source cutover `8f833054` with the protocol branch at `983e003d51bd8f03af2f1ab226f19298d012d722`. This includes the merged BLAKE2s duplex transcript. The handwritten proof-model dependency is proof PR 551 at `929791a799b7cb2db22591a260c815869469c9dc`, with Lean 4.34.0 and mathlib `5ed2965256430c3649e86755f9576b54eca72435`. This model dependency is not yet the final anchored, post-PCS-overhaul source pin.

The extraction release is Aeneas `nightly-2026.10.09-d119a47`, commit `d119a474f852781f8ae88a85424f2f8ba8407b82`, and Charon `798016509139eb51f0d764645f76d068d34ba5f6`, using Rust nightly 2026-09-17. Its original backend targets Lean 4.31.0. The recorded backend portability patches now check the backend, generated public arithmetic-dictionary code, and standard-library content lemmas in the same Lean 4.34.0 environment as the actual handwritten model. `toolchain/backend-provenance.json` records each patch hash and the scope of this check. The scripts verify release and executable checksums.

Run `./verification/whir-aeneas/extract.sh statement` from the repository to regenerate `llbc/pcs.llbc` and `WhirAeneas/Generated/Pcs.lean` from the actual release-mode `pcs::stack_open::check_statement`. There is no manually maintained duplicate Rust verifier. The extraction preserves the deployed range-only guard, release-mode wrapping arithmetic, rejection order, and error indices. It does not adopt the unmerged stronger shape validator. In particular, passing these guards does not imply the model's point alignment or strided-slot shape predicates.

Run `bootstrap.sh build` in this directory to install the checksum-pinned backend, apply the recorded semantic and Lean 4.34 portability patches, obtain the root package's declared Mathlib cache, and build the backend. Heavy compiler and extraction commands are memory-capped and serialized through `/tmp/leanvm-heavy.lock`. The shift patch accepts the full unsigned or signed right operand emitted by release MIR, without narrowing to `U32`, and proves the masked-shift and signed-modulo identities. The iterator alias patch makes the definitionally equal canonical owned-vector iterator type usable by ordinary rewriting. The string-literal patch replaces the backend's `decide +native` default proof with a kernel-checked proof; its before audit exposes `_native.decide.ax_1`, while its after audit lists only the standard three axioms. Neither the portability nor these backend patches change Rust source semantics.

After installing the pinned tools with `bootstrap.sh` and `bootstrap-tool.sh`, run `bash toolchain/check-generator.sh` from this directory. It extracts fresh Charon IR for both minimized Rust reproducers, checks the patched generator's unedited output in Lean 4.34, and exercises the fail-loudly guard on referenced methodless metadata.

## Unresolved formal boundaries

The earlier public anchored `pcs::whir::verify::verify_with_basis` extraction in `WhirAeneas/Generated/Verifier` now checks under Lean 4.34, including its actual opening-record check and terminal anchor weight. Its transitive axiom audit lists only `propext`, `Classical.choice`, and `Quot.sound`. This is a checked generated function, not a theorem equating full Rust verifier behavior with the handwritten model, and it is not an extraction of the subsequent PCS overhaul. The standard-library operations have nonopaque definitions in `WhirAeneas/Std/Bulk.lean` and `WhirAeneas/Std/Guards.lean`: rotation, truncation, owned-vector extension, option equality, and slice first-element access. The recorded parent-trait generator patch resolves the duplicated `Copy` parent fields without editing generated code or the source trait. Its minimal Rust reproducer is `toolchain/tests/copy_parents.rs`. Generated template declarations are not accepted as correctness axioms.

The connected concrete native verifier is not yet fully translated. The recorded, guarded generator repair now translates the minimized monomorphized word-byte roundtrip and executes its generated definition under Lean 4.34. It skips only unused, methodless impl metadata when Charon omitted the corresponding trait declaration, and rejects a parsed fixture that references that metadata anywhere in the translated crate. The generic verifier's remaining loop-context and type-variable translation failures are not repaired by this metadata fix. Parallel and thread-local dependencies were removed from the PCS arithmetic dictionary by splitting public-column evaluation into a separate capability. No opaque substitute for a remaining verifier code path is provided, and the PCS overhaul requires a fresh coherent source extraction.

The checked standard-library lemmas are `WhirAeneas.StdBulk.collect_owned`, `extend_owned`, `rotate_zero`, `rotate_at_length`, `rotate_out_of_bounds`, `truncate_content`, and `truncate_beyond_length`. Their transitive axiom audits contain only `propext`, `Classical.choice`, and `Quot.sound`. Extracted Lean execution and the pinned Rust standard library agree on empty, zero, interior, full-length, and out-of-range rotations; truncation inside and beyond the vector length; and canonical owned-vector extension. The Rust smoke also observes panic before rotation mutation and unchanged capacity after truncation. These are logical-content lemmas and finite executions, not a verified allocator or pointer-level standard-library implementation. The extension theorem requires representable combined length and corresponds only to the canonical owned-vector dictionary used by the generated callsite; generic iterator `size_hint` side effects and unwind partial-state behavior are not covered. The arithmetic element clause carries Rust `Copy`, so truncation does not invoke element destructors in the verifier's actual instantiation. Allocation success, byte-size representability, erased capacity, allocator state, and OOM behavior remain explicit runtime boundaries.

The generated statement checker has compiled and executed under the original supported backend. It accepts the ordinary, unaligned, and high-strided-slot cases accepted by the source range guards, and reproduces point, ring, and missing-ring errors in their original order. Its axiom audit contains only `propext`, `Classical.choice`, and `Quot.sound`. The universal shift lemmas `Aeneas.Std.WrappingShiftRhs.amount_unsigned_lhs_mask`, `amount_signed_lhs_mask`, `signed_amount_unsigned_lhs`, and `signed_amount_signed_lhs` have the same audited axiom set under Lean 4.34; executed high unsigned and negative signed shift cases agree with the pinned Rust release semantics. Actual native and Rows opening verification, plus recursive honest proving/verification and non-Boolean Merkle-selector rejection, passed after the source cutovers. The native and recursive serialized proof comparisons were byte-identical before and after those cutovers. Actual compiled operations imported from the pinned handwritten `Whir.FieldTower` also execute under Lean 4.34 through the canonical ring superclass dictionaries, without executable finite-field enumeration. No extracted full-verifier honest/tampered execution, acceptance/rejection correspondence theorem, security level, or universal ISA refinement is claimed yet.
