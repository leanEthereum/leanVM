# Actual Rust WHIR extraction

This directory relates the actual Rust WHIR verifier to the proof model of proof PR 551 through an Aeneas translation of the unchanged-behavior source. The result is a conditional refinement under the premises listed below. By itself it does not establish a security level, knowledge soundness or unique binding; those are properties of the model, and they transfer only through these premises.

## Summary

### Final theorems

- `WhirAeneas.Native.verify_refines_native` (`WhirAeneas/NativeCompose.lean`). When the generated `pcs::whir::verify::verify`, instantiated with the generated native opening verifier `NativeReads.nativeInst` (`impl OpeningVerifier for VerifierState` over the BLAKE2s duplex, with `open_rows_native`), returns `Ok`, the model's `Protocol.verify` accepts the script's challenges and opening, with each level's committed table in place of its presence marker, against the first committed table and the caller's weight `b`.
- `WhirAeneas.Native.verify_eq_native` (same file). The generated `verify` on `nativeInst` returns `Ok` exactly when the model's `WHIRNativeArithmetic.nativeVerify` accepts. `verify_refines_native` is this theorem followed by the model's `nativeVerify_refines`, with its shape premises proved: `root_shape` (the first table), `root_shapes` (`RootShapes` of the committed tables) and the configuration and lane parts of `shapeValid` (from `nativeVerify`'s own guard, `nativeVerify_lanes`).
- `WhirAeneas.Native.authenticated_native`: under injective leaf and pair hashes, the opened rows are the committed tables' rows at the queries (`AuthenticatedRows`), the hints read off the same proof (`level_hints`).
- `WhirAeneas.Statement.check_eq`, `check_accept_iff`, `check_accept_model`: the generated `Statement::check` is exactly the model-side statement shape check.

Every theorem is kernel-checked without `sorry`, `admit` or `native_decide`. `Audit.lean` (446 theorems), `StatementAudit.lean` (227), `MerkleAudit.lean` (346), `ReplayAudit.lean` (1231) and `NativeAudit.lean` (2010) fail the build on any axiom beyond `propext`, `Classical.choice` and `Quot.sound`.

### Remaining premises of `verify_refines_native`

- `System.Platform.numBits = 64`: the source's `usize` arithmetic is proved for 64-bit targets only.
- `ArithModel`, `RowModel` and `NormalizerModel`: the native `F64`/`F192` arithmetic dictionary, the row element reads and the subspace normalizers of `NovelBasis::new` compute the model's field operations. The native field multiplication is not yet related to the model; this waits for PR 606's portable arithmetic (see "Discharging ArithModel with portable arithmetic").
- `Duplex out R`, `PowHash H`, `RowHash leaf`, `PairHash node`: content contracts of the BLAKE2s duplex mode, the proof-of-work trial hash and the Merkle leaf and pair hashes. These stay opaque because the compression runs in x86 assembly and batched kernels that are not extracted.
- `Function.Injective encode`: the interpretation of `F192` as the model's extension element. `EnsureModel` follows from it (`ensure_native`); `limbs_injective` proves it for the limb interpretation `limbs`. It stays a premise only because `encode` is the same free parameter as in `ArithModel`.
- Injective leaf and pair hashes (`hleaf`, `hnode`): collision resistance stated as injectivity, which binds opened rows to the committed trees.
- `CallerModel W weight_at encode callerAt`, `hcaller`, `hb` and `hz`: the weight evaluator is a parameter of `verify`. Reading it as the multilinear extension of a weight `b` with `2 ^ logN` entries, zero past the lanes, is the caller's contract. The model's `sourceNativeVerify_refines` has the same weight-shape premise.
- `ConfigRel`: the source configuration denotes the model's, within the bounds the source guards enforce: grinding at most 32 bits, `log_n < 64` and level folds below 62. It also requires no lane padding (`padding = 0`): the model has no zero-knowledge padding, so the theorems cover the configurations in which `verify` does not take its hiding branch (see "The hiding branch" below).
- `Challenges.valid`, `ScriptShape`, `GrindShape` and `hroot`: the script (the answers a proof gives, in read order) has the configuration's shape and starts at the given root. They describe the input, not the verifier.
- `NativeAnswers out R H leaf node v (s.tape ++ rest)`: the state's proof bytes and duplex answer the script. This premise fixes which script a proof denotes.
- Committed trees `T j` over rows `C j` (`hT0`, `hT`, `hroots`), and the width bound `hC`: every committed row has its level's row width. Together they state what the prover committed to. `RootShapes` and the first table's shape follow from them.

The element clone being the identity (`clone_native`) and `EnsureModel` (`ensure_native`) are no longer premises.

## Current hash boundary

The current source includes upstream PR 555's x86-64 compression assembly and batched Merkle hashing. These kernels are not replaced with a slower portable implementation for extraction. The compression interface is `WhirAeneas.Hash.SatisfiesRfc7693`, defined using the actual `LeanVMCircuits.Blake2s.Rfc7693.F` imported from the circuits project at `404c8fd0928ea6abea1facd220b91ee7464bd810`. That dependency and the generated portable compression both check in the same Lean 4.34 environment as the WHIR model.

`extract.sh portable` extracts the actual `primitives::hash::compress_portable` without editing its generated Lean. Execution agrees with the shared RFC definition and the native compression on both final flags and counter boundaries. These finite observations are not the universal portable-compression theorem, which remains to be proved.

The conditional native extraction separates compression and batched hash entry points from the supported verifier body. The required batch contract is content-level RFC hashing with exact output length and input order, including the zero prefix of padded leaf images. It must not assume Merkle authentication or verifier soundness. The x86 assembly, Lanes32 memory operations, and SIMD/batch backends remain tested-only boundaries until separate proofs discharge their contracts. Neither the generated function nor a conditional correspondence theorem would verify allocator, OOM, uninitialized-buffer implementation, or ABI frame behavior. This is not an unconditional Rust-to-Lean equivalence claim.

The private, single-caller `#[inline]` helper `fiat_shamir::merkle::hash_packed_leaves` belongs to the same hash boundary as `hash_pairs` and `hash_many`. Given a valid descriptor from `LeafHasher::new`, exactly `n` packed rows and successful allocation, it must return exactly `n` digests in row order. Digest `i` is the shared RFC BLAKE2s hash of the complete leaf image: the descriptor's zero prefix followed by packed row `i`. Deduplication, row count and width checks, the `row_words <= leaf_words` guard, `LeafHasher::new`, byte packing and all authentication decisions remain outside this helper and must be translated and related separately. The helper preserves the existing uninitialized allocation, fill and ownership conversion pattern; this content contract does not verify those memory operations.

On the current source based on `aeb0a3307f8c2ddef44cb69c636a81b18a98f324`, actual release-profile native and Rows opening execution accepts honest proofs and rejects the fixture's tampered proofs. The validator checks the exact inherent receiver type, retained root body, extraction errors and missing function references. The coordinate map into the model is arbitrary: this is a metadata correspondence, not a field refinement.

The occupied-prefix restriction concerns the enclosing dyadic block, not just selected strided positions. For `n = 14`, `committed = 15360`, offset and slot zero, stride exponent 14 and an empty point, the model accepts but Rust rejects. The only selected position is occupied position zero; the enclosing block reaches the unoccupied tail. Both actual executions confirm this difference. Exact equality with the model is a full-cube corollary, while the soundness-relevant implication is Rust acceptance to model shape under `committed ≤ 2^n` and the word-width layout premises. Successful source-prover openings check the same occupied-block restriction before emitting a proof. This guard slice runs before opening-record binding and does not yet cover the complete anchored verifier.

## Current replay, fold and query terms

`extract.sh replay` extracts the actual generic `pcs::whir::verify::verify` (the opening's WHIR replay, generic over `OpeningVerifier`), `pcs::whir::query::sample_queries` and `pcs::ring_switch::RingMap::close` with `primitives` included, into `WhirAeneas/Generated/Replay`; the root validator checks each retained body, including `Stratum::batch`, `RoundQuad::read`, `Verifier::read_round`, `RoundWeight::fixed_index`, `Openings::rows`, `NovelBasis::new` and `Padding::share`. It replaces the earlier fold surface. The standard-library operations it reaches have nonopaque definitions in `WhirAeneas/Std/Replay.lean` (`usize::trailing_zeros`, `usize::div_ceil`, `usize::next_power_of_two` with the release wrap to zero, `Option::as_ref`, `Option::map_or`) and `WhirAeneas/Std/Bulk.lean` (`rotate_left`). The generated `verify` and everything it reaches audit with only `propext`, `Classical.choice` and `Quot.sound`. Two behavior-preserving source commits made this translate: explicit index loops instead of iterator adaptors in the enforced sums, extension-row conversion, base-row reversal, strata, query sampling and normalizers, with the arithmetic-only column loop generic over `Arith` and the new helpers naming their element types (`660f5903`); and the grinding-bits conversion panics with the literal text `expect` printed, so no formatter type is reached (`726f5290`). Native and recursive proof outputs are byte-identical to the parent at each, the pcs library tests and pcs clippy pass, and the paired `scripts/ab.sh` run of `660f5903` flagged nothing in PCS or leanXMSS.

Upstream's module layout and API cleanups (#633 and #634, reached through PR 600 at `c5acc61f5`) moved the round read into `pcs::whir::sumcheck::RoundQuad::read`, which calls the `Verifier::read_round` trait method; its default reads the transmitted coefficients with `prover_messages`, inserts the claim at `RoundWeight::fixed_index` and sums the tail in an index loop. Query sampling moved into `pcs::whir::query` (`sample_queries` takes the depth, `Stratum::batch` builds the strata), the subspace normalizers became `ntt::basis::NovelBasis`, and `WhirReplay::run` is gone: `verify` holds the level-0 replay inline, including the lane fold's last round and the hiding branch. `sample_queries` draws `verifier_message::<F192>()` from a `Challenger` generic over `FromUniform`; the `F192` decoding is now the generated `F192::from_le_bytes` (three little-endian limbs through `as_chunks`, modelled in `WhirAeneas/Std/Native.lean`), so `FunsExternal.lean` no longer defines it.
