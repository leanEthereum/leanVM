# Clean-authored production circuits

The 64-bit wrapping adder in `crates/flock/src/clean.rs` is generated from the Clean circuit `LeanVMCircuits.WrappingAdder.adder64`. `Ld::circuit` in `crates/leanvm_core/src/rv/semantics/memory.rs` calls this generated function, and `Sd` shares the `Ld` circuit. The complete `Load` and `Store` circuits also compose this Clean source before export, as described below. The Flock reduction regression uses the same production adder function, not another handwritten adder.

The same source also generates the 32-bit wrapping adder used by the production BLAKE2s circuit and the 64-bit carry-in/carry-out adder used by ALU, signed multiplication corrections, and division constraints. Division's conditional negation composes affine bit flipping with the exported carry adder. The former handwritten ripple-adder methods are removed. All optimized Rust word and packed witness kernels remain unchanged.

The complete RV shift circuit is authored in `LeanVMCircuits.Shift` and exported as `flock::clean::shift64`. The actual `Shift::circuit` in `crates/leanvm_core/src/rv/semantics/shift.rs` consumes it. This includes amount masking, word-operand extension, arithmetic fill, reversal for left shifts, all six barrel stages, and final word-result sign extension. The former handwritten shift gate construction and its unused reversal gadget are removed; the optimized native shift witness is unchanged.

These are Boolean circuits over `F2 = ZMod 2`, not Clean's prime-field `Addition32` gadget. Input and output vectors are little-endian bits; each element of `F2` is necessarily zero or one. Wrapping sums are modulo `2^64` or `2^32`, with 63 or 31 products in least-significant-bit order and no discarded-overflow product. The carry adder uses 64 ordered products and returns a 64-bit sum and one carry bit.

The `Clean circuits` workflow performs the proof build, axiom audit, serialized theorem kernel recheck, and deterministic regeneration check. The generator rejects unbound, forward, or duplicate product variables. The lowering accepts only affine GF(2) expressions and scalar witnesses immediately constrained to their defining products. Other witnesses, assertions, nested products in affine operands, lookups, interactions, and excessive subcircuit nesting return explicit errors rather than being ignored.

Kernel rechecks invoke stock `leanchecker` sequentially for every library source module, including intermediate modules. Its prefix command on the whole library starts concurrent replays, each with an imported environment. The workflow derives the complete module list from the source tree, fails on a missing compiled module, and separately enforces that the root contains only its module header and public imports, so it has no declarations left unchecked. Serialization bounds peak memory without introducing a custom checker or dropping proofs.

## What is proved

`FullAdder.soundness` proves the integer identity `sum + 2 * carry_out = x + y + carry_in` from the defining Boolean product constraint. Its completeness theorem checks the Clean witness generator. `Adder.circuit` composes those circuits with a proof of the full word identity. `WrappingAdder.circuit` removes the unused high carry product and proves the modular sum.

`Flock.lowerAffine_correct` and `Flock.lower_correct` prove evaluation and constraint equivalence for every assignment. `Flock.flatten_correct` proves that successful bounded flattening returns exactly Clean's flat operations; the bound is an explicit export error, not a silently truncated circuit. `Flock.adder64_source` identifies the exact checked artifact with lowering of the actual Clean source. `Flock.adder64_layout` checks 63 ordered product variables starting at 128 and 64 outputs. `Flock.adder64_soundness` proves that every assignment satisfying that artifact's product constraints has the correct modular output. It does not assume that an assignment was generated honestly.

`Flock.witness_exists` constructs satisfying assignments for acyclic product rows. `Flock.adder64_wellFormed` checks the concrete artifact's dependency order, and `Flock.adder64_complete` proves that every assignment of the 128 input bits extends to a satisfying assignment. Completeness therefore does not stop at an unfulfilled witness-generation premise.

`Flock.adder32_source`, `adder32_layout`, `adder32_soundness`, `adder32_wellFormed`, and `adder32_complete` establish the corresponding exact-artifact claims for the 32-bit wrapping adder. Its product variables are 64 through 94, after 64 input bits. `Flock.carryAdder64_source`, `carryAdder64_layout`, `carryAdder64_soundness`, `carryAdder64_wellFormed`, and `carryAdder64_complete` establish them for the carry adder. Its input variables 0 through 127 name the operand bits, input 128 names the carry-in, and product variables 129 through 192 name 64 ordered products. The 65 output bits represent the exact integer `x + y + carry_in`, so the theorem covers both the low sum and final carry. Each completeness theorem extends every input assignment to a satisfying assignment.

`Shift.assumptions_iff_legal_flags` identifies the semantic domain exactly with flag words `0, 1, 3, 4, 5, 7`: arithmetic shifts must shift right. The flags are Boolean because the source field is GF(2). The source specification uses direct indexed left or right shifts, zero or sign-bit fill, a six-bit or five-bit amount from `v2 XOR imm`, and final 32-bit sign extension. `Flock.Shift.source_eq` identifies the artifact with lowering of this actual source. `Flock.Shift.layout` checks its 579 products at source variables 195 through 773 and its 64 outputs. `Flock.Shift.soundness` proves the specified output for every satisfying assignment in that exact flag domain, not just honestly generated witnesses. `Flock.Shift.wellFormed` and `Flock.Shift.complete` prove that every assignment of the 195 input bits extends to a satisfying assignment. The circuit does not itself enforce flag legality; the semantic theorem exposes this instruction-class domain rather than assuming a security conclusion.

Artifact support, layout, and well-formedness are checked by `decide +kernel`, not `native_decide`. `Audit.lean` prints the transitive theorem axiom closures and fails on any axiom outside `propext`, `Classical.choice`, and `Quot.sound`. No admitted theorem or native-decision axiom is used; mathematical domain and interface assumptions remain explicit.

## Rust interpretation and remaining trust

The generator consumes the checked `Flock.adder64`, `Flock.adder32`, `Flock.carryAdder64`, `Flock.Shift.artifact`, `Flock.Load.artifact`, `Flock.Store.artifact`, `Flock.Alu.artifact`, the five `Flock.Clock.*.artifact` and `Flock.ExtClock.artifact` artifacts directly. Input variables name the function's operand bits and, for the carry variant, its `carry_in` argument. Shift inputs name `v1`, `v2`, and `imm` bits followed by the right, arithmetic, and word flags. Each later variable names the result of its ordered product. An affine zero or one becomes `Wire::ZERO` or `Wire::ONE`, affine addition becomes `Builder::xor`, and each row becomes `Builder::and` or a designated public `Builder::and_output`. Artifact outputs become the returned sum, carry, shifted word, memory bus and value wires, ALU value and jump, the clock's `live` and `fail`, or the Ext clock's flag bits and addresses. Generated common-subexpression reuse changes XOR gate ordering, not affine meaning or the order of products.

`Builder` places ports before its constant pin and product slots. For the `Ld`/`Sd` shape, input bits occupy 0 through 127, output bits occupy 128 through 191, the constant pin is 192, and the 63 product slots occupy 193 through 255. The source's product variable 128 plus its ordinal maps to the corresponding Builder product, not to output slot 128 plus that ordinal. Builder output rows tie the committed output ports to the returned affine expressions. Structural zeros and unused port bits retain Builder's existing forced-zero interpretation.

For the shift shape, Rust's four padded input words occupy slots 0 through 255, the output occupies 256 through 319, the constant pin is 320, and the 579 products occupy 321 through 899. Source variables 0 through 191 map to the three full operand words; source variables 192 through 194 map to the three live flag bits. Source product variable 195 plus its ordinal maps to Rust product slot 321 plus that ordinal, not to a flag or output slot. The other 61 flag-port bits and instance padding retain Builder's existing forced-zero interpretation.

The proven export boundary is the concrete Lean artifact and its GF(2) semantics. Lean's runtime execution, the Rust pretty-printer and formatter, the Rust compiler, and Builder's implementation of XOR, AND, constant pinning, output rows, and slot packing remain trusted parts of the Rust interpretation. Deterministic regeneration checks linkage and drift; it is not presented as a proof of these implementations. The existing packed native `address_rows` witness kernel is unchanged. Its correspondence to the generated circuit is exercised by the production memory witness regression and complete RV proof verification, but the Rust native word-arithmetic implementation itself is not formally verified here.

The RV regression `clean_adder_memory_addresses_wrap_and_carry` proves and verifies real `Ld`/`Sd` accesses through both a negative-immediate overflow and a long carry boundary, then rejects an altered output statement. The Flock reduction regression verifies honest batches and rejects mutations of input, output, constant, and product bits. This establishes exercised integration, not a cryptographic security proof of Flock, the PCS, Fiat-Shamir, or the whole VM. Other instruction circuits and protocol constraints are outside these circuit-family proofs.

`clean_carry_adder_arithmetic_boundaries` proves and verifies actual ALU overflow and unsigned comparison, signed division overflow, and signed high multiplication, then rejects an altered output statement. The adder theorems alone do not prove division or multiplication; the complete ALU, multiplication and division, and BLAKE2s compression have their own proofs, below.

`clean_shift_sign_and_mask_boundaries_prove_and_verify` exercises real RV shifts at signed and word boundaries and rejects an altered output statement. `clean_shift_proves_native_witnesses_and_rejects_false_outputs_and_products` uses the unchanged optimized witness in actual Flock proof verification, then rejects mutations of an output, the first and last products, and an unused flag-port bit. The existing shift regressions cover every legal flag word and all shift amounts against the production gate walk and reference semantics. These checks exercise the Rust interpretation and native witness; their implementations are not thereby formally verified.

## ALU, comparisons and control flow

The actual `Alu::circuit` in `crates/leanvm_core/src/rv/semantics/alu.rs` consumes `flock::clean::alu64`, generated from `LeanVMCircuits.Alu.circuit`. The Clean source composes carry arithmetic, equality, word-result extension, bitwise AND/OR/XOR, signed and unsigned comparisons, indirect-link selection, six branch conditions and the committed jump products. The handwritten ALU gate builder and its unused word-scaling helper are removed; the optimized native arithmetic and packed witness kernel are unchanged.

`Alu.spec_raw` and `Flock.Alu.soundness` prove the full raw Boolean semantics for every satisfying assignment, without restricting flag words to honest decoder output. `Alu.afterArithmetic_reference` and `Flock.Alu.soundness_reference` identify the architectural reference for exactly the legal flag words `0, 1, 2, 3, 5, 9, 16, 32, 64, 16512, 257, 513, 1025, 2049, 4097, 8193, 16384`. This covers wrapping ADD/SUB, ADDW/SUBW sign extension, signed/unsigned set-less-than, logic, both polarities of every branch condition, JAL and JALR's link and cleared low target bit. The supplied `dt` and `pc4` words remain explicit inputs; these local theorems do not independently prove decoding, immediate preparation or the global next-PC bus binding.

`Flock.Alu.source_eq` links the exact artifact to lowering of the real Clean source. `layout` checks 551 ordered products and 128 outputs. `output_products_layout` identifies the last 64 product variables, 822 through 885, with the jump port bits. `wellFormed` and `complete` prove that every assignment to all 335 source input bits extends to a satisfying assignment, including flag words outside the architectural domain.

Rust's six input words occupy slots 0 through 383, output words occupy 384 through 511, and the constant occupies 512. The first 487 products occupy private slots 513 through 999; the last 64 products are written directly at public jump slots 448 through 511 by `Builder::and_output`, without allocating duplicate private products or copying the jump. Compact source input variables map to full operand words, the 15 live flag bits, and `dt`/`pc4`; unused flag bits and padding retain Builder's forced-zero interpretation.

The permanent Flock regression `flock_proves_honest_alu_instances_and_refuses_a_flipped_bit` uses the unchanged native witness for all 17 legal flag words and rejects altered value, jump, final private product, unused flag and padding bits. A release smoke exercised overflow/carry boundaries, word sign extension, signed and unsigned comparisons, bitwise instructions and immediate forms, every branch polarity, JAL and odd-target JALR, then verified an encoded/decoded real VM proof and rejected an altered public output. This exercises the Rust interpretation and native witness, not a formal verification of their implementations.

## Loads and stores

The actual `Load::circuit` and `Store::circuit` in `crates/leanvm_core/src/rv/semantics/memory.rs` consume `flock::clean::load64` and `flock::clean::store64`, generated from the Clean circuits `LeanVMCircuits.Load.circuit` and `LeanVMCircuits.Store.circuit` in `MemoryLoad.lean` and `MemoryStore.lean`. The handwritten memory gate construction and its unused address, width-selection, and byte-shift builder helpers are removed. Address calculation is the 64-bit wrapping adder followed by the aligned bus address calculation. Loads compose byte shifting and width/sign extension; stores compose byte shifting and a mask that preserves every unselected byte. The narrow intermediate store shifts retain structural zero bits, rather than allocating three full 64-bit shift stages.

`Memory.legal_load_flags` and `Memory.legal_store_flags` identify the source domains with load flag words `0, 1, 2, 4, 5, 6` and store flag words `0, 1, 2`. `Memory.bus_aligned_iff` proves that a bus address has zero low three bits exactly when the effective address is aligned to the selected width, within this legal domain. Load soundness specifies extraction and sign or zero extension from its supplied cell for every offset. Store soundness specifies contiguous replacement of the selected bytes under the explicit `Memory.Aligned` effective-address premise. An invalid width or a misaligned store is not silently included in that architectural specification. Global binding of the supplied cell to an aligned memory-table key, instruction decoding, and the table/bus argument remain separate obligations; these local circuit theorems do not assert them.

`Flock.Load.source_eq` and `Flock.Store.source_eq` identify the checked artifacts with lowering of these actual Clean circuits. Their `soundness` theorems apply to arbitrary assignments satisfying the exported product constraints and the respective source domain assumptions. Their `layout`, `wellFormed`, and `complete` theorems check dependency order and prove that every input assignment has a satisfying extension. The artifacts have 128 output bits, bus word first, followed by the loaded value or updated cell. Load has 253 ordered products at source variables 195 through 447; store has 309 at source variables 258 through 566.

Rust load ports occupy input slots 0 through 255 and output slots 256 through 383, with constant slot 384 and products 385 through 637. Store ports occupy inputs 0 through 319 and outputs 320 through 447, with constant slot 448 and products 449 through 757. Compact source input variables map to operand bits, live flag bits, and cell bits, not to the unused bits of padded Rust flag ports. Unused flag bits and instance padding remain forced zero by Builder. Product ordering and the unchanged optimized native load/store witness kernels retain the production shape and proof format.

`clean_memory_proves_native_witnesses_and_rejects_false_cells_products_and_padding` proves and verifies native load/store batches through the real Flock reduction at overflow and carry boundaries, then rejects altered bus or value outputs, a private product, an unused flag bit, and instance padding. A release smoke also executed all byte, halfword, word, and doubleword load/store instruction forms, verified their VM proofs and a 2-to-1 recursive aggregation after encoding/decoding, rejected changed public outputs, and observed misaligned load/store traps. These are integration evidence, not formal verification of the Rust witness kernels, Builder, memory-table plumbing, or recursive verifier.

## Clock circuit

`Clock::builder` in `crates/leanvm_core/src/tables/clock.rs` builds every production table's clock gates from `flock::clean::clock_registers`, `clock_load`, `clock_store`, `clock_hash` and `clock_ext`, generated from `LeanVMCircuits.ClockStep.circuit` on the five slot lists the tables use: `[0, 1, 3]` (ALU, SHIFT, MUL, MULH, DIV), `[0, 3, 2]` (LOAD, LD), `[0, 1, 2]` (STORE, SD), `[0, 1, .., 17]` (HASH) and `[0, 1, 3, 4, .., 12]` (EXT, whose `Ext::clock_circuit` adds its own ports and gates on the same builder). The Clean circuit (`ClockCircuit.lean`, `ClockStep.lean`) is parametric in the slot list and mirrors the former handwritten gate list product for product: per access the carry out of bit 39 of `(ts | slot) + !prev`, over the slot bits a chain of ORs and ANDs whose products before the slot's lowest set bit are structural zeros and skipped (`ClockLow`), then 35 majority products (`Adder`), then the OR of its live-bit disagreement into the row's (the first access's free); the AND of the in-order bits (`ClockAll`), `late` and `fail`; and the step's carry chain (`ClockChain`). Bits 5 and 41 of the step are Builder copies of `live` and `fail`; the 35 chain products are written straight to step bits 6 through 40 by `Builder::and_output` (`outputProducts`). A slot list no table has makes `Clock::builder` panic.

`ClockStep.circuit`'s soundness says the step port's bits 5 to 41 read as an integer are `Clock.step` of the slots on the ports' integers. `Flock.Clock.soundness_of` carries this through any lowering, and for each list `Flock.Clock.Registers.soundness`, `Load.soundness`, `Store.soundness`, `Hash.soundness` and `Ext.soundness` conclude `Clock.Holds slots (prevNums n env.get) (tsNum env.get) (stepNum artifact env.get)` for every assignment satisfying the exported rows, the integers being spelled by the source variables: the clock's bits 5 to 40 at variables 0 to 35, bit `b` of the `i`-th previous timestamp at `36 + 41 i + b`, and the artifact's 37 outputs as the step's bits 5 to 41. This is the `Clock.Holds` that `Bus.ClassTable.row_correct` and `tables_correct` consume per row. `source_eq` ties each artifact to the lowering of the real Clean source; `layout` checks its ordered products (154 for the registers' list, 153 for a load's or store's, 754 for HASH's, 514 for EXT's) and 37 outputs; `output_products_layout` identifies outputs 1 through 35 with the last 35 product variables; `wellFormed` and `complete` prove every input assignment extends to a satisfying one.

`Clock::builder` and `Clock::circuit` are crate-internal: their only callers are the tables' clock circuits (`ClassSpec::clock_circuit` and `Ext::clock_circuit`), whose slot lists are exactly the five exported ones, and any other slot list panics. `the_clock_circuit_is_its_reference` checks, for every table's slots, that the generated circuit's step port is the native `Clock::step` on swept previous timestamps, flipped live bits and padding rows; `the_word_witness_is_the_gate_walk` checks the unchanged native witness writes what the gate walk of every table's clock circuit writes. `clean_clock_proves_native_witnesses_and_rejects_false_steps_products_and_padding` proves and verifies the native `Clock::witness` for live, failing and padding rows of every production list through the real Flock reduction, then rejects a flipped step bit 5, 6 or 41, the final private product and instance padding. Trusted as for the other exports: Lean's runtime, the emitter and formatter, the Rust compiler and Builder's gate semantics.

`LeanVMCircuits.Bus.TableClock` picks each instruction table's exported clock artifact by its slot list (`ClassTable.clockArtifact`) and proves that any assignment satisfying its rows spells ports with `Clock.Holds` on the table's slots (`ClassTable.clock_sound`). `ClassTable.tables_correct_of_clock` is `tables_correct` with `TableRow.Valid` replaced by `TableRow.ClockValid`: the row's clock circuit is satisfied by an assignment whose spelled clock, previous timestamps and step are the words of the row's clock, previous-timestamp and step columns, and EXT's `base` column is Boolean. What stays trusted there is that a committed port column is the word its port bits spell (`tables/circuits.rs` packs bit `i` of the port at bit `i` of the `F64`).

## Ext clock extras

`Ext::clock_circuit` in `crates/leanvm_core/src/rv/semantics/ext.rs` keeps `Clock::builder` for the clock of its twelve accesses and then calls `flock::clean::ext_clock`, generated from `LeanVMCircuits.ExtClock.circuit` (`ExtClockValues`, `ExtClockCircuit`, `ExtClockExport`). For each pointer `a`, `b`, `d` (ports `v1`, `v2`, `vd`) the source adds 8 and 16 with an incrementer (`ExtClock.Increment`: the chain of ANDs over bits `bit + 1 ..= 62` from bit `bit`, then each sum bit an XOR), gates `b`'s two addresses by `!base` with the products `(base + 1) * sum` (`WordScale`), and returns the flags' two bits. `ExtClockValues.incrOut_value` proves an incrementer's bits read `(p + 2^bit) mod 2^64`.

`Flock.ExtClock.soundness` states, for every assignment satisfying the exported rows, `ExtClock.Addresses`: the outputs are the flags' bits, then `(p + 8) mod 2^64` and `(p + 16) mod 2^64` for `a`, `b`, `d`, `b`'s zero when flag bit 1 (`base`) is set. Its inputs are the extra ports only (`v1` variables 0 through 63, `v2` 64 through 127, `vd` 128 through 191, flags 192 and 193). `source_eq` ties the artifact to the Clean source, `layout` checks 479 ordered products at source variables 194 through 672 and 386 outputs, `output_products_layout` identifies outputs 130 through 257 with the gating products, variables 370 through 433 and 492 through 555, which `Generate.lean` commits at bits of ports 5 and 6 with `Builder::and_output`, and `wellFormed` and `complete` give every input assignment a satisfying extension. The generated function returns the flag bits and `a`'s and `d`'s addresses, which `Ext::clock_circuit` copies to ports 1, 2, 3, 4, 7 and 8.

The native `Ext::clock_witness` is unchanged; the generated layout fixes its product order and committed slots. `flock_proves_the_ext_clock_and_refuses_a_flipped_address_or_product` proves and verifies native EXT clock batches through the Flock reduction and rejects a flipped flag copy, `a` address bit, gated `b` address bit, and the last private incrementer product. `clean_clock_proves_native_witnesses_and_rejects_false_steps_products_and_padding` exercises the five generated clock configurations and rejects false steps, private products and padding. A release VM smoke exercised register, load, store and hash accesses and all four extension instruction forms, checked native extension results, verified serialized real proofs and rejected altered public outputs. The extras and shared clock sources have separate exported-artifact proofs; interpreting their generated Rust builders and their composition remains trusted.

## EXT field identities

`ClassTable::identities` in `crates/leanvm_core/src/tables/table.rs` consumes `tables::clean::extension_identities`, generated by `GenerateTables.lean` from `LeanVMCircuits.ExtensionProduct.rows`. The same three ordered quadratic identities are the actual Clean `ExtensionProduct.circuit`, over the proved `GF(2^64)` and its cubic extension `GF(2^192)`. There is no second handwritten identity builder. The generator binds the logical accumulation, operand, old destination and new destination columns to the existing table layout and rejects unsupported columns, linear shapes and non-unit coefficients.

`source` identifies those exact identities with the Clean source, and `source_holds` proves its actual operations hold exactly when the new destination is `a * b + accumulate * old`. `soundness_iff` applies to every assignment of field columns, not just a native witness. `instruction_soundness` interprets a Boolean accumulation column as MUL or MAC, and `base_operand` gives scalar multiplication when the upper two limbs of `b` are zero. `witness_exists` proves every assignment to all ten input columns extends to satisfying result columns without an honest-witness premise.

The optimized native extension arithmetic is unchanged. A release smoke exercised all four extension instruction forms with zero and high-bit operands and a nonzero old destination, compared execution to host field arithmetic, verified serialized real leaf proofs and rejected altered outputs. The existing identity regression rejects each mutated result limb. An executable lowering smoke also rejected out-of-range columns, missing outputs and non-unit linear and product coefficients.

Trusted: Lean execution and the Rust emitter/formatter/compiler; the logical-to-table column binding and the native `BusForm` interpretation; that native `F64` coefficients and their `F192` embedding represent the proved fields; and the optimized native arithmetic. Boolean accumulation and zero upper scalar limbs are explicit instruction interpretation premises. The clock extras produce the corresponding flags and zero addresses, but binding their bits to field columns and deriving zero values from the `x0` memory invariant are not discharged by these local field identities.

## Integer-multiplicity bus and memory argument

Clean's channels now separate the message field from the multiplicity type. The pinned fork retains existing field multiplicities by default and permits `ℤ` for leanVM's producer and consumer counts. `LeanVMCircuits.Bus` proves exact integer balance and its symbolic fingerprint product identity, lookup correctness including decoded bytecode entries, a state walk from balanced state rows, and memory consistency for ordered access rows. `memory_consistent_of_state_walk` derives the after-seeds condition from the state walk; `memory_consistent_shared` composes RAM and advice under disjoint address ranges.

`machine_correct` composes these lookup, walk and memory theorems for complete abstract row flushes. `machine_correct_of_product_check` derives their integer balance from the symbolic product identity and explicitly Boolean bytecode multiplicity bits. The row interface exposes clock bounds, empty low slot bits, the specified live-bit increment and failure marker, per-access previous-clock bounds/order and distinct slots as C1 through C3. `ClassTable.tables_correct_of_clock` derives these clock conditions from satisfying assignments to the actual exported clock artifacts, with explicit word-to-column bindings, and concludes `Machine.Correct` and that each row reads the decoded bytecode entry at its own PC. The production layouts and bus plans described below are now generated from these proofs' Clean source. Native decoder and word bindings, EXT's separately assumed Boolean `base` column and verifier protocol linkage remain explicit boundaries before this closes the VM trace argument.

Symbolic product equality and Boolean producer bits are explicit premises at the current boundary. Schwartz-Zippel fingerprint error, accepted GKR/sumcheck implying these identities, PCS binding and the cryptographic protocol composition are not proved by these bus theorems. No whole-VM soundness or security-level claim follows merely from checking the local circuit artifacts.

## Instruction table flushes

`LeanVMCircuits.Bus.TableFlushes` is the source of all eleven production `ClassTable` layouts and ordered state, bytecode and access tuples. `GenerateTables.lean` emits `tables/clean.rs` from `ClassTable.all`, `Spec.layout`, `Spec.pushes` and `Spec.pulls`; `ClassTable::new` and `ClassTable::flushes` consume those generated functions. The handwritten column allocator and flush construction are removed, including their obsolete helpers and copied-fixture tests. Shared LD/SD value columns, tuple order and constants are preserved. A row pulls `⟨ST, pc, ts, 0⟩`, pushes `⟨ST, npc, ts + step, exit⟩`, pulls its twelve-coordinate decoded entry, and accesses memory in clock-slot order. EXT's limbs 4 and 5 carry `MEM + (MEM + REG)·base`. `ClassTable.all_wellFormed` checks distinct slots below `2^5`, one access per slot, the entry's shape and the supported separators. The narrow emitter rejects out-of-range columns, indices and coefficient words, overwide tuples and unsupported access shapes rather than dropping them.

The generated layouts cover every local column and shared alias; generated flush plans cover the state transition, decoded-bytecode tuple and every ordered register, RAM, hash-block and EXT access coordinate. `Coord.expr` interprets each supported coordinate as a Clean expression over `K`. `Coord.eval_expr` proves expression evaluation agrees with the coordinate semantics for every row, and `sourceTuple_eq` lifts that equality to bus tuples. `Spec.source` is the actual list of integer-multiplicity Clean interactions, with multiplicity `1` for pushes and `-1` for pulls; `Spec.source_eq` proves it is exactly `Spec.flushes`' interactions. The emitter prints the same source coordinate data, not a second copied native plan. Printing and native interpretation remain trusted as listed below.

`LeanVMCircuits.Bus.TableRows` evaluates the model on a row whose column `i` holds `v i` (`Spec.flushes`, `Coord.eval`) and builds the row's `MachineRow` (`Spec.row`): its `pc`, `ts`, `step`, `npc` and `exit` columns, `inOrder` the negated verdict `Clock.fail` on the words of its clock and previous-timestamp columns, one bytecode read of the entry's ten decoded coordinates at its own `pc` (`Spec.row_reads`, the form `machine_reads_at_pc` takes), and its accesses, the registers' those whose separator evaluates to `REG` and the memory's the others. `ClassTable.row_correct` proves, for every table of `ClassTable.all`, that when the clock column holds `ofWord ts`, previous-timestamp column `i` holds `ofWord prev[i]` and the step column `ofWord step` with `Clock.Holds slots prev ts step`, and EXT's `base` column is zero or one, the row's pushes and pulls are, as multisets, the `MachineRow`'s flushes (`Spec.pushes_eq`, `Spec.pulls_eq`), and the `MachineRow` satisfies C1, C2 and C3 (`Spec.row_c1`, `Spec.row_c2`, `Spec.row_c3`), the last two by the clock reference's `clock_next` and `clock_in_order`.

`LeanVMCircuits.Bus.ClockFacts` derives the clock facts from the clock circuit's word-level reference `LeanVMCircuits.ClockSpec`: `clock_next` (the clock column plus the step column is `nextClock ts (!Clock.fail ...)`, fact C2) and `clock_in_order` (a row that does not fail has every access in order). `LeanVMCircuits.Bus.Tables` composes everything: `ClassTable.tables_correct` takes each table row's source flushes plus the state boundary, seeds, finalizations and bytecode producer (`tableBus`) and, when every row is `TableRow.Valid` (its clock ports satisfy `Clock.Holds` and its extension-field flag bit is Boolean), concludes `Machine.Correct` for the rows and that each row's decoded entry is the one it reads at its own instruction address (`machine_reads_at_pc`).

Trusted: Lean runtime printing and Rust compilation; that `Coord::Const(F64(w))` represents `ofWord w` in `K` and the native bus evaluates coordinates as `Coord.eval` does; the native `ClassSpec` selectors, decoder and filled word values; concrete clock port packing and word-to-column bindings exposed in `TableRow.ClockValid`; EXT's separately assumed Boolean `base` column; and correspondence between the verifier's bus and `tableBus`, including its boundary, seeds, finalizations and producer. ## BLAKE2s compression

The `blake2s` instruction class's circuit, `Hash::circuit` in `crates/leanvm_core/src/rv/semantics/hash.rs`, is the generated `flock::clean::blake2s`; the recursion machine's `HASH` table proves its rows with the same circuit. `Hash::circuit` only binds ports: word `i` of `h`, `m` and the result is half `i % 2` of port word `i / 2`, low half first. The former hand-written G loop is removed. The optimized word-arithmetic witness `blake2s_witness` is unchanged, and `the_word_witness_is_the_gate_walk` still pins it to the walk of the generated gate list, which also pins the product slots (14878 carries, two of the 480 additions having 30 because round 0 adds an IV word with a zero low bit).

`LeanVMCircuits.Blake2s.Rfc7693.F` is the compression function F of RFC 7693 written from the RFC's pseudocode, and `Rfc7693.abc` checks it in the kernel against the RFC's Appendix B test vector. `LeanVMCircuits.Blake2s.Compress.circuit` is the Clean circuit: a register program (`Blake2s.program`, ten rounds of eight G functions in the RFC's order) run as Clean subcircuits for its word operations `Add32` (Clean's 32-bit wrapping adder), `AddOdd` and `AddEven` (a literal addend; an even one leaves the low bit and adds `k / 2` to the upper 31 bits with Clean's 31-bit adder), and `XorRotr`. Each word operation names its 32 result bits as witnesses constrained to affine expressions of earlier variables, so that the source's expressions stay small. `Compress.soundness` proves, for every witness satisfying the constraints, that the output is `F h m t f` whenever the 32-bit finalization port is `0` or `0xFFFFFFFF` (`f` false or true); `program_correct` carries the RFC's working vector through the registers. The class's legal flags are exactly those two words.

`LeanVMCircuits.Gates` lowers such circuits: a witness constrained to an affine expression becomes an uncommitted XOR definition, one constrained to a product of two affine operands becomes the next product, and anything else (other witnesses or assertions, lookups, interactions) is an error. `Gates.lower_correct` proves that the steps hold exactly when the Clean constraints do, and `lower_wellFormed` that every step defines the next variable from earlier ones, which gives `witness_exists`. `Compress.lowered` proves that the lowering of the actual Clean circuit at the ports' variables (`t` at 0, `f0` at 64, `h` at 96, `m` at 352) is `Compress.artifact`, a closed form built operation by operation; nothing is evaluated outside the kernel's proof checking. `Export.soundness` and `Export.completeness` state the arbitrary-witness soundness against `F` and the existential completeness of that artifact.

The generator emits one Rust line per register of `Blake2s.program`: `wrapping_add32` for an addition, `wrapping_add32` on a literal's wires for an odd literal, `add_even32` (the low bit passed through, then `wrapping_add31` on the upper bits) for an even one, and `xor_rotr32`. `Export.adder32_call` and `Export.adder31_call` prove that each addition's products and sum bits in the artifact are the exported `adder32` and `adder31` rows and outputs under the call's binding of operand and product variables; `adder31` has the same source, layout, soundness, well-formedness and completeness theorems as `adder32`. Trusted, beyond the boundary stated above: the transliteration of the program into Rust calls and the small word helpers (`literal32`, `low32`, `high32`, `xor32`, `xor_rotr32`, `add_even32`), and `Hash::circuit`'s port binding. That no product operand is Builder's structural zero, so that each product step takes one slot in order, is checked by the walk-versus-word-witness regression rather than proved.

`hash_circuit_matches_the_reference` pins the generated circuit to the native compression, `a_flipped_witness_bit_is_refused` proves an honest batch through the Flock reduction with the native witness and refuses a flipped counter, output, constant, first-carry or last-carry bit, and `blake2s_precompile_proves_and_verifies` proves and verifies a two-block hash in the VM and refuses an altered output.

## Multiplication and division

`Mul::circuit`, `Mulh::circuit` and `Div::circuit` in `crates/leanvm_core/src/rv/semantics/{multiply,divide}.rs` only bind ports to the generated `flock::clean::mul64`, `mulh64` and `div64`. The hand-written gate construction, `Multiplier::build` in `crates/flock/src/gadgets.rs` and the word helpers left without callers (`negate_if`, `any`, `xor_word`, `sext32_if`), is removed. `Multiplier::plan` keeps the carry-save plan for the unchanged native witness kernels; `word_witnesses_match_the_gate_walk` and `batched_low_witness_matches_the_gate_walk` pin those kernels to the walk of the generated gate lists, which pins every product slot.

`LeanVMCircuits.Rv64` transcribes the M extension from the RISC-V unprivileged ISA, on register values as naturals: `mul` (`MUL`, `MULW`), `mulh` (`MULH`, `MULHSU`, `MULHU`, the floor of the 128-bit product over `2^64`) and `div` (`DIV`, `DIVU`, `REM`, `REMU` and the word forms, rounding toward zero, a zero divisor giving all ones or the dividend, `-2^(L-1) / -1` giving the dividend or zero, word results sign-extended). `MulDiv.mul_eq`, `mulh_eq` and `div_eq` prove that the arithmetic the circuits compose equals it for all operands below `2^64`.

The multiplier is the production carry-save plan. `Multiply.plan` transcribes its row selection, products and moves; `Multiply.check64` and `check128` check by kernel reduction that every step's positions satisfy what `Multiply.replay` needs, and `Multiply.product_value` proves that the plan's final ripple sum is `a b` modulo `2^n` for every `a` and `b`. `LeanVMCircuits.Netlist` is a Clean circuit of a gate list, each local wire witnessed and constrained to an affine combination or a product of two; `Netlist.holds_iff` shows its constraints are exactly the gates. `Multiply.gates_product` proves that every assignment satisfying the multiplier's gates outputs `a b` modulo `2^n`, so `Multiply.circuit` is a Clean `FormalCircuit` with that specification. `Mul.circuit` adds the word sign extension (`WordMode`), `Mulh.circuit` two signed corrections (a product, a `WordMux` of the complemented operand, `Adder.circuit 64`), and `Div.circuit` the operands' extension and magnitudes, the checks of the hints, the verdict and the result, each a Clean subcircuit with its own proof. `Div.Spec` sets `bad` exactly when the divisor is nonzero and `q |d| + r = |n|, r < |d|` fails over the integers, which fixes the hints to `|n| / |d|` and `|n| % |d|`; while `bad` is clear the output is `Rv64.div`, and `Div.honest_hints` shows the honest hints clear `bad`.

`MulDivExport` lowers each class with `Gates`: the multiplier's steps in closed form by `Netlist.lower_opsFrom` and `Multiply.layout_wellOrdered`, the glue before and after it flattened and lowered by `decide +kernel`. `Mul.source`, `Mulh.source` and `Div.source` identify the artifacts with the lowering of the actual Clean circuits at the ports' compact variables (`v1`, `v2`, the live flag bits, then `q` and `r` for division), and their `soundness` theorems give the RISC-V result for every assignment satisfying the artifact's steps, not just honest witnesses; `completeness` extends every port assignment to a satisfying one. `multiplier_call` proves that a class's multiplier steps are the multiplier function's own, renamed by the call's binding of operands and wires.

The generator (`MulDivEmit`) emits `multiply64` and `multiply128` as a table of the multiplier's steps, one entry per XOR or product in step order, replayed by `replay`, and each class as one Builder call per step of its glue around a call of the multiplier function. It refuses a product with a structurally zero operand and checks each function's product count, so the generated products and their order are the artifact's. Trusted, beyond the boundary stated above: Lean's runtime evaluation of the emitter, `replay`'s interpretation of a table entry as `Builder::xor` or `Builder::and`, and the call binding in Rust. `clean_multiplications_prove_native_witnesses_and_reject_flipped_bits` and `clean_division_proves_and_a_wrong_hint_cannot_clear_bad` prove batches through the Flock reduction and refuse flipped result, product, constant and `bad` bits, including clearing `bad` for a wrong quotient. `shifts_and_multiplications_prove_and_verify`, `clean_multiplication_boundaries_prove_and_verify`, `divisions_prove_and_verify` and `clean_carry_adder_arithmetic_boundaries` prove and verify every M instruction in the VM, then reject an altered output. These are integration evidence, not formal verification of the Rust witness kernels, Builder, the tables or the protocol.

A release smoke ran all thirteen multiply/divide instruction forms on zero, signed, word and overflow boundaries, compared the VM's results to independently computed host arithmetic, verified an encoded/decoded actual leaf proof and rejected a changed public output. The scoped Flock regressions also passed on the merged tree, including incorrect division hints whose `bad` verdict cannot be cleared.

## Recursion tables

The recursion machine's tables are not Boolean circuits: their columns are elements of `K = GF(2)[x] / (x^64 + x^4 + x^3 + x + 1)` and its extension `E = K[y] / (y^3 + y + 1)`. `LeanVMCircuits.Rec.Field` builds `K` as Mathlib's `AdjoinRoot` and proves `Rec.modulus_irreducible` in the kernel: carry-less word arithmetic (`Rec.mul`, proven to be `K`'s product by `Rec.ev_mul`) checks the 64 squarings `x^(2^64) = x` (`Rec.chain_squares`, `Rec.root_pow_two_pow_64`) and an inverse of `x^(2^32) - x` (`Rec.cofactor_mul`), and Mathlib's degree theorem for factors of `X^(q^n) - X` turns those into irreducibility. `K` is then a Clean `FiniteField` whose `val` is the element's coefficient word, the machine's own representation (`Rec.toWord_ofWord`, `Rec.toWord_injective`). `LeanVMCircuits.Rec.Ext` gives `E` and its limb formulas: `Rec.toE_mul` (the product of `c0 + c1 y + c2 y^2` by limbs, `y^3 = y + 1` and `y^4 = y^2 + y` folding the high terms), `Rec.toE_add`, `Rec.toE_smul`, and `Rec.toE_injective` (limbs are coordinates).

`LeanVMCircuits.Rec.Tables` writes every slot of `EMUL`, `EXK`, `HASH`, `SPLIT` and `CAST` as `Form` data, the prover's `bus::Coord` shape (`Const`, `Col`, `Prod`, `Sum`), read as Clean expressions by `Form.expr` (`Form.eval_expr`), and the identities of `HASH` and `SPLIT` as `Identity` data, a Clean `FormalAssertion` per table (`Rec.identities`, sound and complete for its identities). The theorems, for every row: `emul_spec` (slot 3 is `a·b + d` in `E`, its fourth limb zero), `exk_spec` (`a·k + d`), `hash_mux` (the mux bit is 0 or 1, and the mux limbs are the message's first half at 0 and its second at 1), `split_spec` (every bit column is 0 or 1 and the word's coefficient word is the number those bits spell), and `boolean_spec`. `CAST`'s slots are views of its four columns and `PUB` has no columns. `GenerateRec.lean` prints the same data as `crates/leanvm_core/src/rec/clean.rs`, which `Table::slot` and `Table::identities` in `rec/table.rs` now read in place of the hand-written forms, and `K_PRODUCTS`, products computed by `Rec.mul`, which `f64_products_are_the_proven_field` checks against the prover's `F64` product.

Trusted: the printer of forms and words into Rust; that `F64` and `F192::from(F64(w))` are the `K` element with coefficient word `w` and its embedding in `E` (the test samples products, it does not prove the Rust field); `F192`'s product, pinned by `emul_and_exk_outputs_are_e_arithmetic` against the forms, not proven. `LeanVMCircuits.Rec.Rows` states what the builder's row patterns mean, the bus equalities a pattern relies on taken as hypotheses on its slots: `inverse_row` (an `EMUL` row `a·i + 0` held to one makes `i` the unique inverse of `a`, so `inv` of zero is unsatisfiable), `add_row`, `pack_row` (a `SPLIT` row whose bits past `n` are held to zero spells a number below `2^n`), `cast_views`, `hash_outputs` (a hash row's first-three-word `E` view, not a general buffered duplex challenge), and `node_row` (a Merkle node's mux places `acc` as the first or second half by its Boolean bit). `LeanVMCircuits.Rec.HashPorts` joins a hash row to its compression: `hash_ports_compress` and `hash_row_compress` prove that when the row's packed witness satisfies the exported BLAKE2s artifact and the witness's ports are the row's port columns (64-bit words, 32-bit word `r` of `h`, `m` and the result being half `r % 2` of port word `r / 2`), its output columns are RFC 7693's compression of its chaining value and message columns with its counter column, for both finalization words. `LeanVMCircuits.Rec.Merkle` and `LeanVMCircuits.Rec.Statement` lift this to the hashes the recursion circuit computes in rows, against RFC 7693 section 3.3 (BLAKE2s-256 with `kk = 0`, `nn = 32`, from the parameter IV): `chain_digest` and `chain_rows` prove that hash rows chained output to chaining value, at RFC 7693's byte counts and finalization, output the hash of their message columns (`Builder::chain`, a Merkle leaf's blocks, with `blocksFrom_append` folding a leaf's zero prefix into the chaining value it starts from); `node_row_digest` and `path_root` that node rows chained output to accumulated child output the RFC 7693 Merkle root of the leaf and the bits and siblings the rows hold (`Builder::node`), `opening_node` the two composed (`open_row`); `parent_row_digest`, `parent_right` and `tree_root` that parent rows over a subtree's levels output the root of its bottom level (`Builder::parent`, `authenticate`); `statement_digest` that a tree statement's digest rows output the hash of its header block (tag, item count, zeros) and its items' words (`Kind::digest_rows`). `LeanVMCircuits.Rec.Duplex` models the duplex transcript: `Duplex` is `fiat_shamir::Blake2sDuplex` on whole 64-bit words (every message the recursion verifier absorbs or squeezes is whole little-endian words: the instance's, a scalar's three limbs, a root's four, a nonce, so its byte buffers hold whole words), started by `Duplex.init` from a session id's four words, each compression RFC 7693's `F` at the node's counter (`Role::absorb(first, last).counter(len, previous)`, `Role::Seed.counter(0, 0)`, `Role::Output.counter(0, 0)`), final; `RowState` and the `...Rows` relations are `rec::transcript::Transcript`'s bookkeeping, every compression a hash row whose output is the next chaining value and every squeezed word read from the output row that computed its block. `run_rows` proves that rows replaying absorbs, squeezes (a verifier message's three words, a digest's four) and proof-of-work steps reach the native state and squeeze the native challenge words, `seed_row` that the constant seed chaining value `Transcript::new` takes (the seed node of the session id's words and four zero words) is `Duplex.init`'s, `pow_rows` that the proof-of-work check in rows (no row at zero bits; else the four-word challenge squeezed, the nonce absorbed as one word, a one-block hash row of the challenge, the nonce, two zero words and `ProofOfWork::TRIAL_TAG`, and a `SPLIT` row of its first word with its top `bits` bits held to zero) is `ProofOfWork::verify` of the nonce on the native challenge (`powOk`, by `trial_rows` and `pack_row`). The cursor bound: `Duplex.Bounded` runs (a squeeze only within `MAX_SQUEEZE`, which `Blake2sDuplex::squeeze` and `Transcript::squeeze_word` assert) keep both cursors within it (`run_fits`), and within it an absorb counter names its role, block length and cursor (`tweak_injective`) and is neither the seed nor the output counter (`tag_ne_tweak`). The rows' words become `E` challenges and scalars, and four of them a digest, through `k_to_e`, `e_to_k` and `k_to_d`, whose contracts `LeanVMCircuits.Rec.Contracts` proves (`Model.kToE_good`, `Model.eToK_good`, `Model.kToD_good`). The Rust constants `PARAM_IV`, `zero_prefix`, the seed and output counters, `ProofOfWork::TRIAL_TAG` and `Role::absorb(first, last).counter(len, previous)` are pinned to these Lean definitions by `the_native_constants_are_the_lean_transcriptions` over the values `GenerateRec.lean` prints (every absorb role at full and partial lengths and both cursor ends, four zero prefixes). Not modeled: the byte-level duplex on unaligned input, which the recursion verifier never calls, and `SessionId::new`'s derivation of a session id, which is native. `LeanVMCircuits.Rec.Bus` proves the bus's copy argument: with distinct slot keys (`slotKey_injective`, `SlotKey`'s slot index and row below `2^32`) and each slot linked to the next slot of its class in slot order, the class's first after its last (`classNext`, the links `FixedColumns::of` builds; a permutation, `classNext_injective`), pulls of each slot's key and limbs balancing pushes of its link's key and the same limbs modulo two (characteristic two, so as multiplicities mod 2) make every slot of a class carry the same limbs (`copy_argument`). `LeanVMCircuits.Rec.BusBalance` derives that balance from the bus's product check: `BusBlocks::new` pulls each slot's key and limbs and pushes its `next` key and the same limbs (a Rust test, `every_slot_pulls_its_key_and_pushes_its_next_with_its_limbs`, checks the plan slot by slot), and `bus::verify_balance` checks the products of `β + fp_A(t)` over the two sides equal, with `fingerprint_weights` the union's `eq(A, k)`. `balanced_of_eq`: equal sides, their tuples encoded injectively, balance. `bus_balance_sound`: if the sides do not balance, the points `(β, A)` of `S^5` at which the products agree are at most a `4n/|S|` fraction (`UnionSound.coverage_sound`). `bus_copy_sound`: with `next` the classes' cycles, the points at which the products agree but two slots of one class carry different limbs are at most that fraction. `LeanVMCircuits.Rec.ExtField` proves `y^3 + y + 1` irreducible over `K` (a root would have order dividing 7 and `2^64 - 1`, so be 1, which is not a root), so `E` is a field and every nonzero element has the inverse an `inv` row needs (`exists_inverse`). Not proved here: that the bus's log-derivative sums balance only when the multiplicities do (GKR and the fingerprint's soundness), that `FixedColumns::of` builds the `classNext` links in configurations other than the tracked ones (`checkrec` checks the links of the tracked trees' circuits, below; elsewhere its fold is their transliteration), GKR, the table sumcheck, the PCS; that the Rust builder emits exactly these patterns (it writes each row at the slot indices `GenerateRec.lean` prints from the names these theorems use, `Rec.hashSlotMux` as `clean::HASH_MUX` and so on, but which wire or public constant it writes at each is trusted, as is the chaining of rows), and that the native constants `PARAM_IV` and `zero_prefix` are `paramIV` and `absorb paramIV 0` of zero blocks, that the hash table's port columns are the packed witness's port words (`RecWitness::build`), and the composition of rows into the transcript, Merkle paths, chains and the verifier in rows; and the binding of public rows to the statement.

The duplex definitions above are a mathematical whole-word transcription, not a formally verified equivalence to the Rust byte-level `fiat_shamir::Blake2sDuplex`. `Rec.trial_rows` proves that satisfying HASH and SPLIT rows implement the nonce trial digest's top-bit test; `Rec.pow_rows` connects it to the challenge of the modeled duplex. Both are included in `Audit.lean`. The bounded-run theorems expose the cursor limit as a mathematical premise; equivalence to the native guards and `SessionId::new` remains trusted.

The upstream spongefish transcript migration changes proof bytes, not only the API, with a length-prefixed NARG section followed by hints. The current envelopes are `LVMP` 17 and `LVMT` 19, the tree session domain is `leanvm-tree-16` and the union's is `leanvm-claim-union-3`. A session-derived seed precedes the instance's first message; roots are absorbed as four words, digest challenges squeeze four words, and proof of work squeezes a challenge, absorbs one nonce word and checks the trial digest's top bits. The `Rec.Duplex` row model follows this whole-word framing. Claim-set unions absorb their begin-bit words, and at every node the words of its absent bits, before drawing the fingerprint challenge; equivalence of the verifier's message schedule to this model and union soundness are not proved here.

## Recursion builder model

`LeanVMCircuits.Rec.Builder` is `rec::circuit::Builder` as a Lean program over wire numbers: each method allocates wires, appends rows, records wire equalities and adds public rows as the Rust method does, in the same order, without values (the rows never depend on them). `LeanVMCircuits.Rec.Contracts` proves each method's contract (`Model.Call.exec_good`, and `Model.inv_good`, `Model.node_good`, `Model.chain_good` and the rest for the methods themselves): from a state keeping the builder's invariant (`Model.Inv`: constants and units have their public rows, cached arithmetic rows are in the circuit under their keys), the method keeps it, only adds to the circuit, and in every assignment satisfying any circuit containing its rows (`Model.Sat`: wires held equal carry equal limbs, every row's slots carry the limbs its table's forms give columns satisfying the table, `HASH` columns a packed witness of the exported BLAKE2s artifact, public rows their constants and statement words) its output is what it computes. Among them: `a·b + d` in `E` through unit folding and the row cache (`Model.emulKey_sem`), `a·inv(a) = 1`, a word's bits and a packed word, the `CAST` views, RFC 7693 compressions (`leaf_block` at a constant counter and finalization word, `block`, modeled as `Model.hashBlock`, at a wired one, `Model.leafBlock_eq` relating the two), Merkle nodes with a Boolean bit and a free sibling, parents of two wired children, and `chain`'s BLAKE2s-256 of a word message. `Model.replay_sound` lifts them to any sequence of calls naming wires already made.

The upstream claim-set builder changes add a traced `block` call with an explicit tweak wire. `Model.hashBlock_good` proves its RFC 7693 compression contract when the finalization word's low half is the specified Boolean flag, and `Model.leafBlock_eq` identifies the constant-tweak leaf wrapper. `Model.dToHalves_good` proves the CAST halves have the input components and zero third extension components. The upstream claim-set and canonical union machinery is not formally modeled here.

The Rust builder records external method calls behind `circuit-trace`, which no ordinary build enables. `cargo run --release -p leanvm-cli --features circuits -- circuits <dir>` writes the eight output-tree configurations (leanXMSS-400 and leanXMSS-100, 2 to 1 and 4 to 1, first and node), the leanXMSS-100 2 to 1 tree over zero-knowledge leaves (first and node, its first level verifying the zero-knowledge leaf proofs), every circuit of the two tracked leanXMSS-400 signer-set trees (2 to 1 with first and node; 4 to 1 with first, two-child, three-child and four-child circuits, named as their benchmarks: `-first`, `-node<k>` and `-node` for the largest arity), plus every position of two leanXMSS-100 claim-set examples: one tier with first, two-child and three-child circuits; two tiers with first, small two-child, wrap and large three-child circuits. Every claim-set node circuit, of either tier, reads its places past its children as absent. `Tree::circuit_dump` uses a positional index and that position's fixed columns, not the legacy two-kind selector. Each dump contains builder calls, finished slot classes, public row sources in statement-first order, statement length and fixed copy links.

`lake exe checkrec <files>` replays calls naming already allocated wires with the required sizes (`Model.Valid`), compares the finished rows and public row order to the model (its public rows reordered statement first by `Model.pubFirst`, the order `Model.stmtFirst` gives a child's circuit in the AIR link), and checks each fixed `Next` link is the next slot of its class (`Rec.classNext`). All twenty-three configurations pass with the existing Lean model and parser; no new builder operation or checker grammar is required for multi-bit kind selection, the tier wrap, absent children, the reordered verifier, zero-knowledge leaves or the tracked signer-set trees (#617), whose six dumps are the single-tier claim-set circuits at the benchmarks' capacities. Against the `b094d006` integration, the one-tier two-child and three-child and the two-tier small two-child dumps gain the absent bits, their packing and the empty set's reads, and with the two-tier large node they absorb the bits' words in the union's challenge, all through operations the model already has; the first-level, wrap and eight output-tree dumps change only session-derived seed constants in `d_const` calls and their public rows. ## Recursion design model

`LeanVMCircuits.Rec.Design` models `rec::tree::design` for every `TreeShape`, which no finite family of dumps covers: `Shape` is a `TreeShape` without the leaves' shape and the rates (they enter only the leaf verifier, the session and the commitment), with the first level's arity, the nodes' arity and a claim-set tree's capacities and optional small `Tier`. `Shape.check` is `Tree::new`'s refusals in its order (`TreeError::Arity`, then `TreeError::SmallTier`), and `check_eq_none` identifies the accepted shapes with `Shape.Accepted`. `Shape.places` is `Place::all`, `places_getElem` its closed form `Shape.placeAt`; `Shape.start` and `Shape.stop` are each tier's range in `Design::new`, `Shape.kindBits` and `Shape.shift` its kind bits and tier shift, `Shape.code` and `Shape.position` are `Design::code` and `Design::position`, `Shape.above` the tier bits `Design::kind_bits` holds a kind's word to, `Shape.children` what `Design::node` verifies (a node's arity of the small tier, a wrap's one proof of the large tier, none for the first level), `Shape.union` is `Design::union_shape` with `UnionShape.new` and `ClaimShape.tierCapacity`, and `Shape.vars` and `Shape.layout` are `Design::new`'s dense variables and `StatementLayout`, given the program's two dense variables and each tier's fixed stack's variables (`FixedLayout::kappa`), which depend on the program and the heights.

Proven for every accepted shape: the tiers are contiguous blocks of places, the small tier first, every tier nonempty and the last ending at the last place (`tier_lt`, `tier_iff`, `tiers_cover`, the ranges `Design::new` computes and asserts); the first level is position zero only (`first_iff`); a position's index within its tier is below two to the tier's kind bits, which are within the shift (`index_lt`, `kindBits_le_shift`); a kind is its tier times two to the shift plus its index (`code_eq`), `Design::position` inverts `Design::code` and names only kinds of circuits (`position_code`, `code_position`, `code_injective`), a kind's bits past its tier's kind bits are `Shape.above` and its low bits its index (`code_div`, `code_mod`), only the first level has kind zero (`code_eq_zero`), and with fewer than `2 ^ 62` circuits every kind fits a word (`shift_le`, `code_lt`); every node reads one to `arity` children of a tier the tree has, the large tier only through a wrap (`children_tier`, `children_none`), and every circuit has proofs built from leaves (`all_built`: the circuits verify each other in a cycle, small nodes the small tier, the large node the small tier, the wrap the large tier, but every kind is reached from the first level, so no kind is dead and every proof's tree ends at leaves); a tier's capacity is within the tree's and every union is at its tier's (`tierCapacity_le`, `union_capacity`, `items_mono`); a set within a capacity has at most `Capacity::items` blocks (`set_items_le`), and the children's sets of a union, together within its capacity, fit its children's pool, each run from a chunk boundary as `PoolFill::new` lays them, as a set within it fits its declared pool (`runChunks_le`, `children_fit`, `declared_fit`); every dense polynomial's variables fit the statement's point (`vars_le_dense`, so `carried`'s prefixes are in range), a tier's fixed polynomial has its stack's variables and its kind bits (`fixed_vars`), the fixed polynomial a node's child is read against is among the statement's polynomials (`fixed_poly_present`), and a tree of one tier has no wide polynomial (`wide_absent`); the statement's sections tile it, the kind first and the digest next (`start_succ`, `len_eq`, `section_unique`, `kind_digest_words`).

`Design.converge` is `Tree::converge` over an abstract heights oracle `H σ p` (the heights of circuit `p` built at the tiers' heights `σ`, which is the builder's work and not modeled) and `fits` (`RecLayout::from_taus` succeeding, which `Design::new` requires of every tier at every round through `RecShape::new`, else `TooLarge`): each round joins every tier's heights with its circuits', a round that changes nothing returns, and running out of rounds is `TooLarge`. `converge_fits`: heights it returns fit, every circuit's heights are within its tier's (what `Circuit::floor` needs), and they are at least where it started. `converge_least`: when a circuit's heights grow with the tiers' heights, they are the least heights above the start at which every circuit fits, the least fixed point `Tree::converge`'s documentation claims.

`LeanVMCircuits.Rec.DesignKind` writes `Design::kind_bits` as a builder program, `Model.kindRows`: with two circuits the kind is held to a bit (`square`, `eq_e`); else the product of `kind + code` over the child tier's kinds is held to zero (`Model.vanish`), the kind's first limb is split, its bits past the tier's kind bits are held to `Shape.above` (`Model.holdBits`), its low bits become the `top` bits (`Model.tops`), and in the small tier `is_node` is one plus the product of `top_j + 1` (`Model.firstFold`). `Model.kindRows_good`, for every accepted shape with fewer than `2 ^ 62` circuits and every tier: the program keeps the builder's invariant and only adds to the circuit, and in every assignment satisfying a circuit containing its rows (`Model.Sat`) the child's kind is `Shape.code q` of a circuit `q` of that tier, the `top` bits are the bits of `q`'s index within the tier (the block of the tier's fixed polynomial its fixed claim reads), and `is_node`, the child's scale, is zero when `q` is the first level (whose carried fixed claims it zeroes) and one at every node (in the small tier a product of zeros and ones plus one, `Model.prod_zero_or_one`). `Model.limbRows` is the words' limbs `Design::node` gives the child's verifier (a `k_const 0`, then each word's `e_to_k`; word `i`'s limbs are its three outputs and the zero), and `Model.limbRows_good`: in every satisfying assignment the zero is zero and each word's three limbs are its own (`Model.LimbsBound`), the statement `checkedges` finds the verifier absorbing and reading (`Edges.InstCert`). `Model.nodeRows` is `Design::node` with what stays transcription abstract: per child, the statement's words (`free_e`), the kind rows, the limbs, then `rest`, the child's other rows (`RecShape::verify` past the statement it is given, `bind_state`, its fixed and carried claims, its digest), and after the children `tail` (the union or digest rows, the reduction, the statement's exposure). `Model.nodeRows_good`: for every accepted shape and every node position, if every `rest` and `tail` keeps the builder's invariant (`Model.Good`, true of any sequence of the model's methods naming wires already made, `Model.replay_sound`), then in every assignment satisfying the circuit every one of its `Shape.children` children is bound as `Model.kindRows_good` and `Model.limbRows_good` say (`Model.ChildBound`).

## Recursion transcript binding

`lake exe checkbind <files>` checks that every test of a recursion circuit (an equality made outside the builder's methods that reads a challenge) reads only wires the transcript fixes before the challenge's prover could choose them. It replays the dump through the builder model, takes the transcripts from the duplex's absorb and squeeze blocks, and builds determination rules over wire limbs, each carrying a justification `Bind.Just` naming a row, an equality or a public row of the circuit: a slot limb is its table's form of the columns it reads, a split word and its bits give each other, a constant mux bit picks a message word, a compression at a constant final word gives its output, `inv`'s product gives each factor from the other, and equalities that are not tests hold both ways. Collision resistance gives a compression's inputs from its output and a chaining value from a window of its output stream. A marked union product (`Builder::mark` around `union::PoolShape::rows` and `union::product`) is a function of its pool's digests, begin and selection bits and its point. A worklist binds each transcript's absorbed words and the statement, and records the rules it fires.

The verdict is `Bind.Cert.accepts` of that record: every rule's justification checks against the circuit (`Bind.rulesOk`), each transcript is a chain of compressions from a constant, and for every test some transcript's replay of its firings (`Bind.certifyT`) gives all limbs of both wires a binding time: the number of the transcript's blocks they need, one more than their number if they need the statement. `Bind.tests_by`: a passing certificate puts each test's limbs, at its binding time `k`, in the closure of what the transcript's first `k` blocks absorb, and of the statement only once `k` passes its last block; `Bind.checkbind_sound` is its weaker form with all the transcript's blocks and the statement. `Bind.Just.valid` and `Bind.rules_valid`, for rules reading no hash row a predicate `drop` names: on two assignments satisfying every constraint but the tests and those rows (`Bind.HoldsP`), a justified rule is valid, given the explicit premises `HashCRP` (two hash rows `drop` does not name, given the same output ports, one by each assignment, are given the same input ports), `WindowCRP` (a window of four consecutive output words of two such rows of one chaining value fixes that chaining value) and `UnionsValid` (a union product is a function of its inputs). The verdict's rules drop no row (`Bind.HoldsP` is then `Bind.Holds` with `HashCR` and `WindowCR`, `Bind.Holds.toP`). `Bind.tests_determined` composes them with `Bind.unionsValid`, which proves `UnionsValid` from the rows, so its only premises are `HashCR` and `WindowCR`: each test's wires are a function of what one transcript's first `k` blocks absorb and the challenges drawn before `k`, `k` its binding time, and of the statement only past the last block. A test bound after its latest challenge (a round-by-round sumcheck check, bound once the next round's message is absorbed) is thus a function of the blocks before the next challenge, and the test bound only with the statement is the one whose binding time passes its transcript's last block.

Squeezes are the random oracle. Each transcript seeds its challenges (`Bind.chalSeeds`): a squeeze's output at one more than the number of blocks its chaining value needs, so a challenge is a seed of what is absorbed after it and not of the round that draws it. Each transcript also carries its own rule set, `Bind.Transcript.rulesRO` with its own firings, its random-oracle view: no rule reads a hash row writing one of the transcript's own absorb blocks' or squeezes' outputs (`Bind.dropOf`): not its compression, its collision resistance, its mux, its forms or the output windows. The other transcripts' rows keep their rules, so a reduction's input claims, read from a child proof's transcript and bound through that transcript's digest (its squeeze rows' output windows and collision resistance), stay bound in the reduction's view. The verdict checks both rule sets; the tests' binding (`Bind.tests_by`, `Bind.tests_determined`, the unions) uses the first, the round certificates (`Bind.Cert.sumchecksOk`, `Bind.Cert.oddsOk`, `Bind.Cert.lateOk`) each transcript's second (`Bind.Cert.marksRO`). The theorems over the prover's answers to many challenges take them in the view of the transcript drawing them (`Bind.RomAnswers c s T`: every constraint and replayed call but the tests and transcript `T`'s own compressions, `Bind.HoldsP` dropping `Bind.dropOf` and `Bind.Facts` every squeeze, with collision resistance away from `T`'s rows); an accepted circuit's assignments holding every constraint but the tests are such answers for every transcript (`Bind.RomAnswers.of_holds`).

The union's rows are read off the dump's calls. The certificate names where each pool and product's calls are, call for call as `union::PoolShape::rows` and `union::product` make them (`Bind.PoolCert`, `Bind.ProdCert`), and `Bind.Cert.unionsOk` checks them against a replay that relaxes the tests' equalities (`Model.replayR`) and builds the circuit without its tests, so `Model.replayR_sound` gives every other call's contract in an assignment satisfying `Bind.Holds`. `Bind.PoolCert.pool_sem`: a pool's values satisfy `PoolParse.Sem` (kind bits packed, so bits; the counter word spells the start and kind bits; padding follows an end; a run's end outputs its digest). `PoolParse.parse_unique` and `Bind.PoolCert.pool_unique`: two assignments agreeing on the digests and begin bits, under `HashCR`, give every item the same kind bits and every item but padding the same block, by following each run's chain back from its end to its start bit. `Bind.prod_agree` and `Bind.claim_valid`: the product is then the same, padding's factors being one.

`LeanVMCircuits.Rec.UnionSound` proves the coverage check. `slots_eq`: with Boolean bits, a side's product of `1 + on · (X + 1 + fp_A(t))` is `∏ (X + fp_A(t))` over its claims that are on, `fp_A(t) = ∑_k eq(A, k) t_k`. `poly_injective`: that product, as a polynomial in `(X, A)`, determines the multiset. `coverage_sound` and `union_coverage_sound`: if the selected child claims and the declared claims are different multisets, the two sides' products agree on at most a `4N/|S|` fraction of the points of `S^5`, each side at most `N` slots. `chain_unique`: two chains of compressions from one chaining value with the start marker on their first block only that end in one digest are the same chain, unless two of their compressions collide.

`LeanVMCircuits.Rec.UnionCover` states the coverage check on the circuit. `Bind.point_sem`: the point's calls (`Bind.PointCert`, checked in `Bind.Cert.unionsOk`) make `X + 1` and the weights `eq(A, k)`. `Bind.prod_closed` and `Bind.prod_slotsAt`: a product is `UnionSound.slotsAt` of its pool's slots, each slot's bit its selection bit times its validity and its tuple `(1, label[0..6], member[0..4])`, the label its run's last header (zero before any); `Bind.slots_bits`: the bits are bits. `Bind.slots_agree`: two assignments agreeing on a pool's digests, begin and selection bits, under `HashCR`, have the same claims on. `Bind.union_cover`: if in one assignment holding every constraint but the tests the two pools' claims on are different multisets, the points of `S^5` at which some assignment with the same digests, begin and selection bits, whose compressions do not collide with the first's, holds every constraint but the tests and the coverage test are at most a `4N/|S|` fraction, `N` the larger pool's slots. Its premises are collision resistance and the point's distribution; that the point is squeezed after the pools' digests, begin and selection bits are absorbed is `Bind.tests_determined`.

`Bind.union_sound` is the union's theorem on an accepted circuit, with collision resistance and the challenge's distribution as its only premises. The certificate names each union's coverage test, its two products and the transcript drawing its point (`Bind.Cover`), and `Bind.Cert.coversOk` (part of the verdict) checks the test's wires are the products' outputs, both products read one point, every product has an entry, the transcript's marks cover what both pools commit to (`Bind.PoolCert.committed`: digests, begin bits, selection words), the declared pool has one digest and does not select, and the children's pool's run one-hot closes at its last digest (`Bind.PoolCert.endOk`, the closing `eq_e_const` checks of `union::PoolShape::rows`). Fix what the transcript absorbs by an assignment `val₀` holding every constraint but the tests, in which the selected child claims and the declared claims are different multisets, and let the point be uniform on `S^5` over outcomes `Ω`. If at each outcome the prover answers with an assignment holding every constraint but the tests, absorbing the same words, under `HashCR` and `WindowCR` against `val₀`, the outcomes at which its point is the challenge and the coverage test holds are at most a `4N/|S|` fraction.

All twenty-three marked dumps pass. `fixtures/pre626-claimset-two-tier-circuit-1.txt.xz` is a two-tier node circuit from before the union absorbed its begin bits (#626): its coverage test is unbound, and CI checks that `checkbind --expect-unbound` still rejects it.

Which equalities are tests is part of the verdict: `Bind.taintOk` replays the calls marking each wire that reads a challenge (`Bind.taintStep`: a squeeze's output, or a wire a call makes from one, but a constant), and `Bind.tests_cover` proves that in an accepted certificate no field equality the circuit keeps as a constraint reads such a wire. Digest equalities and the equality inside `inv` are constraints however they are made. The classification is not a premise of these theorems' soundness: each is stated for the assignments satisfying `Bind.Holds`, every constraint but the tests, and `Bind.Sat.holds` gives `Bind.Holds` from `Model.Sat` whatever the classification, so every assignment an accepting proof can have is among them. A wrong classification can only make an equality that reads a challenge a constraint, whose probability no theorem then bounds; `Bind.tests_cover` excludes that.

`LeanVMCircuits.Rec.PoolClaims` reads the multisets as the sets the digests name. A claim set is written as blocks (`PoolClaims.ClaimSet.blocks`, `ClaimSet::items`) and its digest is their chain of compressions from the parameter IV (`PoolClaims.ClaimSet.digest`, with `PoolClaims.blakeF` the compression a `block` call's row computes); `PoolClaims.ChainCR` says no pool row's compression collides with one of the chain's. `PoolClaims.run_reads`: a run whose expected digest is a chain's last output reads the chain's blocks item for item. `PoolClaims.readC_blocks` and `PoolClaims.reads_sum`: the pool's items read the sum of the claims of the sets its runs name. `Bind.pool_claims`: on a pool's rows the claims on are at most that sum, and that sum when the pool does not select. `Bind.cur_runAt`: the run one-hot of a chunk is at the number of begin bits set so far, so under `PoolCert.endOk` every run is a digest's and two runs are two digests'. `Bind.decl_claims`: the declared pool's claims on are the claims of the set its digest names; `Bind.sel_claims`: the children's pool's claims on are among the sum of the sets theirs name. `Bind.union_sound_sets` (through `Bind.sets_differ`): `Bind.union_sound` with the premise that, in `val₀`, the union's digests name sets (`Bind.SetsNamed`) and the declared set's claims are not among the children's.

`LeanVMCircuits.Rec.Composition` is the union bound over the transcripts a prover can try. `Bind.union_sound_queries`: a prover making `Q` queries, each absorbing what its own `val₀ q` gives the transcript and drawing a point uniform on `S^5`, and answering with the query it picks, passes the coverage test at its query's point for at most a `Q · 4N/|S|` fraction of the outcomes; the points need not be independent. `Bind.union_sound_sets_queries` is the same with each query's multisets read as the named sets.

`LeanVMCircuits.Rec.Sumcheck` is sumcheck's round-by-round soundness at the protocol level. An instance's truths (`Sumcheck.Inst`: each round's eq weight when factored out, the honest round polynomials of degree at most `d`, each challenge's instance summing to the honest polynomial at it, and the final value), a prover answering each round with a polynomial of degree at most `d` that may depend on the challenges so far, and the verifier's checks (`Sumcheck.accepts`: each polynomial passes the round's check against the running claim, `Sumcheck.lin`, `g(0) + g(1)` or `(1 - e) · g(0) + e · g(1)` with the eq weight `e` factored out; the next claim is it at the challenge; the last claim is the final value). `Sumcheck.sumcheck_sound`: if the claim is not the instance's sum, the verifier accepts at at most `n · d · |S|^(n-1)` challenge vectors of `S^n`; `Sumcheck.sumcheck_sound_frac`: an `n · d / |S|` fraction. `Sumcheck.sumcheck_sound_fun` is the same bound for a prover given by its round polynomials at each challenge vector, round `i`'s reading only the challenges before it (`Sumcheck.PrefixDep`, `Sumcheck.accepts_ofFun`), and `Sumcheck.sumcheck_sound_on` counts only the vectors of a set `A`, the round polynomials reading only the challenges before them among those (`Sumcheck.PrefixDepOn`).

`LeanVMCircuits.Rec.Rounds` and `LeanVMCircuits.Rec.RoundSound` link the circuit's late tests to their protocols. `LeanVMCircuits.Rec.AirLink` reduces the AIR link. A committed witness (`AirLink.Witness`) is a height and columns per table, the public table's four value columns included; its slots are every table's rows' slots up to the heights, padding included, keyed by `SlotKey::new` and carrying their table's limb forms. `AirLink.Claims` is what the AIR claims of it: each table's row count within its height and `2^32` (`RecLayout::new`), each row of the circuit satisfying its table (HASH's mux bit and compression, SPLIT's bits; EMUL, EXK and CAST have no identity, as Rust's `Table::identities`), the public columns carrying each public row's constant or statement word, and the bus balanced with each slot's `next` the next slot of its wire's class (`BusBalances`). `AirLink.sat_of_claims`: those claims give `Model.Sat` at the statement for the assignment reading each wire's limbs off the first slot of its class (`assign`); `claims_of_sat` is the converse for an honest witness, so the claims are satisfiable exactly when the circuit is, and `union_rejected`, `statement_rejected` and `emul_rejected` are circuits no witness meets. The bus is derived from its GKR root claim: `bus_of_product` gives the balance from the two products' agreement at a draw off `busDraws`, which `bus_event` and `busDraws_card` bound by `4 · slots / |E|` (`bus_balance_sound`), and `busBad_frac` bounds the outcomes whose draw is in it when the draw is uniform after the commitment. What remains is `AirLink.ChecksGiveRows`: off the checks' events, the crBad event and the constraint batch's event `batchBad` (left abstract), true check inputs give the rows' claims and the products' agreement; `hair_of_air` derives `hair` from it and `tree_sound_air` is `tree_sound_parts` with it, each child's bound gaining `batchBad` and `busBad`. Rust exposes the statement's public rows first (`statement_first`) and the model keeps build order; `Sat` reads the public rows as a set, so the order does not matter as long as each statement word is exposed once at its own index. `LeanVMCircuits.Rec.TreeBound` puts the bounds together: `AirLink.tree_sound_bound` is `tree_sound_air` with each event's fraction replaced by its bound, `epsPCS v + epsCR v + epsBus v + epsBatch v` per child beside its reduction's and checks' events; `AirLink.tree_sound_crEvent` takes `crBad` to be the ideal compression model's `Edges.crEvent`, bounded by `Edges.epsCR` of the child's query count, and `AirLink.tree_sound_ideal` also bounds the bus by `4 · slots / |E|` for a draw uniform after the commitment. `epsPCS` (`Edges.PcsBound`) and `epsBatch` stay premises there. `LeanVMCircuits.Rec.AirBatch` bounds the constraint batch: as `TableArgument::verify` and `constraints::verify` check it, at the bus's point `ζ` and a challenge `ξ`, the bus forms' sums plus `Σ_j ξ^(2+j) C_j(ζ)` vanish, `C_j(ζ)` identity `j`'s values (66 over HASH and SPLIT) weighted by `eq(ζ, row)` (`AirLink.BatchClaim`). If some row breaks an identity, the draws at which the claim still holds are at most `(n + 67)/|E|` (`batchDraws_card`: Schwartz-Zippel in `ζ` for the nonzero identity's extension, then the roots in `ξ`), and `batchBad_frac` bounds the outcomes whose draw is among them; with the hash rows' flock witnesses (`Flocked`) and no broken identity every row satisfies its table (`tables_of`). The remaining premise becomes `AirLink.ChecksGiveBatch` (true check inputs give the row counts, the public columns, the flock witnesses, the batch claim and the products' agreement at their draws), and `tree_sound_batch` and `tree_sound_ideal_batch` are the bounds with `epsBatch v = (n v + 67)/|E|`; the draws are taken uniform after the commitment, as lenses, not the prover's adaptive Fiat-Shamir draws. `AirLink.checksGiveBatch_of_inst` reduces it to `AirLink.ChecksGiveInst`, in which the table sumcheck's and bus GKR's honest instances are the committed witness's: the table sumcheck's input claim, the bus totals' `σ_0 + ξ σ_1`, is the committed witness's honest sum `AirLink.tableSum` (the bus forms' weighted sums and `Σ_j ξ^(2+j) C_j(ζ)`), which is the batch claim with bus parts the forms' sums less the totals (`AirLink.batchClaim_of_sum`), and the bus GKR's root claims are its honest roots `AirLink.pullRoot` and `AirLink.pushRoot`, held equal by `bus::verify_balance`, which is the product claim (`AirLink.productClaim_iff`).

`LeanVMCircuits.Rec.AirRun` replaces the lenses by the prover's Fiat-Shamir draws. A value committed before time `k` of a run (`Bind.CommittedBefore`) is a function of what the transcript absorbs before `k`, the commitment among it; `Bind.Run.committed_at` makes it fixed across the challenge vectors put in at an oracle when every challenge is drawn at `k` or later, and `Bind.draws_not_fixed` is the mutation: the draws themselves are not. The round theorems take their honest instances as such values: `Bind.sumcheck_run_sound_at`, `Bind.whir_run_sound_at`, `Bind.odd_run_sound_at` and `Bind.top_run_sound_at` take the instance, the hints' true values and the true children as functions of the oracle fixed before the check's challenges (`Bind.Run.sumcheck_committed` and the like give that for anything committed before them, `Bind.CommittedBefore.comp` for what is computed from the committed witness). `AirLink.busRun_frac` and `AirLink.batchRun_frac`: where the bus's five and the batch's `n + 1` challenges are a run's, drawn after the committed witness and the bus parts, the oracles at which the draw is in the witness's draw event are at most `4N/|E|` and `(n + 66 + 1)/|E|`, the prover adaptive. `AirLink.tree_sound_run` is `tree_sound_batch` over a uniform oracle with each child's draws so drawn (`AirLink.DrawsRun`), with no lens premise.

`LeanVMCircuits.Rec.TableSum` models the table sumcheck over tables of different heights as a `Sumcheck.Inst`. `Sumcheck.mvInst` is the honest instance of a polynomial on the Boolean cube, binding its first variable first with no eq weight factored out (`mvInst_sum`, `mvInst_ok`, `mvInst_final`, `mvInst_weight`). `constraints::verify` runs `n` rounds, `n` the tallest table's `τ`, binding the variables from the highest down; a table is active in the rounds of its own variables, where its weight takes `1 + ζ_m + r`, and sits out the others, where it takes `r`. So table `T` is `AirLink.cornerEq ζ τ_T` (`eq(ζ_j, x_j)` on its own variables, `x_j` on those it sits out) times its summand (`AirLink.summandPoly`, `TableSummand::batch`: its push form, `ξ` times its pull form, identity `j` of `allIds` at `ξ^(2 + j)`, each a quadratic form `AirLink.Quad`) on its columns' multilinear extensions (`AirLink.mle`), and `AirLink.tableInst` is `mvInst` of the owned tables' sum with the variables reversed, so round `j` binds Rust's `chi[n - 1 - j]`. `AirLink.tableInst_sum`: where every `τ` is at most `n`, the instance's sum is `AirLink.tableSum` at the forms' honest sums (`AirLink.formSums`), each table summing its own rows, the variables it sits out summing to their corner (`AirLink.corner_sum`). `tableInst_ok` gives it degree `d` for `d ≥ 3`, `tableInst_final` its final value (each table's weight as the verifier folds it, `AirLink.foldWeight` and `foldWeight_eq`, times its summand at its columns' extensions at `chi`), and `tableInst_weight` no eq weight in any round (`v.read_round(4, claim, None)`). The committed witness is taken at a layout (`AirLink.committedAt`: each table at `2^τ_T` rows, the public table's columns the verifier's at the statement), and `AirLink.ChecksGiveTable` asks for the hash rows' packed witnesses, the table sumcheck's input claim being `tableInst`'s sum and the bus GKR's roots being the witness's honest roots; `checksGiveInst_of_table` gives `ChecksGiveInst` from it where the layout holds the child's rows within `MAX_TAU` (`AirLink.LayoutFits`) and every owned table's `τ` is at most the rounds, and `checksGiveRows_of_table` gives `ChecksGiveRows`, the premise of `AirLink.tree_sound_end`. `checkbind` names each residual sumcheck as a table sumcheck (`Bind.TableCert`, checked by `TableCert.ok` and required for every residual): its rounds read no eq weight, its input claim is the `mul_add` of the bus totals at `ξ`, and a GKR first layer made before it reads one root as both trees' value. All twenty-three marked dumps name one per residual. `TableCert.sem`, `TableCert.answers_weight` and `TableCert.claim_iff`: where the calls hold, the named check's input claim is the named totals' `σ_0 + ξ σ_1`, so `ChecksGiveTable`'s table conjunct with the totals and `ξ` read off the certificate is the named sumcheck's input claim being its honest instance's sum; its rounds meet `SumcheckAnswers`' eq-weight field for `tableInst`; and the two roots are one wire.

`LeanVMCircuits.Rec.TableResid` certifies the table sumcheck's residual term by term (`Bind.ResidCert`, checked by `ResidCert.okIn` and required by `checkbind` for every table sumcheck). Each of its five terms, in `Table::OWNED`'s order, names its weight's calls (from a `one`, round `j` a `mul_add(w, add(ζ_m, r_j), w)` where the table is active, `τ > m = n - 1 - j`, and a `mul(w, r_j)` where it sits out), its column claims, its push and pull forms at them (`BusForm::at`: a `mul_add(coeff, col, acc)` per linear term from the form's constant, then a `mul` and a `mul_add` per product term), their `mul_add(ξ, pull, push)`, and its identities in `AirLink.allIds`' order (`BusForm::at_constants`: an `e_const 0`, then a `mul_const_add` per term with the model's words), each added at `ξ^(2 + j)`, the powers `TableResidual::batch` makes from a `one` by `mul(p, ξ)`. `ResidCert.sem`: where the calls hold, the residual terms sum to `Σ_T foldWeight ζ τ_T r · summandAt forms ξ T col_T` at the named point, `τ`s, forms and column claims. `ResidCert.final_eq`: where the named point is `ζ`, each named `τ` the committed witness's, the named forms `forms` and each table's named column claims its columns' extensions at `chi r`, that sum is `tableInst`'s final value (`tableInst_final`), so the named sumcheck's test is `sumcheckEvent`'s at the honest instance. Mutation tests reject a weight read with another `τ`, an identity with another word or read as another table's, identities out of order, a form reading another column and a power not the previous one's times `ξ`. On every marked dump each table sumcheck's residual is named so.

`LeanVMCircuits.Rec.BusDecompose` models `bus::verify_balance`'s decomposition of a side's leaf claim (`Side::decompose`). A side is a layer of `2^μ` leaves: block `b` of `2^κ_b` rows at place `q_b` among the blocks of its height, every other leaf padding (`1`). `AirLink.leaf_decompose`: the leaf claim `Σ_x eq(ζ, x) L(x)` is `Σ_b sel_b Σ_z eq(ζ[..κ_b], z) leaf_b(z) + (1 - Σ_b sel_b)`, the selector `sel_b = eq_bits(q_b, ζ[κ_b..])` (`AirLink.sel`, `rowEq_block`, `sum_rowEq`). A table's block carries `β + Σ_i w_i c_i(z)` over its row's coordinates (`AirLink.DCoord`: a constant, a column, a product, a scaled column, or a virtual `IntIndex` or `Public` coordinate the verifier evaluates itself; a `Sum`'s children are terms at its weight), so its part is its form (`AirLink.blockQuad`, `BusForm::accumulate`) summed over its rows plus its virtual coordinates' share (`AirLink.blockKnown`, `block_sum`). `AirLink.side_decompose`: the leaf claim is the side's framework part (`AirLink.framework`: the framework blocks' leaves at `ζ`, the tables' virtual coordinates and the padding mass) plus each table's form (`AirLink.sideForm`, its blocks' forms at their selectors) summed over its rows against `eq(ζ[..τ_T], z)`. `AirLink.totals_eq` and `totals_eq_formSums`: the totals `bus::verify_balance` derives, `framework + Ṽ(ζ)`, are the forms' sums (`formSums`), the framework part cancelling in characteristic two. `AirLink.tableClaim_of_leaves`: with both sides' totals so, the table sumcheck over the bus point's first `N` coordinates, every owned table's `τ` at most `N` and no row breaking an identity, the totals' `σ_0 + ξ σ_1` is `tableInst`'s sum at those forms: `ChecksGiveTable`'s table conjunct from true leaf claims.

`LeanVMCircuits.Rec.GkrInst` models the bus GKR's layers. `Sumcheck.eqInst` is the honest instance of `Σ_x eq(p, x) · P(x)` with each round's eq weight `p_i` factored out, as `v.read_round(5, claim, Some(eq_point))` reads it (`eqInst_sum`, `eqInst_ok`, `eqInst_final`, `eqInst_weight`). A product tree's node `k` levels above its leaves (padded with ones) is the product of its `2^k` leaves (`AirLink.level`): the product of its four children two levels down (`level_four`) or its two children one level down (`level_two`), the root the product of all leaves (`level_root`); `AirLink.pullRoot_eq_level` and `pushRoot_eq_level` make the bus's honest roots its trees' roots over the slots' `β + fp_A(t)` (`AirLink.treeLeaf`). `gkr::verify_products`' radix-four layer at a point `p` and `λ` runs one sumcheck of `Σ_t λ^t Ṽ_t(p)` (`AirLink.mleAt`); `AirLink.layerInst` is its honest instance: its sum is the claim at the honest level values (`layerInst_sum`, `layerInst_sum_level` on a product tree), it has degree `4` (`layerInst_ok`), round `i` factors out `p_i` (`layerInst_weight`), and its final value is `poly_eval(products, λ)` of the children's honest values at the challenges (`layerInst_final`, `AirLink.childMle`). `AirLink.next_claim`: the layer's next claim, `interp(interp(a, b, low), interp(c, d, low), high)` of those children, is the level below's value at `[low, high] ++ r`, the next layer's point, and `odd_next` is the odd layer's line through its two children, so the honest values carry from the root (`mleAt_zero`) to the leaves layer by layer.

`checkbind` names each table sumcheck's bus GKR from its root to its totals (`Bind.GkrCert`, checked by `GkrCert.ok` and required for every table sumcheck): its first layer, a top or odd layer reading the root as both trees' value; then its radix-four layers past the top (`Bind.LayerCert`), each a certified sumcheck with no residual whose input claim is the layer's claim over the previous layer's next claims, whose final side is the layer's expected product of its children, whose rounds' eq weights are the previous layer's point (`[low, high]` and its rounds' challenges, `[r]` past an odd layer) and whose next claims are a top layer's lines (`LayerCert.chain`); and each total the `add` of a framework share and the last layer's next claim (`totals[s] = framework + values[s]`). `GkrCert.sem`, `LayerCert.link_sem` and `LayerCert.chain_cons` read a passing certificate where the calls hold, and `GkrCert.okIn`'s and `LayerCert.linkOk`'s mutation tests reject totals reading another wire, a first layer reading two roots, a round with another eq weight and a layer over other values. On every marked dump each table sumcheck's GKR is named so, over all its layers.

`LeanVMCircuits.Rec.GkrParts` makes each radix-four layer past the top a check of `RecParts`. `Bind.layer_part`: where the parent's circuit holds a linked layer's calls and its sumcheck's test, its next claims true (each tree's level below at `[low, high] ++ r`) make its values, the previous layer's next claims, true (each tree's level at the previous point), off its sumcheck's event against `AirLink.layerInst` (`sumcheckFalse`, bounded by `sumcheck_run_sound_at`), the line event `LineBad` (at most `2|S|` of the pairs `(low, high)`, `lineBad_card`) and the `λ` event `LamBad` (at most one `λ`, `lamBad_card`). `checkbind` asks each layer to draw its challenges as a top layer's (`LayerCert.chalOk`, `GkrCert.layersOk`: `λ`, `low`, `high` in order from its transcript, its children bound by `low`'s time, `LayerCert.boundOk`, and its values by `λ`'s time with the words squeezed with `λ` but its own as seeds, `LayerCert.lamOk`: the sibling-word argument of WHIR's batch rounds, as the values read the previous layer's `high`, squeezed from the chaining value `λ` is squeezed from; both with mutation tests), and `Bind.layer_run_sound_at` bounds the line and `λ` events together over a run by `3 / |E|` of the oracles off the run's collision event, the true values and children fixed before the layer's challenges (the values fixed across `λ` at each `(low, high)`, `Run.sib_agree`, so at most one `λ` each; the children fixed across `(low, high)` at each `λ`, so at most `2|E|` pairs each); `LayerCert.chal_eval` makes the challenge wires `layer_part` reads the oracle's.

`LeanVMCircuits.Rec.GkrChain` chains the bus GKR's checks from the root to the leaves on the named certificates. Stage `0` is the first layer's values (the root), stage `1` its next claims and stage `k + 2` layer `k`'s (`Bind.GkrCert.outsAt`); stage `k`'s point is where its values are claimed, as wires (`GkrCert.ptAt`) and as the oracle's challenges (`GkrCert.ptR`); `LayerCert.chain_at` links each layer of a passing chain to its stage, and `GkrCert.ptAt_ev` reads every stage's point wires as the oracle's challenges (`chal_readR`, each challenge's wire its own words where the transcript's squeezes answer the oracle). `top_step`, `odd_step` and `layer_step` (`top_part`, `odd_part`, `layer_part`) make stage `k`'s values each tree's level at stage `k`'s point from stage `k + 1`'s, and at the last point the level of the sides' stacked leaves is their leaf claim (`SideCert.leafClaim_mleL`). `LayerCert.linkOk` also asks each layer's sumcheck to read no hints (its input claim is the previous next claims, bound by `λ`'s time), with a mutation test. `Edges.ChildCerts.layer_ok` and `ChildCerts.leaves` (in `Flocked`) instantiate them on a child's certificates.

`LeanVMCircuits.Rec.Heights` discharges the layout's hypotheses for a tree `Tree::new` built. `Tree::converge` (`Design.converge`) rebuilds the circuits at the tiers' heights until none passes its tier's, each round requiring `RecLayout::from_taus` to accept them (`fitsTaus`: every `τ` at most `MAX_TAU = 32`), then raises each circuit's floor to its tier's heights; a node reads a child of tier `t` at `σ t` (`RecShape::new`). `AirLink.layoutFits_converge`: every circuit `converge` returns, its heights holding its rows (`HeightsHold`, least at the rows' `clog 2`: `heightsHold_clog`), fits its tier's layout (`LayoutFits`, via `Design.converge_fits`). `constraints::verify` runs the tallest owned table's `τ` rounds (`AirLink.rounds`), so every owned table's `τ` is at most them (`taus_le_rounds`); the public table is in no summand, so `tableInst_sum` asks it of the owned tables only. `AirLink.checksGiveRows_of_converge` is `checksGiveRows_of_table` with both hypotheses replaced by those facts. A one-tier example converges in the kernel.

`LeanVMCircuits.Rec.Named` reads `ChecksGiveTable` off the checks `checkbind` names. `AirLink.checksGiveTable_of_named`: where child `v`'s parent accepts its certificate and names the table sumcheck (`Bind.TableCert.ok`), `ChecksGiveTable` holds with the totals, the root and `ξ` the named wires' values, given three checks' inputs as `RecParts.inOk`: the named sumcheck's input claim being its honest instance `tableInst`'s sum on the committed witness, the named root being both trees' honest roots (the bus GKR's first layer), and the hash rows' packed witnesses (`Flocked`, flock's reduction). The parent's satisfied circuit gives the certificate's facts (`Bind.Sat.holds`, `Bind.facts_of_holds`), and `TableCert.claim_iff` reads the named input claim as the totals' `σ_0 + ξ σ_1`. `named_inputs`: parts whose three inputs are those claims meet the hypotheses.

`LeanVMCircuits.Rec.TableChain` lays the checks from the bus GKR's root to the opening as `RecParts`. `Edges.tableParts`: the GKR's layers from the root (each one's outputs the next one's values, the last one's the leaf claims), the balance, the table sumcheck and flock's reduction, whose outputs are openings. `Edges.tableParts_ok`: they meet `RecParts.Ok` where each check's test holds off its event and the openings off `pcsBad`; `Edges.checksGiveTable_of_parts`: their named inputs give `ChecksGiveTable` (`checksGiveTable_of_named`). The balance is new: `bus::verify_balance` derives the totals `tot_s = fw_s + v_s` from the leaf claims `v_s` and the framework parts `fw_s`, and the table sumcheck checks `tot_0 + ξ tot_1`. `AirLink.balance_part` and `balance_of_inst`: where the framework parts plus the true leaf claims are the forms' sums (`totals_eq_formSums`), the table sumcheck's input claim true makes each leaf claim true off the balance's event `balDraws`, the bus parts (the forms' sums less the totals) nonzero yet the batch claim holding. `Bind.balance_named` states it on the named certificates: where the calls hold and the table sumcheck and its bus GKR pass (`TableCert`, `GkrCert`), the GKR's two last next claims are the true leaf claims. With a nonzero constant or linear coefficient the batch claim has at most `66 + 1` roots in `ξ` (`xi_roots_low`), so the event is at most `(66 + 1)/|E|` of the draws (`balDraws_card`), of the outcomes under the batch's lens (`balBad_frac`) and of a run's oracles where the draw `(ζ, ξ)` is drawn after the witness and the bus parts' dependence on `ζ` (`balRun_frac`, `batchRun_frac`'s premises). `Bind.table_part`: where the residual is certified (`ResidCert.okIn`), its last side tested against a zero, its hints true and its column claims the committed columns' extensions at `chi r`, the table sumcheck's input claim is its honest instance's sum off `sumcheckFalse` (`sumcheck_part` with `ResidCert.final_eq`). Each layer's test is `Bind.layer_part`'s (`top_part` or `odd_part` for the first).

`Circuit::heights` is transcribed (`AirLink.circuitHeights`, from `Table::height_log`: `log2Ceil` of the rows, `log2_ceil_usize`, and for the hash table the larger of `minBlocksLog`, `min_n_blocks_log`, and flock's floor), and `AirLink.heightsHold_circuit` proves it holds the rows; `rec::table::tests::a_tables_height_is_the_proven_transcription_and_holds_its_rows` compares the transcription with `height_log`. `AirLink.checksGiveRows_of_tree` is `checksGiveRows_of_converge` at those heights, `HeightsHold` discharged. Its building facts stay premises; `rec::tree::tests::every_circuit_is_at_its_tiers_converged_heights_which_hold_its_rows` and the two-tier tree's test check that each circuit `Tree::converge` returns has its tier's heights, at which a node reads its children, holding its rows.

`LeanVMCircuits.Rec.Tries` is the union bound over transcripts a prover tries. An outcome is an oracle per try on its transcript's words with the compression oracle they share; try `i`'s event may read every try's oracle. `Bind.frac_fix_le`: an event at most an `ε` fraction of try `i`'s oracle and the compression oracle at every value of the other tries' oracles is at most an `ε` fraction of all outcomes (with the others fixed as whole functions try `i` is an oracle algorithm on its own oracle, the setting of `Bind.Run` and `AirLink.tree_sound_end`). `Bind.frac_pick_le`: whichever try the prover outputs, the output try's event is at most the sum of the tries' bounds, `frac_pick_le_mul` `m · ε`; `bitPick_frac` is an example meeting it. `Edges.tries_bound_deployed`: with each try's failure within `tree_sound_end`'s bound at `tree_bound_deployed`'s sizes at every value of the other tries' oracles, the output try fails on at most an `m / 2^19` fraction with #551 budgets `2^20` per binding shape and `m / 2^7` with `2^32`, `Q` counting every compression query the prover makes.

Still assumed for the edges: the recursive verifier's soundness (`hrec`: a child's circuit is satisfied at the statement its parent's verifier reads, which is where acceptance giving `Model.Sat` enters); that the marked claims are the ones the reduction reduces (within `hstep`, which `Bind.sumcheck_test_sound` bounds); what a claim's truth is (`tD`, `tM`: the polynomials' and matrices' values at the outcome); that a child's scale is the model's `is_node` beyond the twenty-three dumps (Rust's `Design::kind_bits` being `Model.kindRows`, which `checkdesign` checks on the dumps; `Model.kindRows_good` proves `is_node` zero at the first level and one at every node for every accepted shape, and `checkedges` also checks each dump's scale is computed in its tier's mode, `DesignClaims.modeOk`, under which `Edges.nodeScale` is so, `DesignClaims.tierMode_scale`); that a wrap's and a tree of outputs' node's statement digest is its child's and its children's tree digest beyond the twenty-three dumps, on which `checkedges` checks it (`Edges.DigestCert`); and that a claim-set node's digest is the union's digest of the digest wires it reads.

`LeanVMCircuits.Rec.FlockInst`, `FlockZero`, `FlockLin` and `RingSwitch` model flock's reduction over the hash rows: the zerocheck's honest instance over the packed tables with the skip domain on the circuit's constant words (`Flock.zeroInst`, `phat`, `lagS`), the lincheck's (`FlockLin.linInst`), the ring switch's map `Φ` and Annex A's bound (`RingSwitch.ring_switch_sound`: a wrong slice vector meets the honest target at at most `phiDeg · |E|^5` of the map draws), each with a certificate of its calls (`Bind.ZeroCert`, `Bind.LinCert`, `Bind.RingCert`) and its part (`zero_part`, `zero_rows`, `lin_part`, `lin_triple`, `RingCert.sound`). `LeanVMCircuits.Rec.Flocked` names the whole reduction on a replay (`Bind.FlockCert`: the three certificates and the lincheck's Lagrange weights `Bind.LagCert`, linked), which `checkbind` asks for every named table sumcheck on its transcript, and composes it: `Flocked.quirky_a`, `quirky_b`, `quirky_c` make the zerocheck's triple the lincheck's `u^T A_0 Z`, `u^T B_0 Z`, `u^T Z` at the split point, `ring_slice` makes the ring switch's slice the lincheck's, `Bind.flock_rows` gives every block's rows and pin off the events (`skipRun_frac`, `fixRun_frac`, `ringRun_frac`, with `alphaRun_frac` and `pinRun_frac`, bound them over a run), and `Bind.flocked_of_rows` gives `AirLink.Flocked` with `HashGates`. `Bind.hashGates` proves `HashGates` of `Hash::circuit`'s rows for blocks of at least `2^14` bits: `LeanVMCircuits.Rec.HashRows` transcribes flock's `Builder` on the Clean artifact's steps (`flock::clean::blake2s` makes their calls in order, `Blake2s.Emit` with `Export.adder32_call` and `adder31_call`), a wire being the structural zero or its linear form over the slots, so a product with a structurally zero operand takes no slot, with `Hash::circuit`'s ports (`Builder::new(&INPUT_BITS, &[64; ### End-to-end composition

The target statement: for a recursion circuit whose dump replays to `s` with an accepted certificate `c` (`Bind.Cert.accepts c s`), and a proof of statement `st` that the native verifier accepts, except with probability at most `ε_PCS + ε_CR + Σ_u Q · 4N_u/|E| + ε_tests` over the verifier's challenges in the ideal compression model (`Q` the compression queries, `N_u` the larger pool's slots of union `u`), some assignment `val` satisfies `Model.Sat st s val`, and in it every union's declared claims are among its selected child claims. Its parts:

1. PCS (#551, #600). Each stacked opening the verifier checks is explained by one committed witness: list binding (`Whir.StackWHIRROM.rom_list_binding_numeric`, `Whir.InteractiveSoundness.adaptive_list_binding`) and the commitment anchor's uniqueness (`Whir.CommitmentAnchor.selected_unique`, `Whir.CommitmentAnchor.joint_opening_probability_numeric`) give `ε_PCS`. #600 makes the Rust callers bind each opening to its commitment record (`pcs::stack::StackCommitment::verify`); the link from the Rust verifier to the Lean model is finite differential tests, not a theorem.
2. The AIR tables' constraints, buses and public columns, true at the committed witness, give `Model.Sat st s val` for every configuration (`AirLink.sat_of_claims`), the bus from its products' agreement off `busDraws` (`AirLink.bus_of_product`). The identities from the constraint batch off `AirLink.batchDraws` (`AirLink.tables_of`, `batchDraws_card`). `AirLink.checksGiveBatch_of_inst`: the batch claim from the table sumcheck's input claim equal to the committed witness's honest sum (`AirLink.batchClaim_of_sum`) and the product claim from the bus GKR's roots equal to its honest roots and held equal; `AirLink.checksGiveInst_of_table`: that honest sum is the sum of the table sumcheck's honest instance over tables of different heights (`AirLink.tableInst_sum`), with the heights and public columns the layout's and the verifier's, and `Bind.TableCert` names the checks on the dumps; the honest roots are the bus trees' roots, carried to the leaves by the GKR layers' honest instances (`AirLink.pullRoot_eq_level`, `layerInst`, `next_claim`). Not proven: that the verifier's accepted checks' input claims are true on the committed witness, with the bus forms' decomposition and flock's reduction (`AirLink.ChecksGiveTable`).
3. This directory: `Bind.Sat.holds` gives `Bind.Holds` from `Model.Sat`; `Bind.union_sound_sets_queries` bounds each union's coverage test by `Q · 4N/|S|` over `Q` tried transcripts, with the multisets read as the sets the digests name, under `HashCR`, `WindowCR` and `PoolClaims.ChainCR`, whose failures `ε_CR` charges as #551's ideal-compression ledger does. 4. `ε_tests`: `Bind.sumcheck_test_sound` bounds each certified sumcheck test (the table sumcheck's residual included, where its hinted fixed-column claims are true) by `n · d / |E|` against the honest instance, `Bind.pow_test_sound` each proof-of-work check by `Q / 2^b`, `Bind.odd_test_sound` each GKR odd layer by `m / |E|`, `Bind.top_test_sound` each GKR radix-four top layer by `(m + 1) / |E|`, `Bind.whir_test_sound` each WHIR terminal test by `n · d / |E|` over all its rounds, `AirLink.balRun_frac` the bus balance by `(66 + 1) / |E|`, and `Bind.split_test_sound` makes each claim split exact; for a prover's run over a uniform oracle (`Bind.Run`), `Bind.sumcheck_run_sound_at`, `Bind.odd_run_sound_at`, `Bind.top_run_sound_at`, `Bind.whir_run_sound_at` and `Bind.pow_run_sound` state the same bounds as fractions of the oracles off the run's collision event; `Edges.tree_sound_certs_frac` carries the reductions' bounds over the tree with its edges checked by `checkedges`, each child's statement being the words its parent's verifier reads, adding each child's `badRec`. `Edges.tree_sound_parts` splits the recursive verifier's soundness at that statement (`hrec`) into the child's checks' events, `ε_PCS`, `ε_CR` and the AIR link of item 2, which is not proven; `AirLink.tree_sound_exec` states it per execution and `AirLink.tree_sound_end` with #551's bound as `ε_PCS`, `Edges.tree_bound_deployed` evaluating it at deployed sizes and `Edges.tries_bound_deployed` over several tried transcripts, an oracle per try.
