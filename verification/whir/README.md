# Executable WHIR model, binding and interactive extraction

This isolated Lean project models leanVM's binary-field interleaved WHIR variant, originally pinned to [`edafd396120f453de6f75013f231bfda2049f217`](https://github.com/leanEthereum/leanVM/tree/edafd396120f453de6f75013f231bfda2049f217) and integrated normally with upstream [`10266a181437019400bc93d8dfbb373301ba8aa5`](https://github.com/leanEthereum/leanVM/tree/10266a181437019400bc93d8dfbb373301ba8aa5). It contains the executable concrete prover/verifier, checked field/encoder mathematics, adaptive interactive list binding, immutable-anchor selection mathematics, an actual original-statement interactive reset extractor, and a proved adaptive ideal-compression duplex coupling. The duplex model matches the pre-#607 transcript at #552's `f11f84f585680cf10f676bb4d9ae1a67e26547ca`, not the newly deployed session and raw-byte transcript. The live Rust harness remains historical. Fresh Rust differential checks are separate implementation evidence. These results do not establish Fiat-Shamir knowledge soundness, universal current-source correspondence or unconditional concrete BLAKE2s security.

## Refinement of the actual executable kernels

The operational kernels are polymorphic over their minimal operations, and the concrete prover/verifier call those same definitions specialized to `Concrete.E`. Their array refinements are not a parallel mathematical reimplementation. The concrete ring and field instances are now derived from the exact bit-level operations and kernel-checked irreducibility proofs.

- `ArrayAlgebra.dot_eq_sum` and `roundMessage_eq_sum` prove that the actual array reductions and mutable message loop compute bounded finite sums, including their original min-length and default-index semantics.
- `message_eval`, `roundMessage_cube`, `foldLane_cube` and `honest_round_cube` connect those actual executable definitions to `compactRound`, `roundConstant`, `roundQuadratic`, `foldFirst` and the existing generic `honest_round`, with an explicit equivalence for the remaining Boolean coordinates.
- `honest_foldLane` and `honest_foldLow` prove actual round evaluation equals the dot product of the actual folded arrays, for every aligned shape and equal witness/weight lengths over any characteristic-two commutative ring. `dot_weightGlue` and `roundMessage_weightGlue` prove the actual batched target and intro message match the actual batched weight.
- `ArrayLayout` proves actual array rotation versus `Layout.terminalPoint`, actual `getD` padding and base-encoder leaf reversal versus the list specification, and exact low/top fold indices and lengths. Oversized `rotatePoint` inputs clamp because `Array.extract` clamps; list rotation wraps. The universal bridge uses `min k size`, while the direct protocol bridge states `k ≤ size`. Padding similarly records that a valid live prefix fits the padded width.
- `Protocol.verify` now calls `VerifierState.fold`, `batch` and `checkTerminal` for every algebraic transition. `ReplayRefinement.fold_preserves` and `batch_preserves` prove these exact functions maintain the interpreted array state. `trace_preserves` composes arbitrary numbers of those actual transitions, including block/level changes; `trace_terminal` proves that an honest trace ending in one witness scalar passes the actual Boolean terminal checker. The power-of-two specialization discharges the pairing-shape condition for the protocol's layouts.

`OperationalRefinement.verify_ok_iff` identifies successful execution of the actual nested verifier with its checked transition trace. `QueryRefinement` and `BatchingRefinement` discharge the actual authenticated-row/induced-weight identities; `TerminalRefinement` connects the actual residual MLE to successive array folds. The soundness proof follows adversarial, not just honest, executions through these same functions. A universal theorem that the full optimized Rust prover and verifier refine this Lean program is not claimed.


## Intentional differences from original WHIR

The implementation commits in K = GF(2^64), challenges in E = GF(2^192), and uses additive domains and the novel polynomial basis. The original multiplicative WHIR folding formulas cannot be copied into characteristic two. Quadratic messages contain only the constant and quadratic coefficient; the linear coefficient is reconstructed as `claim + quadratic`.

At the historical source pin there is no commitment-time OOD sample, following Flock, so its proved relation is list binding rather than unique binding. The separate #600 cutover adds the retained commitment-time anchor and binds every later opening to its complete identity. Subsequent OOD claims occur after new commitments. The protocol sends intro polynomials one message ahead; `CausalGame` and the checked history/replay modules preserve that schedule, including the invisible final tail challenge, without allowing strategies to inspect future tape.

L0 folds the top witness variables because each interleaved lane is a contiguous stack block. Codeword lane order is reversed, so missing zero-tail lanes become leading zeros in a leaf. Only the live suffix is transported. Caller-coordinate rotation must not be applied to per-level induced weights.

Queries are sampled with replacement in binary-sized stratified groups. They are not iid uniform columns and are not deduplicated. The sampling proofs derive the exact finite distribution from uniform raw E chunks, including chunk sharing, unused bits and repeated cosets. Random-oracle compilation counts every allocation and final completion. The advertised numerical bounds are deliberately **unground**: no proof-of-work amplification and no numerical 128-bit security claim is made.

Ring switching combines all 64-slice claims by a gamma challenge before drawing the six-stage additive map. Each claim's scale remains inside that map. Claim points need not be prefixes of one another. `RingPCSGame` proves false original family/point claims lead to either a quantified ring-map/batching event or false transformed WHIR claims, using the same commitment-time K-witness list. `StackWHIRROM` includes gamma, six map challenges and lambda in one initial 8E allocation, not eight independent oracle opportunities.

## Why this formalization approach

The inspected upstream ArkLib revision is [`35ddcaa83f683011f944f58904be779495a5709a`](https://github.com/Verified-zkEVM/ArkLib/tree/35ddcaa83f683011f944f58904be779495a5709a/ArkLib). Its sumcheck implementation separates executable coefficient messages from polynomial interpretation; `Interaction/ComputableSoundness.lean` proves an actual executor/adversarial-strategy bound. Its Reed-Solomon Johnson/MCA infrastructure is now an imported and instantiated dependency, not merely a precedent: `JohnsonMCA`, `JohnsonNumerics` and `JohnsonListNumerics` discharge the required concrete field, agreement-set and numerical hypotheses.

Dependency auditing found a genuinely false admitted repeated-size `Fin.sumCases` identity: the sizes `[1,1]` provide a kernel-checked counterexample. [ArkLib PR #1297](https://github.com/Verified-zkEVM/ArkLib/pull/1297) removes that unused identity and an unused admitted polynomial-basis placeholder, and repairs the axiom baseline. The pinned fork contains that fix. Other admitted legacy ArkLib interfaces are not silently treated as proofs of WHIR, Merkle security or Fiat-Shamir security; every imported dependency used by a `Whir` theorem is checked transitively by `Audit.lean`.

The inspected Ironwood revision is [`86e3c7026db8c9af27ca731e6b5c7f2d8fc7f0fc`](https://github.com/zcash/ironwood/tree/86e3c7026db8c9af27ca731e6b5c7f2d8fc7f0fc/Zcash). `Arithmetic/NatKernelEquiv.lean` uses a representation map instead of an assumed implementation/spec isomorphism. `Arithmetic/FftSpec.lean` decomposes actual FFT refinement into bit reversal, twiddles and rounds. `Arithmetic/FastMsm.lean` uses a proved `csimp` equality rather than an unchecked implementation replacement. `Meta/AxiomCheck.lean`, `TrustBoundary.lean` and `CensusCheck.lean` motivate direct endpoint and elaborated-environment auditing. Ironwood's multiplicative FFT theorem is not an additive-NTT proof for leanVM.

## Security endpoints and crypto games

`InteractiveSoundness.adaptive_list_binding` proves the actual `CausalGame.AdaptiveListBinding` predicate, not just its definition. For each commitment oracle and lane count it chooses `InitialCandidates.witnesses` before quantifying over public claims and the adversarial strategy. `production_probability` bounds accepted false openings by 2^-73 when the number of public claims is at most 2^64, for every production profile. The candidate list is a mathematical finite list; enumerating it is not required by the executable verifier.

The proof constructs concrete initial-batching, fold-restoration, OOD/query-restoration and terminal-collision events. `CausalPrefix` and `CausalStrategy` prove that each event depends only on the current challenge and the strictly earlier reply/tape prefix. Field cardinalities, the additive encoder's RS interpretation, Johnson/MCA list size, same-agreement-set transfer, concrete OOD separation, sampling distribution and all numerical side conditions are proved rather than packaged as a missing-soundness premise.

`TypedOracleCompiler` executes adaptive oracle machines with a private global memo table. Repeated or cloned requests retain their answers; partial projections do not disclose the rest of a sample. Its whole-history completion is causal, and every payoff agrees with the reference oracle execution. At most `B * (K + 1)` challenge allocations are charged for request depth at most `B` and at most `K` adversarial requests, including the final verifier completion.

`WHIRROM.rom_list_binding_numeric` bounds actual standalone false acceptance by `min 1 (B * (K + 1) * 2^-79)`. `StackWHIRROM.rom_list_binding_numeric` gives `min 1 (B * (K + 1) * (2^-79 + ringCharge cap))` for original stacked family/point claims. Both prove their concrete replay parsing, strict-prefix event correspondence and terminal trace cover; neither asks the caller to assume accepted false openings are covered by bad events. Immutable statement catalogs and root oracles are explicit inputs, not mutable values chosen after a challenge.

`DuplexRefinement`, `DuplexFraming` and the `WHIRNativeSecurity` public compression chain model the historical pre-#607 byte duplex at `f11f84f585680cf10f676bb4d9ae1a67e26547ca`. The capped conditional `2^-42` endpoint concerns that mode and the modeled unanchored native WHIR experiment under the resource and source-model premises below; it does not currently apply to the rewritten #607 deployment. The actual ideal-compression mode coupling is proved, not a supplied DMV assumption. It is not a concrete BLAKE2s security bound or a theorem covering every deployed caller. Separate pinned anchored physical and cursor-byte refinements do not yet compose into an anchored Fiat-Shamir endpoint; generic repeated-scalar vector sampling also does not establish whole-request exhaustion/error equivalence.

`DuplexRefinement` implements that pinned source's buffered stream, held final block, absorb/squeeze roles, full chaining value, vector sampling, cloning, nonce/grinding and limits. `DuplexEncoding`, `DuplexFraming` and `WHIRHistoryKey` prove framing inverses, message/template injection, canonical WHIR history encoding and structural mode conditions. `DuplexCompression` implements BLAKE2s compression. ## Caller statement-binding precondition

The original opening statement must be fixed before its batching challenge packet: every point, slice value, offset, selector and shape must come from already observed messages, the seeded public layout or strictly earlier verifier challenges. A commitment-record identity frame binds the record, not an otherwise unbound caller statement. The generic stack API and `leanvm_core::pcs` forwarding wrappers therefore retain this precondition; the anchor does not replace it.

## Stronger binding and extraction investigation

`CommitmentAmbiguity` checks exact root-locality of the executable verifier, including its error result, and a valid small interactive commitment with two incompatible accepting opening sessions against the same immutable oracle. It separately checks the actual production first-query parity probability. This is an ideal causal interaction result with supplied independent challenges, not a demonstrated attack on deployed Fiat-Shamir.

`CommitmentAnchor` defines commitment identity as the complete immutable root, shape, anchor point and advertised value. The root-fixed candidate list precedes the one fresh uniform extension-field anchor point. Supported padding is injective, and the anchor weight is truncated to the occupied lane prefix while preserving the actual padded witness MLE. Outside the point-only collision event, every malicious choice of advertised value selects at most one supported candidate simultaneously across all later sessions. The actual causal verifier checks this same anchor in every opening batch; its unique-opening failure bound conditional on an unambiguous anchor is the original opening ledger with the additional anchor claim counted.

The checked anchor ambiguity term is `choose(L,2) * dimension / |E|`, bounded by `2^-124` at the proved list cap and supported production dimensions. This is only list selection ambiguity, not whole system security. `ConcreteSecurityBudget` recomputes the capped `2^-42` list-binding ledger using the proved whole-view mode loss `min(1,(2Q^2-Q)/2^256)`; its ROM term alone still prevents a uniform `2^-43` ledger at those caps. The source, Merkle and mode terms remain separate, and the endpoint is the modeled unanchored source event, not a composed anchored endpoint. Commitment-time anchor/cursor mathematics and pinned source decoding remain distinct from full Fiat-Shamir and concrete cryptographic composition.

`PCSRewindSource.complete_original_knowledge` is **interactive only**. The actual bounded reset machine collects legal authenticated Root0 rows, runs the counted Gao/base-word decoder and checks every original family slice, ordinary and strided point claim, and the literal retained anchor before returning a word. Every output is a member of the original Root0 candidate list and explains all original claims; neither candidate availability nor honest-root equality is a premise. For acceptance probability `κ`, the exact acceptance-plus-no-output bound is `1/2^50 + 2^-s`. This is an extraction cutoff and repetition failure expression, not a security level.

Writing `gap = κ - 1/2^50`, the proof chooses fuel without requiring the executable machine to estimate `κ`. When `gap > 0`, the checked round bound is `((8N/gap)+1)(d+2)` and the checked attempt bound is `((8/gap)+1)s`, with Root0 row count `N` and initial folding depth `d`. `complete_original_resource` bounds the actual source arithmetic, strict-prefix oracle calls, consumed encoded reply words, original preparation/checks, retained rows and coordinate comparisons. Its Gao component is degree seven in `N`; the whole expression is polynomial in physical input dimensions, `1/gap`, `s` and literal admitted reply length. Rectangular Root0 input and occupied-lane restrictions are explicit. Prover CPU time and unbounded raw-response allocation are outside the unit-oracle-access boundary.

Compiled source-extractor checks exercise nontrivial K coefficients, all original claims, malformed metadata and the case where `gamma = 0` masks a false original family in the compressed claim but the original checker rejects it. Kernel-checked output, probability and resource endpoints use only `propext`, `Classical.choice` and `Quot.sound`. This is **not a Fiat-Shamir knowledge result**, a full Rust correspondence theorem, or an unconditional concrete BLAKE2s claim. `KnowledgeExtraction` also retains the separate sparse record-only impossibility result; classical choice in the anchor's mathematical selector is not the implemented extractor.

`PCSRoundByRoundSource.run` separately decodes the full Root0 message by direct indexed Gao/base-word processing, checks the actual common support and all original claims, and receives no strategy or verifier coins. Its output, SAME-word heavy-support recovery and counted degree-seven cost are kernel checked. The compiled generic-helper smoke exercises corrupted roots and malformed original statements. This decoder contract alone is not a completed RBR or Fiat-Shamir theorem.

The counted Gao interpolant skips basis construction and inversion whenever a received coefficient is zero, for arbitrary mixed inputs rather than a special all-zero decoder. `ReedSolomonExtraction.countedInterpolationTerm_value` and `countedInterpolant_value` prove the same mathematical interpolant; support and decoder-cost proofs retain their source connection. The resource count includes each coefficient test, and the closed interpolation budget includes the corresponding linear term. The actual Root0 decoder now shares the public domain's nodal polynomial across occupied lanes. `PCSActualSourceRootDecoder.decodeRoot_value` preserves the previous row-decoder output for every input, and `decodeRoot_cost` charges its construction once while retaining the existing polynomial bound. Canonical counted multiplication uses the shorter operand on the left of its asymmetric convolution; its mathematical product and counted bounds are proved unchanged.
