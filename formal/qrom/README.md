# QROM security of leanSPHINCS

This project proves leanSPHINCS strongly unforgeable in the quantum random-oracle model (QROM), with Keccak-256 modelled as a random function that the adversary queries in superposition. It is a proof step beside the classical one (`lean_sphincs/FORS`, `FORS.Lifetimes.h26_layered_adversary`), not an end statement: `formal/statement.tex` keeps quantum security out of what is proved, since the end statements are in the random-permutation model. It builds on VCVio's quantum layer (compressed oracle, instability, square-root hybrid).

## Done

- `Qrom.qrom_search_le`: a `t`-query program outputting `k` inputs finds one whose value is good with probability at most `λ (√6 t + 2k)²`, where every input has a fraction at most `λ` of good values. Database event bound (`EventBound`), the check on `H` read on the compressed database (`Bridge`), the one-cell bound (`Cell`), cell-wise operators (`PiKron`), the assembly (`Search`, `Leaf`, `QromSearch`).
- `Qrom.OvGame.ov_search_le`: the same bound for games whose hash answers some inputs from fixed data, depending on a classical side state, beside classical side ports such as a signing oracle, with `t` the number of calls in all (`Override`, `OvBridge`, `OvEvent`, `OvSearch`).
- `Qrom.OvGame.hiding_le`: replacing the hash by `G` on the inputs that carry data not yet revealed costs `√Pr₁ ≤ √Pr₂ + n √(4 ε tr ρ)`, when at most a fraction `ε` of the unrevealed values protect any input (`Blocks`, `OvBlocks`, `Hiding`, `HidingAvg`, `HidingMain`). Two games that agree on a set of side states closed under predecessors run every program to the same joint states and query weights there.
- `Qrom.OvGame.search_withVerifier_cells_le`: the same bound for a predicate on the whole value of a cell of inputs, with `λ` the fraction of good cell values and the checked cells chosen from the program's output and the verifier's. The oracle on inputs is simulated by one on cells: a call to a component of a cell is one call to the cell with the other components on uniform superpositions, which no addition changes (`Cells`).
- `Qrom.Sphincs.winProb_le_h26`: for the parameters of `FORS.h26_layered`, an adversary given the public key and making at most `n` calls in all (hash queries, quantum or classical, and signing requests) forges with probability at most `((n + 2048) / 2^61)²`. It follows from `Qrom.Sphincs.winProb_le`, the bound for any parameters, `(√ε_hid + (n + 1 + verifyQueries) √(4 · 2^-128 tr ρ))²`, made explicit by `Qrom.Sphincs.winProb_le_lamS` and numeric by `Qrom.Sphincs.winProb_le_h26_terms`. Pinned to Lean's three standard axioms in `Qrom.lean`.

## The leanSPHINCS proof

The adversary is a program whose calls go to the hash or to the classical ports (the public key, signing); the signer and key generation hash classically through the same random function, and the signing log is the game's side state.

1. **Presampling** (`Sphincs/Presampled`): the honest computation (key generation, every signature of every message, the randomizers and digests) reads the hash at distinct points, so the game equals the average over data `d` of one whose hash is a fresh `G` overridden by `d` (`winProb_eq`).
2. **Hiding** (`Sphincs/Hidden`, `Sphincs/HidingStep`): the inputs that read unrevealed data (`SK.seed`, `SK.prf`, unsigned chain values and FORS secrets, unsigned randomizers) are answered by `G`, at a cost of `n √(4 · 2^-128 tr ρ)` on the square root.
3. **Classification** (`Sphincs/Classify`): the classical Level A classification, applied to the hidden game's hash, splits a winning forgery into a protected read, a hit of `G` on an honest value, an encoding input of a counter the signer did not take whose data value carries the key's word, or a digest from `G` covered by the logged digests (`Sphincs/Bound/Split`).
4. **Bounds** (`Sphincs/Bound`): protected reads cost `verifyQueries · 2^-128` (`Terms`). Hits and encoding collisions together cost `2^-128 (√6 (n + 1 + verifyQueries) + 2 verifyQueries)²` (`Swap`): the colliding counter is above the one the signer finds, where the honest computation never reads the data, so exchanging the data there with `G` at those inputs is an involution of the pairs `(d, G)` that turns the collision into a hit of `G`. Covered digests go through the deferral of the signed digests to presampled ones (`Defer`) and a search, with the digest calls of one message and randomizer as the components of one cell (`DigCells`, `CoverCells`), for the cell of the forgery's digest calls holding a digest the presampled digests cover, costing `λ_full (√6 (n + 1 + verifyQueries) + 2)²`. A digest at an index is covered when the presampled digests there open its leaves, so `λ_full` is at most the `k`-th moment of a binomial count over `2^(k a)`, that is `∑_j S(k, j) (N / 2^h)^j / 2^(k a)` for `N` signatures, with `S` the Stirling numbers of the second kind (`LamCov`), at most `9 · 2^-130` for `FORS.h26_layered` (`Sphincs/Numeric`).

## How tight

For `FORS.h26_layered` the bound reaches 1/2 at about `2^60.8` calls (`2^60.5` in the rounded form `((n + 2048) / 2^61)²`), and for `n ≥ 2^20` it is `2^6.2` above the success of Grover's search for a covered digest, which takes 4 hash calls an iteration (the two digest calls, computed and uncomputed). About 4 of those bits come from simulating the oracle on cells, where one call to a digest call is charged as a query to the whole digest; a bound counting the calls of a cell apart is not known to avoid a fourth power of the calls. The search constant `6` (Grover's is 4) and the hit and hiding terms make up the rest.
