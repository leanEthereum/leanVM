# Adaptations from PR #738

The guest is `formal/rv64/guest` of `origin/FV-rust-verifier-via-riscv`, copied file by file. What changed for current `main`:

- **A `no_std` verifier without touching `crates/`.** #738 made `crates/verifier` itself `no_std`, and reworked `bytecode.rs`, `layout.rs`, `bus.rs` and `whir.rs` for cycle count. Here `crates/verifier` stays as it is: `../scripts/nostd-verifier.sh` writes a mechanical `no_std` + `alloc` copy to `verifier-nostd/` (gitignored): `std::` becomes `core::` (`alloc::` for `collections`), and each module imports `Box`, `String`, `ToString`, `ToOwned`, `Vec`, `vec!` and `format!` from a crate-level `prelude`. None of #738's algorithmic rewrites are applied. `Cargo.toml` depends on that copy, so run the script before `cargo build`.
- **Scalars are two words.** `E` is now `K[y]/(y^2 + xy + 1)`, two `K` limbs (`E::new(c0, c1)`), so each stream scalar in the input is 2 words, not 3.
- **`Bytecode::new` is fallible.** It returns a `Result` now; an `Err` halts with reject, like any other `VerifierError`.
- **Verdicts for machine-checked.** Accept is `a0 = 0`, reject `1`, malformed input, heap exhaustion or a panic `2` (#738: accept `1`, reject `0`): machine-checked's `Accepted` is SP1's `HALT`, an `ECALL` with `t0 = 0` and `a0 = 0`.
- **No `unimp` from the guest.** `halt` is a returning `ECALL` (not `options(noreturn)`) followed by `loop {}`, i.e. `j .`, and is `#[inline(never)]`, so the image has two `ECALL`s, `halt`'s and `_start`'s (also followed by `j .`). `panic = "abort"` instead of `"immediate-abort"`: a panic site calls `core::panicking`, which ends in the panic handler, which halts with `2`; with `"immediate-abort"` each panic site is an `unimp`, which machine-checked's proved lift does not take. The only `unimp`s left are `core`'s own `intrinsics::abort()` in the stable sort's `quicksort`, which go with the `sort_by_key`/`BTreeMap` rewrites of `crates/verifier`. `-Z trap-unreachable=no` changes nothing (a byte-identical image), so it is not set.
- **Frozen function boundaries and lowering.** `nostd-verifier.sh` marks every function of the copy `#[inline(never)]`, or `#[inline(always)]` if `../boundaries.txt` lists it (`../scripts/inline-attrs.py`), so that the verifier's functions in the image do not depend on LLVM's inlining heuristics; `core` and `alloc` keep `-inline-threshold=25`. Rustflags add `-C jump-tables=no` (no jump or lookup tables) and `-Z merge-functions=disabled`.
- **Relocations kept.** `build.rs` links with `--emit-relocs` and `--no-relax`; `../scripts/check-relocs.py` checks that every `auipc` pairs exactly with its users.
- **Blocks start 8-aligned.** `Bump::alloc` aligns every block to at least 8 bytes (`layout.align().max(8)`), where #738 aligned it to the layout's alignment. With a smaller alignment a block could start inside the doubleword that ends the previous one, and a store into it (memcpy's first bytes) would rewrite a doubleword below `NEXT`, which the contracts' memory frame (`Env.Frame`, by doublewords) forbids.
- Everything else is unchanged: memory map and `link.x`, entry, the input's word layout, toolchain `nightly-2026-10-03` with `-Zbuild-std`, the release profile but for `panic`. The repository's root `.cargo/config.toml` also hands `-C target-cpu=native` to this target, which rustc ignores with one warning per feature, as it did in #738.

Build, from this directory: `../scripts/nostd-verifier.sh && cargo build --release`. Output: `target/riscv64im-unknown-none-elf/release/verifier-rv64`, a static non-PIE `EXEC`, not stripped.
