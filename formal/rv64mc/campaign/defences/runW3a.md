- **Why**: callers of zeroing `try_allocate_in` need the bytes (wave 2a R1-4). The precondition is `MemsetT.MemsetPreT` unchanged, so every call site that met `MemsetSafeT`'s precondition meets this one; the stopping set stays `False`.
- **How**: the proof is `MemsetT.total`'s text (same `Base`, `Kept`, the three `Total.loop`s with the same measures `k`), each loop invariant conjoined with `Fill m m' dst n c cur` (bytes `[dst, cur)` are `c`, bytes outside `[dst, dst + n)` are the entry's), the doubleword loop's also with `r .x15 = splat (regs .x11)` (the code's replicated byte). `Fill.byte`, `Fill.dword` (via `bat_setByte`, `bat_setMem`, `extractByte_splat`) move the cursor; `Fill.setPost` turns `Fill` at `dst + n` into `SetPost`'s two byte conjuncts. `MemsetT.tail_total` gives the C wrapper.
- **Claims**: `MemsetSpecT.safe : MemsetSpecT env p i need → MemsetSafeT env p i need` (new implies old, by `Isa.TContract.mono`, keeping `hp.1`). `MemsetT.lean` untouched. `SetPost`'s third conjunct is `ByteFrame` (every byte outside `[dst, dst + n)` kept), stronger than `CopyOut`'s doubleword frame; both are proved.
- **Rejected**: proving the partial `MemsetSpec` and combining by `HoldsT.of_holds` (a second proof of the same loops); a copy of `MemsetT.lean` with `Kept` strengthened (the invariants here reuse `MemsetT`'s definitions).

### D3. `DropSliceT.DropSliceSpecT env size := HoldsT ... (fun regs m => BufT env m (regs .x11) (regs .x10) size) (fun _ _ _ _ => True)`.

Wave 2a's draft took `len = 0 ∨ (InWin ptr (size * len) ∧ aligned)`; this takes `VecReprT.BufT` with the length for the capacity, which (a) is VecReprT's predicate, as the brief asks for `Vec` arguments, and (b) puts the elements below `NEXT`, which the loop's reads need to resolve past the frame's slots. `BufT.of_le` (in this module) gives it from a vector's `BufT` of its capacity and `len ≤ cap` (`VecT`'s third conjunct).
