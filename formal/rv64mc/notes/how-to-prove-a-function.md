# How to prove a function

The worked examples are `E::mul` (no loop), `clmul_low` (a constant table), `clmul` and `eq_eval` (a loop, a heap slice, a panic): copy their files.

## Files

- `Rv64mc/Spec/<Area>/<Fn>.lean`: `Pre`, `Post` in terms of the Model's mirror (`Model.eMul`, `Model.eqEvalRust`) and `Core/Repr.lean`'s predicates (`EListAt`, `SliceArgs`, `Env.Live`), and `def spec env p i need := Holds env p i need Pre Post`, the stack `need` a parameter (ghost values, such as a slice's elements, quantified outside: `∀ xs ys, Holds …`). Arguments in registers as the RISC-V ABI passes them: an `E` by value is two registers (`c0`, `c1`), a `u128` is low then high (`Spec.Field.lo128`, `hi128`), a slice is a pointer and a length. No proof here.
- `Rv64mc/Proof/<Area>/<Fn>.lean`: `theorem ok (env) (p) (i) (L : Link) (hp : p[i]? = some (tmpl L)) (hL : L.WF p) {need needC …} (hnC : frame + needC ≤ need) … (<per callee: Callee.spec env p L.<callee>.idx needC>) (<per table: DataRef.Words env L.d_<key> d_<key>_words>) : <Fn>.spec env p i need`, over the generated template (`Gen.Tmpl.<Module>`), never an address, an index or a stack size: `frame` is the template's `addi sp, sp, -frame` (a leaf with a frame takes `(hn : frame ≤ need)`, one without takes nothing). A Proof never imports `Gen/Needs`, so a callee whose frame changes re-proves no caller.
- `Rv64mc/Table/<Area>.lean`: each `ok` at `liftProg Gen.fns` and its index `Gen.Idx.<Module>` (`Rv64mc/Gen/Index.lean`), at `need := Gen.Needs.<Module>` (the generator's frame plus deepest callee, `Rv64mc/Gen/Needs.lean`), with `Gen.<Module>.tmpl_eq` and `wf` (from the link module `Gen.Link.<P>` that `Gen/index.tsv`'s `link` column names, which holds several functions), each `frame + needC ≤ need` by `decide`, a callee's `Table` theorem as its hypothesis (or a hypothesis of the table theorem while that callee is unproved), and a table's `DataRef.Words` as a hypothesis, which `DataRef.Words.of_data` proves from the image's `env.data`.
- A callee not proved yet: write its `Spec` file anyway and take `Callee.spec env p L.callee.idx needC` as a hypothesis. A callee that never returns is `Spec.Runtime.NoReturn env p idx needF`.
- A constant table (a template field `d_<key> : DataRef`, whose content the generator writes as `d_<key>_words`): take `DataRef.Words env L.d_<key> d_<key>_words` as a hypothesis; `rv_auto` reads `d.hi + d.lo + 8 k` as word `k` of it (`Core/ReprLemmas.lean`). A table that holds addresses (slice headers pointing at other constants) has `d_<key>_words L`: each address is `L.d_<p>.hi + L.d_<p>.lo`, `d_<p>` a field of the link for the object it points to (its `hi` the address, `lo` zero), whose words are emitted too, so the template stays relocatable and a load of the pointer reads that term. The template's `tables L` lists every table with its words; `DataRef.InData env (tables L)` says they are all in `env.data` (the link step's fact), `DataRef.InData.words` gives each one's `DataRef.Words`, and `DataRef.InData.mem` with a check of `DataRef.pairs (tables link)` by `decide +kernel` proves a spec's statement about the image's data (`Table/Whir.lean`, `whirQueriesTable`).
- Table entries use Gen.Idx.<Module>, never numerals; proofs use Layouts.* constants, never literal offsets.

## The proof

```lean
theorem ok … : EMul.spec env p i need := by
  rv_auto hp with [hL] using [hcl, hrd]
  all_goals simp only [Model.eMul, ← hi128_xor, ← lo128_xor, ← hi128_shl1, ← lo128_shl1]
  all_goals simp only [BitVec.xor_assoc, BitVec.xor_comm, xor_left_comm, append_hi_lo]
```

- `rv_auto hp with [hL] using [callee specs]` steps every path and closes the calling convention, every callee's precondition (its stack room, `env.Static`, `NEXT`), the memory frame (`Env.Frame`, own stack stores and callees' frames), `env.Static` and the saved registers. What it leaves: the functional part of `Post` (and of a callee's `Pre`), and a goal at every loop head (the target of a backward jump). `with` takes the link's facts (`hL` whole); `using` takes contracts (`Holds`, `NoReturn`, or `∀ f, …`). `stop [pc]` adds a stop (`pc` is the index in the body: label `k` is at `2k`).
- Functional goals: unfold the Model (`simp only [Model.f]`), put XORs in one order (`BitVec.xor_assoc`, `BitVec.xor_comm`, `xor_left_comm`), `ac_rfl` at one level. Values loaded from a heap object read `M.getMem (p + BitVec.ofNat 64 (16 * j))`: rewrite with a `load` lemma through the frame (`EListAt.load`, `Core/ReprLemmas.lean`, where such lemmas go). A bit reversal the compiler lowers to shifts and masks is `reverse_net` (`Proof/Field/Reverse.lean`): `rw [← reverse_net]; simp only [swapBits, bswap]` (and `ac_rfl` if the `|||`s are grouped differently).
- A loop: `theorem loop … : ∀ k j R M, j + k + 1 = len → Inv … j R M → SafeN … ⟨⟨i, head, ret, top⟩ :: rest, R, M⟩` (head from the goal `rv_auto` leaves), the hypotheses of `ok`'s context it needs (`hk`, the stack bound, `env.Static m`, `NEXT`'s bound, the objects). `Inv` states every register the body reads in the form `rv_sym` computes (pointers as `base + BitVec.ofNat 64 (16 * j) + 8#64`), the accumulator as the Model's fold over `take j`, the saved registers, `env.Frame top Tactic.F m M`, and the prologue's stores as `∀ a, top + -frame ≤ a → M.getMem a = (stores).getMem a`. Proof: `induction k`, each case `intro j R M hj hinv; rv_intro hinv; rv_sym hp with [hL] using [...]`; at the back edge `apply ih (j + 1) _ _ (by omega)` then `rv_close`; what is left is the pointer step, the fold step and the exit test. In `ok`, `refine loop … (len - 1) 0 _ _ (by omega) ?_` then `rv_close`.
- Name branch hypotheses as `rv_sym` does: the latest `hc`, earlier ones `hc_1`, `hc_2`; split facts are `hpre_k`, `hret<call>_<k>`, `hinv_k`.

## The heap, `sret` and `out`: `set_option rv_sym.heap true in`

Put `set_option rv_sym.heap true in` before `theorem ok` of a function that stores outside its own stack (a block it allocates, a caller's `sret` or buffer), calls a callee with an `sret` or `out`, or reads its heap objects after stores or calls. Off (the default), `rv_auto` leaves exactly the goals it left before; on, it closes more, so turn it on in a new proof, or in an old one together with deleting the workarounds it makes unnecessary. Worked example: `Rv64mc/Proof/Layout/Constant.lean` (`Form::constant`: a stack `Vec` header built in place, a call with an `sret`, a ghost `lo` at `NEXT` at entry, in one line). On `Form::term` (stores into a fresh block and into `sret`) `rv_auto` leaves only the `FormIn` postcondition, and `rv_close` proves the monomial's `VecAt` in the final memory from the entry's (`transport`) and each address fact `Proof/Layout/Term.lean` states by hand.

- Addresses are compared by `omega` (`Sym.arithProve`) where offsets of one base do not decide: a slot `top - k` against a block `alloc` returned, against an `Owned` or `Live` object (`a + n ≤ NEXT`, or `top ≤ a`), `NEXT` itself, the static data. Its facts are the context's comparisons of numbers and words (word equations as numbers), a frame's bounds on `NEXT`, `InRange`, `Owned`, `Live`, `Fresh`, `Apart`, `Region`, your own `Pre`'s definitions unfolded, layout sizes (`Layouts.Form.byteSize`) as numerals, the environment's layout, and each address `b + c` as `(b.toNat + c) % 2^64` (a slot as `top - k` exactly). Only the facts that share an atom with the goal go to `omega`.
- `env.next M` is read through the stores into `M` (`nextNorm`): callee posts and preconditions speak of `env.next m` at entry, so a ghost like `lo = NEXT at entry` matches.
- The frame (`Env.Frame top out m M`) is built store by store and call by call with any `out`: a store into the stack (`frame_slot`), into `out` (`frame_out`), into what the function allocated (`frame_fresh`: at or above `NEXT` at entry, below `NEXT` now); a callee without `out` (`frame_callF`), or with one whose every word is the caller's stack, fresh, or the caller's `out` (`frame_trans`, `mayWrite`). `env.Static` after such stores is `static_store` when the address misses the static data. All in `Tactic/Heap.lean`.
- After a call, besides `keep<k>_1` (memory at or above the callee's stack top, now also for a callee with `out`, with the premise `¬ out a`), `keep<k>_2` keeps what is below `NEXT` at the call or at or above the callee's stack top (`frame_keep`, `frame_keep_out`); loads read through both.
- A representation predicate of a later memory, from a hypothesis of the same predicate (same arguments) of an earlier one, is carried by its lemma `<P>.keep` (or `<P>.keep'`; a definition without one by the one it unfolds to): `WordsAt.keep`, `EAt.keep`, `EListAt.keep`, `VecAt.keep`. The lemma's premises are filled: a memory kept (`Keeps m m' a n`, or any definition that unfolds to `∀ b, … → m'.getMem b = m.getMem b`) by walking the stores and the callees' frames with `omega` on the addresses, a fact about numbers by `omega`, a part (`Elems m p xs → Elems m' p xs`) recursively. So a family that states `<P>.keep` in this form (the footprint as `Keeps` over a range, a nested structure's buffers as one `Region lo hi` below `NEXT`) gets its predicate carried across stores and calls for free.
- A representation predicate a callee's precondition asks of memory built in place (a `Vec` header on the stack): its fields (a structure, `VecAt`) or its definition's parts (`WordsAt`, `EAt`) are closed one by one, reads of memory resolved through the stores; closed comparisons by `decide`; a `∀ k, k < [].length → …` by `omega`; a hypothesis of the same predicate up to unfolding (`Model.constantRust v` against the literal form) closes it.
- `rv_mem` rewrites the goal's reads (registers, `NEXT`, memory) as the executor does, for the postcondition you prove by hand.
- Byte stores (`sb`, kept as `setByte`) are stores into the doubleword at their aligned address (`Core/ReprBytes.lean`): a load reads through them (`getMem_setByte_ne`, or `getMem_setByte_eq` into its own doubleword, giving `replaceByte`), and they enter the frame (`frame_byte`, `frame_byte_out`, `frame_byte_fresh`), `env.Static` (`static_byte`) and `NEXT` (`next_setByte`). Eight bytes at an aligned address are its doubleword: `getMem_of_bytes` (`BytesAt` to `packBytes`), and `getByte_aligned` the other way.
- A narrow load (`lb`, `lh`, `lw`, signed or not) at a literal offset of a constant table reads its value, given `DataRef.Words env L.d_<key> d_<key>_words` and `DataRef.Aligned L.d_<key> n` (the base a multiple of 8, `n` doublewords; the link step proves it by `decide`). At a symbolic offset (a loop), use `DataRef.Words.load` (the value is `dwLoad w ws[k] o`).

## Arguments and options

- `using [...]` and `with [...]` are elaborated after `rv_auto` has opened the contract, so they may name its `regs`, `m`, `top`, `ret` and `hpre_k`: a callee's contract at a ghost of the entry, `hterm [] value (env.next m) 8#64 0`.
- `through [pcs]` steps through the given backward-jump targets instead of stopping there (a dispatch join, a target inside one loop body); `through *` through every one (a path still stops where it would come back to a pc it has passed).
- With `rv_sym.heap`, a branch on two literals (`2#64 = 0#64`) steps only the branch taken, and literals in `with` facts are put in the executor's form, so `48#64` and `BitVec.ofNat 64 48` match.
- `set_option rv_sym.bind 32 in`: a callee's result whose value is deeper than 32 stays the callee's register (`r<k> .x10`), its equation a hypothesis `hret<k>_j`, instead of being written into the register file: a chain of calls (63 squarings) no longer nests one term in the next. Prove the final value by rewriting with the `hret` equations, or cut the chain into lemmas over variables as `Proof/Field/KInv.lean` does.
- With `rv_sym.heap`, an equation `R .x = ?v` whose right side is a goal's metavariable (an invariant's value left to fill) is filled with the executor's value; a load from the heap through a run of stores into the stack shows once that its address is off the stack (`ne_of_off_stack`), not once per store.
- An equation the closer compares by reducible unfolding is given a budget, so two large terms that differ are given up on instead of unfolded for minutes.

## Cost

Record each function in `notes/proof-log.tsv`: `module`, `instr` (from `Gen/index.tsv`), `loops`, `proof_lines` (lines of `ok` and its loop lemmas), `cpu_s` (tactic plus kernel, `set_option profiler true` on a copy, or `/usr/bin/time` less the imports), `manual_notes` (what was not automatic). A straight-line function should cost about a second; if it costs more, profile before anything else.

## Pitfalls

- Never prove an equation the kernel must find by unfolding a value: no `Eq.refl` between a register read and a computed value, no literal arithmetic by `rfl` (the kernel unfolds `2^64 - 1` one successor at a time, and a `mulhu` value into `Nat.div`). Use the named lemmas `rv_sym` uses, or `decide` for closed facts.
- Never run `bv_omega` or `omega` on a goal whose context holds the program's state: it carries the whole context into every auxiliary proof. State the arithmetic as a lemma with only what it needs (`end_iff`, `step_ptr`) and apply it.
- `any_goals exact lemma _ _` on goals the lemma does not fit can unify for minutes: close goals in order, one bullet each.
- Write literals as `0x…#64`, as the templates do; `(16 : BitVec 64)` is another term and stops a syntactic match.
- A representation predicate (`EListAt`, `Live`) is kept whole in hypotheses; `SliceArgs` and your own `Pre`/`Post` definitions are split into their conjuncts.
- Warnings fail the build: no unused `all_goals`, no deprecated lemma names.
